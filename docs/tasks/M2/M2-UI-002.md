# M2-UI-002: Install-plan dialog and progress

## Objective
Plan install… opens a dialog that shows the whole `InstallPlan` — every download (URL, size, checksum source), every command, every system change and whether elevation is needed — with Install / Cancel; Install calls `env/install` with the `planId`, and progress shows on the page and in the transport.

## Context
Epic 2.7; ADR-0014 §2 (approval is a protocol fact).

## Required interfaces
- `env/planInstall`, `env/install`, `env/installProgress`; `Dialog` (SYSTEM-004).

## Implementation requirements
1. Dialog lists steps in order with icons per kind; system-scope plans carry a warning banner and the elevation note.
2. Install is the primary action; Cancel closes without calling the daemon.
3. During install: determinate progress, current step, Cancel (`$/cancel`); failure shows the error kind in plain language (checksum mismatch, approval denied…).
4. The transport shows the install as the running activity (one place for "something is executing").

## Constraints
- ADR-0014 (accepted) is the decision record; do not reopen its decisions in this task.
- Frozen contracts (IPC 0.1 meanings, editor bridge 1) unchanged; additive protocol changes only where this spec says so.
- `scripts/check.sh` green; no test deleted, weakened or skipped.
- The UI never edits a plan; it shows exactly what the daemon returned.

## Acceptance criteria
1. Smoke: plan dialog shows every step of a fixture plan; Install starts it; Cancel stops it.
2. a11y: dialog traps focus, Escape cancels, steps are a list with names.

## Tests
- smoke `install plan dialog shows every step`, `cancel install`; a11y suite; `scripts/check.sh`.

## Failure conditions
- Install starts without the dialog's explicit Install.
