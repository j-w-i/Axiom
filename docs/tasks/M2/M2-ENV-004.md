# M2-ENV-004: System installation through the host package manager (always approved, elevated by the OS)

## Objective
`system_package` plans detect the host's package manager (apt, dnf, pacman, brew, winget), list the exact packages and command, require approval, and run through the platform's elevation prompt; Axiom never stores credentials and never runs silently.

## Context
Epic 2.4. ADR-0014 §2; `docs/research/toolchains.md` §System package managers.

## Required interfaces
- `InstallMethod::SystemPackage` (provider.rs); plan machinery from M2-ENV-002.

## Implementation requirements
1. Manager detection per OS (presence of the binary; on Linux prefer the distro's native manager).
2. Plan: `SystemPackages{manager, packages}` with the exact argv that will run, marked `scope: system`, `effects: [system_change, elevation]`.
3. Execution: Linux `pkexec <argv>` (fallback `sudo -A` with the OS askpass if pkexec is absent); macOS `brew` without elevation; Windows `winget` (its own UAC).
4. Output streamed as progress; non-zero exit fails the install with the tail of the output.
5. Verify by re-running tool detection.

## Constraints
- ADR-0014 (accepted) is the decision record; do not reopen its decisions in this task.
- Frozen contracts (IPC 0.1 meanings, editor bridge 1) unchanged; additive protocol changes only where this spec says so.
- `scripts/check.sh` green; no test deleted, weakened or skipped.
- Never run a package manager without an approved plan; never pass `-y`-style flags the plan did not show.

## Acceptance criteria
1. On Linux CI (container with dnf or apt and a fake pkexec shim), a plan for a tiny package is produced and executed through the shim with the exact argv shown.
2. Without approval nothing runs.

## Tests
- `cargo test -p axiom-env` (cases: `detects_manager`, `plan_lists_exact_argv`, `runs_only_approved_plan` with a shim).
- `scripts/check.sh`.

## Failure conditions
- Any elevation without the OS prompt, or credentials cached by Axiom.

## Documentation updates
`docs/architecture/security.md` (system installs), `docs/roadmap/current.md`.

## Handoff
The per-OS elevation path actually used and what was verified on which OS.
