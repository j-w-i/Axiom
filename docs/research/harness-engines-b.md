## 1. Gemini CLI (google-gemini/gemini-cli) - source

**Layout**: `packages/{core,cli,sdk,a2a-server,devtools,vscode-ide-companion,test-utils}`. Engine is `packages/core/src`.

**Agent loop**: `core/client.ts` (`GeminiClient`, `MAX_TURNS = 100` per prompt, line 86), `core/turn.ts`, `core/geminiChat.ts`
(streaming chat, retry, `CONTINUE_PROMPT_TEXT='Please continue.'`). Tool calls go through `scheduler/scheduler.ts`, which batches contiguous
"parallelizable" tools (line ~545). Loop guard: `services/loopDetectionService.ts` (same tool call 5x = `TOOL_CALL_LOOP_THRESHOLD`; same content chunk 10x = `CONTENT_LOOP_THRESHOLD`;
plus an LLM judge over the last 20 messages with confidence >= 0.9). Retries: `utils/retry.ts` `DEFAULT_MAX_ATTEMPTS=10`, plus model fallback (`fallback/`, `availability/`).
Model routing service (`routing/`, complexity threshold default 90).

**Provider abstraction**: weak by design. `core/contentGenerator.ts` wraps Google GenAI (Gemini API key, Vertex, OAuth/Code Assist `code_assist/`), plus `localLiteRtLmClient.ts`
(local model). Decorators: `loggingContentGenerator`, `recordingContentGenerator` / `fakeContentGenerator` (record/replay for tests), `modelMappingContentGenerator`.
Not multi-vendor. `core/tokenLimits.ts`: default 1,048,576 tokens.

**Tool system** (`tools/`): `read_file`, `read_many_files`, `write_file`, `replace` (edit), `glob`, `grep_search` (ripgrep variant), `list_directory`, `run_shell_command`
(+ background tools `shellBackgroundTools.ts`), `web_fetch`, `google_web_search`, `write_todos`, `ask_user`, `activate_skill`, `enter/exit_plan_mode`, `get_internal_docs`,
`save_memory` (`memoryTool.ts`), tracker tools (`tracker_*`: create/update/get/list/add_dependency/visualize), `invoke_agent`, MCP resources tools. Tool declarations are per-model-family
(`tools/definitions/model-family-sets`, snapshot-tested in `coreToolsModelSnapshots.test.ts`).
- **Edit format**: `replace` = exact old_string/new_string with a cascade in `tools/edit.ts`: exact -> flexible (whitespace-insensitive line match) -> regex (tokens joined by `\s*`) -> fuzzy; `allow_multiple`; `omissionPlaceholderDetector.ts` rejects "// ... rest unchanged" style output; line-ending preservation (`line-endings.test.ts`); `modifiable-tool.ts` lets the user edit the proposed diff in an external editor.
- **Limits**: read_file 2000 lines default, 2000 chars/line, 20 MB file (`utils/constants.ts`); tool output truncation threshold `DEFAULT_TRUNCATE_TOOL_OUTPUT_THRESHOLD = 40_000` (`config/config.ts:487`); shell live buffer 100,000 chars (`tools/shell.ts:91`); web_fetch 250,000 chars, 10 s timeout, 10 req/min rate limit (`tools/web-fetch.ts`); MCP default timeout 10 min (`mcp-client.ts:99`).

**Context management** (`context/`): two generations coexist. (a) `chatCompressionService.ts`: compress at **50% of model token limit** (`DEFAULT_COMPRESSION_TOKEN_THRESHOLD=0.5`), keep last **30%** (`COMPRESSION_PRESERVE_THRESHOLD`), last **3** tool-response turns at full fidelity (`RECENT_TURNS_PROTECTED`), preserved function-response budget 50k tokens, "collapse" old tool responses to 2 KB snippets once history > 256 KB, retrieval tools (read_file etc.) exempt up to 64 KB. (b) `toolOutputMaskingService.ts`: mask old tool outputs to files under `tool-outputs/` when protected window of 50,000 tokens is exceeded and >= 30,000 prunable (`DEFAULT_TOOL_PROTECTION_THRESHOLD`, `DEFAULT_MIN_PRUNABLE_TOKENS_THRESHOLD`), latest turn always protected. (c) New pipeline `context/pipeline/` + `context/processors/` (rolling summary, state snapshot async, node distillation/truncation, blob degradation, history truncation) = composable "processors" over a working buffer (`contextWorkingBuffer.ts`, `orchestrator.ts`). Worth studying as a design: it is the most elaborate compaction architecture in this group.

**Session persistence + checkpoints**: `services/chatRecordingService.ts` writes JSONL sessions to `~/.gemini/tmp/<project_hash>/chats/session-<ts>-<id>.jsonl` (parent-id subdirs for subagents). Checkpointing (opt-in, `docs/cli/checkpointing.md`): `services/gitService.ts` shadow repo at `~/.gemini/history/<project_hash>` with isolated gitconfig and sanitized env (`GIT_DIR`/`GIT_WORK_TREE` unset), author "Gemini CLI"; each approved file-modifying tool creates a snapshot commit + conversation JSON in `~/.gemini/tmp/<hash>/checkpoints`; `/restore` reverts files, restores history and re-proposes the tool call. Also `/rewind` (`docs/cli/rewind.md`) and `services/worktreeService.ts` (git worktrees).

**Subagents**: `agents/` - `local-executor.ts` (own loop; `DEFAULT_MAX_TURNS=30`, `DEFAULT_MAX_TIME_MINUTES=10`, 1 min grace period), built-ins `codebase_investigator`, `generalist`, `cli_help`, browser agent (`agents/browser/`, drives Chrome via MCP wrapper), `skill-extraction-agent`; remote agents over A2A (`a2a-client-manager.ts`, `packages/a2a-server`). Subagents are exposed as tools of the same name (`invoke_agent`); user-defined in `.gemini/agents/*.md` and `~/.gemini/agents/*.md` (frontmatter `kind: local`, `tools`, `model`, `max_turns`, `timeout_mins`). `@agentname` syntax forces delegation.

**Sandbox/permissions**: Approval modes `default | autoEdit | yolo | plan` (`policy/types.ts`). Policy engine `policy/policy-engine.ts` with TOML rules (`policy/policies/*.toml`: read-only, write, plan, yolo, agents, sandbox-default...), priority tiers Default(1.x) < Extension(2.x) < Workspace(3.x) < User(4.x) < Admin(5.x) (comment in `write.toml`); per-rule `toolName`, `decision` (allow/ask_user/deny), `modes`, `interactive`, argument regex, `safety_checker` (in-process "allowed-path" checker). Shell safety parsing (`policy/shell-safety*.test.ts`, `sandbox/utils/commandSafety.ts`). OS sandboxes in `sandbox/`: Linux bubblewrap (`bwrapArgsBuilder.ts`), macOS Seatbelt (`seatbeltArgsBuilder.ts`, `baseProfile.ts`), Windows (`GeminiSandbox.cs` helper). Folder trust gates workspace skills/hooks/policies (`FolderTrustDiscoveryService.ts`). Env var scrubbing `environmentSanitization.ts`. Loop detection and confirmation bus (`confirmation-bus/`) decouple UI from policy.

**MCP**: `tools/mcp-client.ts`, `mcp-client-manager.ts`, `mcp-tool.ts`; stdio/SSE/streamable HTTP; OAuth (`mcp/oauth-provider.ts`, token storage in keychain/file, service-account impersonation, Google auth provider); settings `mcpServers.<name>` with `trust`, `includeTools`, `excludeTools` (exclude wins), allow/excluded server lists; MCP prompts become slash commands (`prompts/mcp-prompts.ts`); resources tools. No deferred tool search found in `packages/core/src` (grep for ToolSearch/deferred: none relevant). [INF] full MCP schemas always loaded.

**Hooks/skills/instructions**: Hooks (`hooks/types.ts`): `BeforeTool, AfterTool, BeforeAgent, AfterAgent, Notification, SessionStart, SessionEnd, PreCompress, BeforeModel, AfterModel, BeforeToolSelection` in `settings.json` under `hooks`, `matcher` regex for tools; command hooks over stdin/stdout JSON; `trustedHooks.ts` fingerprints project hooks. Skills (`skills/skillManager.ts`): precedence built-in < extension < `~/.gemini/skills` < `~/.agents/skills` < `<ws>/.gemini/skills` < `<ws>/.agents/skills` (workspace only when folder trusted); SKILL.md needs only `name` + `description` (own tolerant frontmatter parser handles colons). Context file `GEMINI.md` (configurable via `context.fileName`, can list several, e.g. `["AGENTS.md","GEMINI.md"]`), global `~/.gemini/GEMINI.md`, workspace + ancestor walk, JIT discovery when a tool touches a directory (`tools/jit-context.ts`), `@file.md` imports (`utils/memoryImportProcessor.ts`). Custom commands: TOML in `.gemini/commands/**/*.toml` (`prompt`, `description`, `{{args}}`, `!{shell}`, `@{file}`), namespaced by subdirectory. Settings precedence (docs/reference/configuration.md): system-defaults < user `~/.gemini/settings.json` < project `.gemini/settings.json` < system `/etc/gemini-cli/settings.json` (admin override) < env/CLI.

**Performance**: perf/memory test dirs `perf-tests/`, `memory-tests/`, `evals/` (behavioral evals), `agents/memory-leak-regression.test.ts`. No numbers published in repo that I checked. Single Node process; PTY shell via `shellExecutionService.ts`.

**Strengths**: policy engine with tiered TOML and admin tier; OS sandbox on all 3 OSes; shadow-git checkpoints with restore of conversation + tool call; sophisticated compaction pipeline; JSONL sessions; loop detector with LLM judge; skills `.agents/skills` interop; subagents as tools incl. A2A remote.
**Weaknesses**: Gemini-only (no provider abstraction); three overlapping compaction mechanisms (complexity); no deferred MCP tool loading; checkpoints off by default; heavy TS package (137 MB clone).
**Adopt**: tier-priority policy rules (default<extension<workspace<user<admin), `trust`/`includeTools`/`excludeTools` MCP filter semantics, loop detector constants (5 / 10 / LLM-judge 0.9), tool-output masking-to-file with protected window (50k) and min-prunable (30k), shadow repo with isolated gitconfig/env, folder-trust gate on repo-supplied hooks/skills/policies, edit cascade exact->flexible->regex.
**Avoid**: single-vendor content generator coupling; three concurrent compaction systems.
**Reusable components**: `policy/*.toml` format; `services/gitService.ts` shadow-repo recipe; `context/processors/*` pipeline design; `tools/edit.ts` replacer cascade; `sandbox/{linux,macos}` argument builders (bwrap/seatbelt profiles); `hooks/` runner (command JSON protocol).

## 2. Cline (cline/cline) - source

**State**: the repo was rewritten around an SDK. `sdk/packages/{shared,llms,agents,core,sdk,ui}`, `apps/{cli,cline-hub,vscode,vscode-rollout,examples/desktop-app}`. Toolchain Bun + Node >= 22 (`AGENTS.md`). A long-running **hub daemon** (`apps/cline-hub`, `@cline/cline-hub`, auto-spawned by the CLI; `sdk/packages/core/src/hub/`) hosts sessions over WebSocket for CLI, VS Code and a Tauri+Next desktop app. Layering enforced: `shared <- llms <- agents <- core <- apps` (`sdk/ARCHITECTURE.md`): `agents` = stateless loop, `core` = stateful orchestration/persistence.

**Agent loop**: `sdk/packages/agents/src/agent-runtime.ts` (2979 lines). Constants: `MAX_TOKENS_RECOVERY_LIMIT=3` (output cut-off recovery with "be more concise" nudge), provider error retries 3 with 1 s base, 15 s max backoff; optional `maxIterations`. Hooks are contracts in `shared/src/hooks`. Safety: `core/src/runtime/safety/{loop-detection,mistake-tracker,rules}.ts` (consecutive identical tool-call signature counter via sorted-key JSON). Turn queue for pending prompts (`runtime/turn-queue`). `submit_and_exit` tool requires "verify by EXECUTION" evidence text (`extensions/tools/schemas.ts`), a notable prompt-level completion gate.

**Provider abstraction**: `sdk/packages/llms/src/providers/` built on the Vercel AI SDK (`ai-sdk.ts`): `@ai-sdk/{anthropic,openai,openai-compatible,google,google-vertex,amazon-bedrock,mistral,gateway,otel}`; gateway-style registry (`factory-registry.ts`, `gateway.ts`, `handler.ts`), generated model catalogs (`catalog/catalog.generated.ts`, live catalog, `model-id-aliases.ts`), error classification, middleware dir, OAuth token manager with cross-process refresh lock (`runtime/orchestration/oauth-refresh-lock.ts`). Default provider is Cline's own account service.

**Tool system** (`core/src/extensions/tools/definitions.ts`, `constants.ts`): `read_files`, `search_codebase`, `run_commands`, `fetch_web_content`, `apply_patch`, `editor`, `skills`, `ask_question`, `submit_and_exit`, plus `spawn_agent` / team tools (`tools/team/`). Edit formats: `editor` = Anthropic-style (`old_text` must match exactly once, `new_text`, create-if-missing, `insert_line`; prompt says keep edits small, `INPUT_ARG_CHAR_LIMIT`); `apply_patch` = OpenAI-style `*** Begin Patch / *** Add|Update|Delete File / *** Move to / *** End of File` (`executors/apply-patch-parser.ts`). `model-tool-routing.ts` picks which edit tool per model family (inference from filename and presets). Limits (`executors/output-limits.ts`): command output 48,000 chars (middle elided, head/tail kept so notices survive), search 48,000, read 2,000 lines, 2,000 chars/line, 48,000 chars per read; file size 10 MB; detached log 10 MB. Stated rationale: every char is resent each turn, cost is quadratic. `command-guard.ts` blocks file-mutating shell commands in plan mode.

**Context management** (`extensions/context/`): trigger at **90%** of input window (`COMPACTION_TRIGGER_RATIO=0.9`, `CONTEXT_WINDOW_INPUT_RATIO=0.9`), target 70% (`DEFAULT_TARGET_RATIO`; 0.5 for long conversations), preserve recent 20,000 tokens, summary max 8,192 output tokens, tool-result and file-content snippets cut at 2,000 chars, default max input 128,000 when unknown. Strategies: `basic-compaction.ts` (deterministic), `agentic-compaction.ts` (LLM summary, min input 1,024 tokens), plus `budget-projection/`. `PreCompact` hook slot exists.

**Session persistence + checkpoints**: SQLite (`shared/src/db/sqlite-db.ts`, `core/src/services/storage/sqlite-session-store.ts`, team stores with schema versions) plus conversation store and session manifest (`session/stores/`), history search index (`session/search/session-history-search.ts`), fork metadata, session versioning/import (`session/services`, `services/session-import`). Checkpoints (`core/src/hooks/checkpoint-hooks.ts`): **not a shadow repo**; uses real repo `git stash create --include-untracked` equivalent: a per-session persistent `GIT_INDEX_FILE` in `~/.cline/data/checkpoint-scratch/<hash(cwd+session)>` and `git write-tree` + `commit-tree` so untracked files become a third parent; stash message prefix `cline checkpoint session=`; scratch dirs reaped after 14 days; `checkpoint-restore.ts`, `checkpoint-diff.ts`. (Old VS Code Cline used a shadow git repo; this SDK version does not, per this code.)

**Subagents**: `spawn_agent` (CLI and desktop only per `docs/features/subagents.mdx`); own context; approving the spawn approves all sub-tool calls (no inner approvals); subagent can spawn subagents; **no MCP tools in subagents**; plan mode has no edit tools. `configured-agent-config.ts` for YAML/markdown-defined agents in `.cline/agents` and `~/.cline/agents`. In-memory team primitives (`team/`), `multi-agent.ts`, SQLite team events.

**Sandbox/permissions**: approval per tool + auto-approve settings (`docs/features/auto-approve.mdx`); desktop approval over file IPC (`runtime/tools/tool-approval.ts`); worker/subprocess sandbox for plugins (`runtime/tools/worker-sandbox.ts`, `subprocess-sandbox.ts`); `.clineignore`. No OS-level sandbox for the shell found. [INF] relies on approvals and command-guard.

**MCP**: `extensions/mcp/` (client, manager, OAuth, apps, remote-proxy, name-transform, annotations/policies); settings file `cline_mcp_settings.json` (`mcpServers`, `shared/src/storage/paths.ts:88`); marketplace install (`services/mcp-install.ts`, `marketplace.ts`); MCP "apps". No deferred tool search seen. [Unverified] absence.

**Hooks/skills/instructions** (`shared/src/storage/paths.ts`): rules from `<ws>/AGENTS.md`, `<ws>/.clinerules` (file or dir), `<ws>/.cline/rules/`, `~/.agents/AGENTS.md`, `~/.cline/rules/`, `~/Cline/Rules`, `~/Documents/Cline/Rules`. Skills dirs: `<ws>/{.clinerules,.cline,.claude,.agents}/skills/` (it reads `.claude/skills` deliberately). Workflows (slash commands as markdown): `.clinerules/workflows`, `.cline/workflows`. Hooks: file-based, one executable per event named `TaskStart, TaskResume, TaskCancel, TaskComplete, TaskError, PreToolUse, PostToolUse, UserPromptSubmit, PreCompact, SessionShutdown` in `~/.cline/hooks`, `~/Documents/Cline/Hooks`, `<ws>/.clinerules/hooks` (names map to SDK events `agent_start...`, `hooks/hook-file-config.ts`; subprocess JSON protocol `hooks/subprocess-runner.ts`); plus programmatic **plugins** (JS/TS modules in `.cline/plugins`, `~/.agents/plugins`, `package.json#cline`).

**Performance**: hub avoids per-window engine duplication; checkpoint persistent index to avoid rehashing; output caps documented above. No benchmark numbers in repo read.

**Strengths**: cleanly layered SDK with a daemon shared by CLI/IDE/desktop (closest to Axiom's own topology); reads rules/skills from neighbours (AGENTS.md, `.claude/skills`, `.agents`); checkpoints without a second repo; quadratic-cost-aware output caps; plugin system; per-model tool routing; cross-process OAuth refresh lock.
**Weaknesses**: subagents bypass approvals; no subagent MCP; no OS sandbox; hooks are one-file-per-event (less expressive than matcher JSON); big monorepo churn (rewrite) so old docs/behaviour differ.
**Adopt**: daemon + thin clients topology, output cap constants (48k chars, head/tail elide with notices at edges), compaction 90%/70%/20k preserve, `submit_and_exit` evidence gate [INF: may over-prompt], stash-with-index checkpoint trick for untracked files, rules path search order.
**Avoid**: approving a spawn as blanket approval of children; per-event executable-file hook format as primary (use JSON config, import Cline's as a legacy format).
**Reusable components**: `apply-patch-parser.ts` (V4A patch grammar), `compaction-shared.ts` constants, `checkpoint-hooks.ts`, `paths.ts` discovery list, `mcp/name-transform.ts`.

Slash commands: markdown in `.roo/commands/`, global and built-in (`services/command/commands.ts`).

**Strengths**: mode system (tools-per-persona) is simple and understood by users; non-destructive truncation; folded file context for summaries; full command output persisted with preview; broad provider list; per-task checkpoints.
**Weaknesses**: archived; VS Code-bound; no hooks; sequential subtasks only; handwritten providers (maintenance cost); no sandbox.
**Adopt**: custom-mode file schema as an *import* target (`.roomodes`), non-destructive truncation tags, folded-file-context summaries, persist-full-command-output + preview, per-profile condense threshold.
**Avoid**: depending on this repo (dead); mode switching as the only specialization mechanism (prefer subagent definitions + tool allowlists).

## 4. Aider (Aider-AI/aider) - source

**State**: v0.86.3.dev, Python, Apache-2.0, last push 2026-05-22. HISTORY.md says "Aider wrote 62% of the code in this release". No MCP, no hooks, no subagents, no native tool-calling loop. It is a *prompt-and-parse* editor.

**Agent loop**: `aider/coders/base_coder.py`: one LLM call per user message; parse edits from the reply; apply; optional auto-lint/auto-test; on failure feed errors back (`max_reflections = 3`, line ~101, `num_reflections` reset per message; line 939 "Only 3 reflections allowed"). Context overflow detected via litellm `ContextWindowExceededError` (line ~1464). No iterative tool loop, so it is cheap and predictable. `/ask`, `/architect`, `/context`, `/help` coder variants.

**Provider abstraction**: litellm (`aider/llm.py`, `models.py`, `sendchat.py`), model metadata + per-model edit-format defaults in `aider/resources/model-settings.yml` (357 `- name:` entries) and `model-metadata.json`; aliases; `weak_model` (commit messages, summaries), `editor_model` (architect mode); reasoning settings (`--reasoning-effort`, thinking tokens), prompt caching `--cache-prompts` (cache-breakpoints `chat_chunks.py`).

**Edit formats** (`aider/coders/__init__.py`, each a `Coder` subclass + `*_prompts.py`): `whole` (whole file), `diff` (SEARCH/REPLACE blocks, `editblock_coder.py`), `diff-fenced` (path inside the fence, for Gemini), `udiff` (unified diff with no line numbers, designed to stop "lazy coding"; `udiff_coder.py`), `udiff-simple`, `patch` (OpenAI-style V4A, `patch_coder.py`), `editor-diff`, `editor-whole`, `editor-diff-fenced` (stripped prompts for architect's editor), `architect` (two-stage: architect model proposes in prose, editor model applies; `architect_coder.py` runs editor with `map_tokens=0`, `suggest_shell_commands=False`), plus `ask`, `context`, `help`. Function-call variants (`*_func_coder.py`) are disabled. Apply robustness: `search_replace.py` tries a ladder: exact `search_and_replace`, `git_cherry_pick_osr_onto_o` / `git_cherry_pick_sr_onto_so` (uses real git merge machinery), `dmp_lines_apply` (diff-match-patch), each under preprocessors (strip blank lines, relative indent) (`all_preprocs`, lines ~528-565); `editblock_coder.py` also handles `...` elisions, leading-whitespace repair, fuzzy "did you mean" feedback to the LLM. Default format is chosen per model in model-settings.yml (e.g. `udiff` for GPT-4 Turbo-class, `diff` for most Claude models).

**Repo map** (`aider/repomap.py`; the thing to copy): tree-sitter tags (`aider/queries/tree-sitter-language-pack/*-tags.scm` and `tree-sitter-languages/`; ~30+ languages) -> definitions/references graph (NetworkX) -> **PageRank with personalization** -> binary-search the number of ranked tags that fits `max_map_tokens`. Weights (`get_ranked_tags`, lines ~365-520): identifiers mentioned in chat x10; long snake/kebab/camel names (>= 8 chars) x10; private `_names` x0.1; identifiers defined in > 5 places x0.1; edges from files already in chat x50; self-edge 0.1; personalization 100/num_files for chat and mentioned files. Defaults: `map_tokens = 1024` (models.py:783, scaled to max_input/8, clamped 1024..4096; warning if > 2x), `--map-multiplier-no-files` 2 (when no files in chat the budget is multiplied, capped by context window - 4096 padding; the CLI arg default is 2, `RepoMap.map_mul_no_files` default 8 is overridden), `--map-refresh auto|always|files|manual`. Cache: `diskcache` in `.aider.tags.cache.v{3|4}` keyed by file mtime (SQLite fallback on error). Output is a signature skeleton of top-ranked files, not whole files. This is the main reason Aider works on large repos with a small context.

**Context management**: no compaction at threshold; `history.py` `ChatSummary` summarizes `done_messages` in a background thread when over `max_chat_history_tokens` = clamp(max_input_tokens/16, 1024, 8192) (`models.py:358`), recursive halving (`depth`); weak model does it. Chat history restorable from `.aider.chat.history.md` (`--restore-chat-history`).

**Persistence + checkpoints**: git *is* the checkpoint layer. Every applied edit is auto-committed (`repo.py` `commit`, message generated by weak model, prefixed "aider: " in some attribute modes; `--attribute-author/committer/co-authored-by` trailer logic), `/undo` reverts last aider commit, `/diff`, `/git`. Dirty files are committed first ("pre-commit" so user changes stay separate). Files: `.aider.chat.history.md`, `.aider.input.history`, `.aiderignore`, `.aider.conf.yml` (search git root, cwd, home), `.env`, `--read` read-only files (e.g. `CONVENTIONS.md`).

**Subagents/sandbox/MCP**: none. Shell commands are *suggested* and the user confirms (`suggest_shell_commands`); no sandbox. `--auto-lint` / `--auto-test` run configured commands (`linter.py` uses tree-sitter syntax check by default).

**Hooks/skills/instruction files**: none of AGENTS.md/CLAUDE.md natively; convention is `--read CONVENTIONS.md` or `read:` in `.aider.conf.yml`. Watch mode (`watch.py`): `# aider!` / `# aider?` comments in files trigger runs. Config: YAML `.aider.conf.yml`, `.aider.model.settings.yml`, `.aider.model.metadata.json`.

**Performance/benchmarks**: `benchmark/` (Exercism polyglot harness, Docker); the aider leaderboard (website) is the de facto public edit-format/model benchmark. Specific numbers not read from repo here. [Unverified] current leaderboard values.

**Strengths**: best-in-class repo map (PageRank over tags); battle-tested edit formats + model-specific defaults; layered fuzzy apply with git merge fallback; git-native undo; architect/editor split lets a reasoning model plan and a cheap model edit; tiny context cost; model settings database.
**Weaknesses**: no agent loop/tool use/MCP/subagents/sandbox; dormant maintenance; Python/litellm; reflection cap 3; summary-only history management.
**Adopt**: repo map algorithm and weights (port to Rust with tree-sitter; Axiom needs symbol graph anyway, [INF] it can double as element-to-source index seed), model-settings table with per-model edit format and quirks, SEARCH/REPLACE as fallback format for models without good tool calling, architect/editor split as a native "plan model + apply model" option, apply-ladder (exact, whitespace-normalised, diff-match-patch, git merge).
**Avoid**: relying on prompt-parsed edits as the *primary* path for tool-calling models; committing automatically to the user's branch by default (offer shadow checkpoints instead; Aider's own `/undo` depends on clean commit history).
**Reusable components**: `repomap.py` algorithm, `queries/*.scm` tag queries (tree-sitter queries are Apache/MIT per upstream grammar repos; check each file header before copying), `search_replace.py` ladder, `model-settings.yml` data, `udiff_coder.py` prompt/hunk logic, `benchmark/` harness idea.

## 9. Cross-cutting conclusions for Axiom

1. **Import surface to build first** (cheap, high payoff, all verified above): AGENTS.md and CLAUDE.md (with `@import`, depth 4, and Claude's rule "AGENTS.md only if no CLAUDE.md" as default, configurable), GEMINI.md, `.cursor/rules/*.mdc`, `.clinerules` + `.cline/rules`, `.roo/rules*`, `.continue/rules`; SKILL.md from `.agents/skills`, `.claude/skills`, `.cursor/skills`, `.gemini/skills`, `.cline/skills`, `.roo/skills`; Claude-format `hooks` JSON (superset target; map Gemini/Cursor/Cline events onto it); `mcpServers` from `.mcp.json`, `.cursor/mcp.json`, `.roo/mcp.json`, Gemini/Cline settings. Roo modes (`.roomodes`) and Gemini TOML commands are separate, small importers.
2. **Native engine design**: Cline's layering (stateless loop crate, stateful orchestrator, hub daemon shared by all clients) matches Axiom's daemon-plus-Flutter shell; Gemini's policy engine (tiered priority TOML with admin tier) and OS sandbox args builders are the best security reference; Claude's sandbox (Seatbelt/bwrap + network proxy) is the proven model and `sandbox-runtime` is open source.
3. **Edit strategy**: ship a tool-call `str_replace` editor (exact-once, Cline/Claude style) with a fallback ladder (exact, whitespace-normalised, regex-tokens, fuzzy; Gemini/Aider) and `apply_patch` V4A for models trained on it (Cline, Aider `patch`, Roo). Keep SEARCH/REPLACE and udiff as prompt formats for weak-tool-calling models and for architect/editor mode. Reject placeholder omissions (Gemini detector).
4. **Context**: constants differ widely: Gemini compresses at 50% and keeps 30%; Cline at 90% with 70% target and 20k preserved; Roo configurable 5 to 100%; Aider never compacts but summarizes to 1/16 of input (1024..8192 tokens). [INF] The common winning move is cheaper than summarizing: mask/offload old tool outputs to files first (Gemini 50k protect/30k prune; Cursor files-for-everything; Claude MCP results > 50k chars to file), then summarize. Make thresholds per-model and configurable; protect the last N turns (Gemini 3).
5. **Output caps**: converge on about 2,000 lines / 2,000 chars per line for reads and 40k to 48k chars for command/search output with head+tail elision and recovery notice at the edges (Gemini 40k, Cline 48k). Persist full output and give a read tool (Roo `read_command_output`, Cursor temp files).
6. **Deferred tools / code mode**: only Claude Code (docs) and Cursor (blog) defer MCP tool schemas (names only up front; Cursor reports -46.9% tokens; Anthropic reports 98.7% in a code-execution example). None of the five open projects implement it. Axiom should implement a tool-search/deferred registry natively; code-execution-with-MCP needs the sandbox first.
7. **Checkpoints**: three designs: shadow repo (Gemini, old Roo/Cline), stash-with-private-index in the real repo (new Cline), git auto-commit (Aider), files-only snapshot outside git (Cursor, Claude). Recommend the shadow repo (isolated gitconfig/env, per project hash) restoring files + conversation + pending tool call (Gemini), plus a note that shell side effects are not covered (Claude says Bash changes untracked).
8. **Subagents**: Claude's model (definition files, tool allowlists, fresh context, nesting depth 3, 20 concurrent, worktree isolation) is the benchmark; Cline's blanket approval and no-MCP-in-subagents are cautionary; Gemini's subagents-as-tools and A2A are worth supporting for delegation to external harnesses.
9. **Loop and failure guards**: identical-call counters (Roo 3, Gemini 5 + content 10 + LLM judge, Cline signature counter), max turns (Gemini 100 main, 30 sub), output-cut recovery 3 (Cline), provider retries 3 to 10 with backoff to 15 s (Cline) or 10 min (Roo).
10. **Maintenance risk**: Roo archived, Continue read-only, Aider dormant; only Gemini CLI and Cline are active open references. Copy ideas and data, do not track them as upstreams.
11. **Delegating to existing harnesses** [INF]: Gemini (`acp-mode.md` ACP and `a2a-server`), Cline (hub WebSocket, ACP in `apps/cli/src/acp`), Claude Code (Agent SDK, headless `-p`) all expose programmatic surfaces; Aider via CLI scripting only. Priority for adapters: ACP/headless JSON of Claude Code, Gemini, Cline.
