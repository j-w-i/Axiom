## Behaviour implemented
- **`OutputPanel.tsx`** is rendered through `Panel` (title "Console", `testId="output-panel"`).
  - **Meta:** while a task runs, it shows the LED, the mono label and the elapsed time in `mm:ss`. After the task, it shows the last command with an on or err LED.
  - **Tools:** Copy all output, Clear, and Hide console (Mod+J), all IconButtons with hints.
  - **Prompt:** a `$` sigil and a borderless mono input. It shows `btn--quiet` Run, or `btn--danger-quiet` Stop while running. `:focus-within` draws an inset `--accent-line` hairline.
  - **Empty output:** "Run a command in this workspace".
  - **Unchanged:** the ContextMenu, the testids, `.output__row`, `data-stream` and `data-kind`.
- **`src/ui/clock.ts`:** `formatElapsed` moved here from `shell/transport.ts`, which re-exports it, so components need not import `shell/`. It adds `useClock(active)`, a 1 Hz clock that skips updates while the window is idle.
- **`Panel`** takes an optional `testId`.
- **Workbench** passes `onHide={ctx.togglePanel}`.
- **CSS:**
  - All console rules are in `styles/components/console.css` and use only tokens.
  - The old output rules were removed from `app.css`, and `.panel__bar` / `.panel__bar .input` were removed from `panel.css`.
  - The focused-region rule (`shell.css`) and smoke check 4f now target `[data-region="console"] .panel__head`.
- **Shots harness:** freezes `.console__time` as well as `.transport__time`.

## Performance findings fixed in this task
1. **P12 regression from the header LED.** The first build had about 150 frames over 20 ms against about 45 for base, and under-stream p95 was about 4 ms worse.
   - **Cause:** a second pulsing LED, the console's "run" LED, next to the transport's.
   - **Fix:** the console LED is static. motion-system §5.3 already requires this: one running indicator animates.
2. **Residual cost per output batch.** Each batch re-rendered the header's three Radix-tooltip buttons. The meta and tools are now memoised, and `onHide` goes through a ref because `togglePanel` is a new function on every Workbench render.
3. **The bench `output` scenario was broken since SHELL-002.**
   - **Cause:** it clicked the command field at a window fraction (y 0.704). After SHELL-002 moved the console, that point is in the editor, so `seq` never ran.
   - **Effect:** it reported about 1 ms "settled" for both builds and never failed.
   - **Fix:** it now focuses the field with Ctrl+Shift+R (parity T-7) after a click in the editor, and reports `null` if the output region never changed. Qt keeps its click.
   - Recorded in `performance.md`. The 79.2 ms QA-002 baseline predates SHELL-002, so it is valid.
