# M1.6-EDITOR-002: Monaco theme from syntax tokens; region focus shortcuts

## Objective
Monaco's `axiom-dark` and `axiom-light` themes are generated entirely from the design
tokens: chrome colours from `--editor-*` and syntax rules from `--syn-*`. The editor
font defaults to the bundled IBM Plex Mono 13/20 (or the fallback stack if D2 is
rejected). Three region-focus shortcuts (Ctrl/⌘+0 side bar, Ctrl/⌘+1 editor,
Ctrl/⌘+\` console prompt) are added after a conflict check against Monaco's bindings.
Typing latency is unchanged.

## Context
- `docs/design/design-system.md` §2.2 (`--syn-*`, `--editor-*`), §5 (code type).
- `docs/design/workspace-spec.md` §1 (region focus shortcuts), §2.3 (Monaco
  appearance).
- Prototype mapping: `experiments/e5-visual-concepts/src/monaco.ts` (`themeFrom`:
  the token → rule table to reproduce, including the `--syn-keyword-style` hook).
- Current: `apps/desktop-tauri/src/editor/surface.ts` (`defineThemes()` reads 9
  tokens via a hidden probe element and canvas hex conversion).

## Required interfaces
- Editor bridge 1 (frozen): no message changes. `ConfigurePayload` font
  family/size/wrap keep coming from settings; only the *default* family changes.
- `editor/src/monaco-setup.ts` (shared, unchanged).
- Tokens from SYSTEM-001: `--syn-text, -comment, -keyword, -type, -string, -number,
  -punct, -macro`, `--syn-keyword-style`; `--editor-bg, -gutter, -line, -lnum,
  -lnum-active, -selection, -cursor, -guide, -guide-active`; `--surface-overlay`,
  `--line-strong`, `--scroll-thumb(-hover)`, `--warn`, `--danger`; `--font-code`,
  `--code-size`, `--code-leading`.

## Implementation requirements
1. Rewrite `defineThemes()` to emit the rule list of the prototype's `themeFrom`:
   - tokens `""`, `comment` (italic), `keyword` (fontStyle from
     `--syn-keyword-style`, empty in the recommended direction), `keyword.type`,
     `type`, `type.identifier`, `identifier`, `string`, `string.escape`, `number`,
     `constant`, `delimiter`, `operator`, `annotation`, `attribute`, `keyword.md`,
     `variable.md`, `strong` (bold);
   - colours: `editor.background`, `editor.foreground`, `editorGutter.background`,
     `editor.lineHighlightBackground` (`--editor-line`), `lineHighlightBorder`
     transparent, line numbers (+active), `editor.selectionBackground` and
     `inactiveSelectionBackground`, `editorCursor.foreground`, indent guides
     (+active), `editorWidget.background`/`border`, `editorBracketMatch.border`
     (`--editor-guide-active`, transparent background), `focusBorder` transparent
     (focus is shown by the region rule), scrollbar slider (+hover/active),
     `minimap.background`, `editorWarning/Error.foreground`.
2. Keep the hex conversion through canvas and add alpha support (`#rrggbbaa` from
   `rgb(… / a)`), as the prototype's `hex()` does.
3. Themes are regenerated when `data-theme` changes and when tokens change in
   development (HMR), and are applied with one `monaco.editor.setTheme` call.
4. The default editor font when the setting is empty: `getComputedStyle(root)
   .getPropertyValue("--font-code")`, `--code-size` 13, line height 20
   (`--code-leading`). Call `monaco.editor.remeasureFonts()` once after
   `document.fonts.ready`.
5. Region focus in `shell/shortcuts.ts` (capture phase, like the others):
   Mod+0 → focus the tree (`[role=tree]`), only if the side bar is visible (otherwise
   show it first); Mod+1 → `documents.focusEditor()`, or the existing equivalent bridge
   command if present (no new bridge message); Mod+\` → focus the console prompt
   (showing the console if hidden). Before binding, list Monaco 0.57's default
   keybindings for these chords on each OS (the KeyMod table in the completion report).
   On conflict, the shell binding wins only outside a focused Monaco **unless** the
   chord has no Monaco action. Record the decision per chord.
6. If D2 is rejected, the default font is the fallback mono stack from
   `design-system.md` §5, and requirement 4's remeasure still applies.

## Constraints
- No change to `editor/src/*` or to the bridge-1 message set (frozen; governance).
- The typing path must not gain work: theme work happens only on theme or settings
  change.

## Non-goals
- Semantic highlighting (LSP, M4); user-editable syntax themes (M7); minimap removal.

## Acceptance criteria
1. Syntax colours in a Rust and a Markdown file match the token values (canvas pixel
   sampling in an e2e check on 3 known tokens: `fn` keyword, a string, a comment).
2. Switching theme recolours the editor without reloading models; selection, cursor
   and guides use brass/neutral as specified.
3. Mod+0, Mod+1 and Mod+\` move focus as specified, and the focused-region rule
   (SHELL-002) follows.
4. Typing p95/p99 within P1 (≤ baseline + 1 / + 2 ms).
