# T-03: Build the Tauri host in the root Cargo workspace

## Objective
The Tauri host crate `src-tauri` builds from the root `Cargo.toml`. It starts
the app with `--daemon` and `--data-dir`, answers `--version` without a display,
exits non-zero with a message when the webview cannot start, and exposes exactly
the seven host commands of architecture.md §2.3 plus `dialog:allow-open`.

## Context
Source: implementation-roadmap.md §1 (wave B), §2 (T-03), §6 (`dev-setup.md`).
Host surface: `docs/migration/qt-to-tauri/architecture.md` §2.1 (invariants) and
§2.3 (command table). Security: §2.6 and `docs/architecture/security.md`.
Headless GUI runs: `AGENTS.md` pitfalls — Linux GUI runs use
`apps/desktop-tauri/scripts/headless.sh`. Parity row S-11 (`--version`) is
from `docs/migration/qt-to-tauri/feature-parity.md`.

## Required interfaces
- `apps/desktop-tauri/src-tauri/` (existing: `Cargo.toml`, `build.rs`,
  `capabilities/`, `permissions/`, `tauri.conf.json`, `src/`, `tests/`).
- `crates/desktop-bridge` (`axiom-desktop-bridge`, created by T-02): the host
  depends on it; do not reimplement the bridge.
- `Cargo.toml` root members and `[workspace.dependencies]`.
- `scripts/check_deps.py` `ALLOWED` map.

## Implementation requirements
1. Add `apps/desktop-tauri/src-tauri` to the root `Cargo.toml` members; the
   package name is `axiom-desktop-tauri`. Its dependency on the bridge is
   `axiom-desktop-bridge` by path (not a registry version).
2. CLI (clap, already in workspace dependencies): `--daemon <path>`,
   `--data-dir <path>`, `--version`. `--version` prints the host version and
   the protocol version (0.1) and exits 0 before any window or webview is
   created.
3. Startup: if the webview cannot be created (no display, missing WebKitGTK,
   missing WebView2), print a one-line message to stderr and exit with a
   non-zero code. The daemon is never started in this path.
4. `build.rs` pins the command list (`AppManifest::commands`) to exactly:
   `host_subscribe`, `daemon_request`, `daemon_cancel`, `daemon_restart`,
   `app_info`, `open_external`, `app_quit`.
5. `capabilities/main.json` grants window `main` exactly those seven commands
   and `dialog:allow-open`, nothing else.
6. Test `src-tauri/tests/capabilities.rs` (new file) parses `capabilities/*.json`
   and `build.rs`, and fails on any command or permission not listed in
   architecture.md §2.3. This test is part of the required test set.
7. `daemon_request` forwards only methods for which
   `axiom_desktop_bridge::ui_callable(method)` is true; `initialize` and `shutdown`
   are rejected by the host.
8. Do not enable `tauri-plugin-shell` or `tauri-plugin-fs`; do not add any command
   that reads or writes files or starts processes (roadmap T-03 "must not").
9. Errors: `thiserror` enum in the host; no `unwrap`/`expect` outside tests.
10. Update `scripts/check_deps.py` `ALLOWED` with
    `"axiom-desktop-tauri": {"axiom-desktop-bridge", "axiom-protocol"}` (exact set
    you need, nothing more) and the matching row in `docs/architecture/modules.md`.

## Constraints
- Protocol 0.1 and editor bridge 1 are not changed.
- Tauri and its plugins are the only new GUI dependencies; their versions are the
  ones already pinned in `apps/desktop-tauri/src-tauri/Cargo.toml`.
- The host holds no workspace logic; it never resolves workspace paths
  (governance rule 6).
- `apps/desktop-tauri/src/` (UI) is not changed (T-06, T-07 and T-08 own it).
- Linux build requires WebKitGTK 4.1 development packages; use
  `apps/desktop-tauri/scripts/sysroot.sh` when root is not available.

## Acceptance criteria
1. `cargo build -p axiom-desktop-tauri --release` succeeds on ubuntu, macos and
   windows CI runners (req. 1).
2. `axiom --version` prints the version and protocol 0.1 and exits 0 with
   `DISPLAY` and `WAYLAND_DISPLAY` unset (req. 2).
3. With no display available and `--daemon` set, the binary exits non-zero with
   a one-line message (req. 3).
4. `capabilities.rs` passes and the granted set equals the seven commands plus
   `dialog:allow-open` (req. 4–6).
5. `daemon_request("initialize")` and `daemon_request("shutdown")` are rejected
   by the host (req. 7).
6. `scripts/check_deps.py` passes with only the listed edges (req. 10).

## Tests
- `scripts/check.sh rust` — green.
- `cargo test -p axiom-desktop-tauri` — includes `tests/capabilities.rs` and the
  host unit tests for req. 7.
- `cargo run -p axiom-desktop-tauri -- --version; echo $?` with display variables
  unset — prints version, exit 0.
- `env -u DISPLAY -u WAYLAND_DISPLAY cargo run -p axiom-desktop-tauri -- --daemon target/debug/axiomd` — exits non-zero with a message.
- CI `tauri` build job on three OSes (T-09 wires it; until then report
  "unverified on macOS/Windows" if CI has not run).

## Failure conditions
- Any command or plugin beyond the seven commands and `dialog:allow-open` is
  granted, or the capability test is weakened.
- `--version` opens a window or needs a display.
- The host reads or writes workspace files or spawns processes.
- A cell of the three-OS build is red without a recorded cause: not Tested.
- `scripts/check.sh rust` not green.
