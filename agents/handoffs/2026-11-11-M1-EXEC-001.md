## Behaviour implemented
- Ids `t1`, `t2`, …; argv/shell spawning; stdin null; stdout/stderr read concurrently in ≤ 8 KiB chunks.
- A `Sequencer` mutex assigns `seq` and sends in one critical section, so seq order equals channel order across both streams. Channel capacity 256 gives backpressure to the child through the pipe.
- Incremental UTF-8 per stream (`utf8.rs`), U+FFFD for invalid bytes, a dangling partial sequence at EOF becomes one U+FFFD.
- `Exited` is sent after the process is reaped and both pipes drained; task history is updated *before* `Exited` is sent, so `list` is already consistent for the client.
- `cancel`: marks cancelled, SIGTERM to the group, SIGKILL after 3 s; a final group kill after a cancelled task exits removes stragglers holding pipes.
- History: per workspace, 50 finished kept, running never pruned.
- Dropping the last `Executor` clone kills the process groups of running tasks (`Inner::drop`), plus `kill_on_drop`.
- A dropped event receiver does not block the child (output is drained and discarded).

## Deviations and decisions
- Cancelled `sleep` reports `signal: Some(15)` (SIGTERM) with `exit_code: None`; spec only fixes signal 9 for the stubborn case.
- Spawn failure for `Shell` commands names `sh`/`cmd`.
- `cancel` returns once the request is registered (the supervisor performs terminate/kill); `cancel_all` waits for exit.
- `ExecBackend` is `Send + Sync` (needed to share inside `Arc`).
- Any task id (including finished) is accepted by `cancel` until it is pruned from history; afterwards `NotFound`.

## Known defects / limitations
- A grandchild that moves to its own process group/session escapes `killpg` (same as any pgid approach).
- Pid reuse: group signals target the pgid of a child we spawned; after the child is reaped the pgid is only signalled by the final cleanup kill within the same supervisor step, a tiny window.
