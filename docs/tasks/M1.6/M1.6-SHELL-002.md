# M1.6-SHELL-002: Workbench frame: panels, splitters, layout persistence, focused region

## Objective
The window's regions (side bar, editor column, console) use the new `Panel` and
`Splitter` components and the material grammar. Structure is flat, separated by tone
and seams; splitters resize without a React render per pointer event; layout is
persisted as `axiom.layout.v2` and can be reset; the region holding keyboard focus is
marked.

## Context
- `docs/design/workspace-spec.md` §1 (layout model, dimensions, focus rule).
- `docs/design/design-system.md` §2.2 (surfaces), §4 (flat material), §6 (sizes),
  §8 ("Focused region"), §9 (`Panel`, `Splitter`).
- `docs/design/motion-system.md` §3.5 (no animation during drag).
- Prototype: `experiments/e5-visual-concepts/src/workbench.ts` (`useResize`),
  `src/concepts/r.css` (flat headers), `src/base.css` (`.panel`, `.split`).

## Required interfaces
- `src/shell/Workbench.tsx` from SHELL-001; `ui/` primitives from SYSTEM-003;
  `usePresence` from INTERACTION-001 (mounting only here; panel motion is
  INTERACTION-002).
- Tokens: `--surface-canvas`, `--surface-chrome`, `--surface-panel`,
  `--surface-editor`, `--line`, `--line-mid`, `--accent`, `--accent-line`, `--head-h`
  (30), `--s-*`.

## Implementation requirements
1. `src/ui/panel.tsx` exports `Panel({ title, meta, tools, region, children })`:
   `<section aria-label={title} data-region>` with a header (`--head-h` 30 px,
   `--surface-panel`, 12/600 title in `--text`, meta in `--text-muted`
   `--text-small`, tools right-aligned) and a 1 px `--line-mid` rule below. No gradient
   and no lit edge (flat material).
2. `Splitter` (same file) replaces `ui/primitives.tsx`'s splitter: a 1 px visible
   `--line` seam with a 7 px hit zone (`::after` inset −3 px). On hover, after a
   120 ms delay, a 3 px `--accent-line` overlay appears (opacity transition
   `--dur-1`). It has `role="separator"`, `aria-orientation`, `aria-valuenow/min/max`,
   and arrow keys ±16 (Shift ±48). **New:** Home resets to the default, as does
   double-click.
3. Drag writes `--side-w` / `--panel-h` on the workbench element inside a
   `requestAnimationFrame`-coalesced handler, with pointer capture, and commits to
   React state once on `pointerup` (prototype `useResize`). Limits: side bar 180–480
   (default 252), console 120–520 (default 232), clamped to the window.
4. Layout persistence: `axiom.layout.v2` = `{ sidebar, panel, sidebarVisible,
   panelVisible }`, migrated from v1 on first load (v1 is read once, then removed).
   The "Reset Layout" command (palette, View menu) restores the defaults, including
   the < 900 px rule that starts with the side bar hidden.
5. Region surfaces: side bar and console `--surface-panel`; editor column
   `--surface-editor`; structural seams `--line`.
6. Focused region: the workbench tracks `focusin` and `focusout` and sets
   `data-focused-region="files|editor|console"`. The matching panel header gets a
   2 px `--accent` rule along its top edge (`inset 0 2px 0`).
7. Move these styles from `app.css` into `styles/components/panel.css` and
   `styles/shell.css`, using new tokens only (no legacy aliases in moved rules).

## Constraints
- No new region or placeholder: no activity rail and no agent dock (D4, governance
  rule 9).
- Monaco must re-lay out once per drag commit (its `automaticLayout` sees one size
  change per frame at most; no per-pointer React render).
- Accessibility rules of `docs/migration/qt-to-tauri/design-system.md` §3 for the
  splitter remain.

## Non-goals
- Show/hide motion of panels (INTERACTION-002); the title row (SHELL-003); the
  explorer rows (SHELL-004); console contents (SHELL-006).

## Acceptance criteria
1. Dragging either splitter produces exactly one React commit per drag (dev profiler
   counter) and never more than one layout per frame.
2. Keyboard resizing works (arrows, Shift+arrows, Home), and double-click resets.
3. A v1 layout in `localStorage` is migrated to v2 with identical values; "Reset
   Layout" restores the defaults.
4. Focusing the tree, the editor or the console prompt moves the 2 px brass rule to
   that panel's header.
5. Panels have no gradients or bevels; seams render as single 1 px lines at 100% and
   200% (no doubled seams at splitters).

P4 (splitter drag: p95 ≤ 17.5 ms, one commit per drag) through the QA-002
`splitter-drag` scenario, before and after. P1 typing is unchanged (±1 ms).

## Failure conditions
- Any per-pointer-event React render during a drag.
- The focused-region marker is missing for any of the three regions.
- An e2e geometry or parity check is changed to accommodate the new layout without
  reviewer sign-off.
