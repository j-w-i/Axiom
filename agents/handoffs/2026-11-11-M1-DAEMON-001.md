## Behaviour implemented
- CLI: `--data-dir`, `--log-level error|warn|info|debug` (default warn), `--version`. `--data-dir` wins over `AXIOM_DATA_DIR`.
- Logging to stderr only. Startup: SchemaTooNew → one stderr line, exit 2; other store failure → exit 1; corruption recovery logged once at error.
- Handlers in `src/handlers/{workspace,fs,task,settings}.rs`, one function per method; router registration in `src/router.rs` (macro `wire!`); known settings table in `src/settings.rs`.
- `workspace/open` → recent_touch + `workspace.lastRoot` (one `spawn_blocking`); `close` → `cancel_all`, drop watcher, close; `recent` → list(20) filtered to existing dirs; state keyed by canonical root, `null` deletes, `TooLarge` → `too_large`.
- `fs/watch`: a forwarder task owns the `WatchHandle`; `false` aborts it (dropping the handle). Idempotent both ways.
- `task/start`: cwd via `Workspace::resolve`; spawn failures and missing cwd come from `Executor`; the event forwarder is registered with `after_response`.
- `settings/get|set`: stored over defaults; known keys validated (`invalid_params`, details `{key}`); `null` resets; `settings/didChange` with effective values is sent after the response.
- Shutdown hook: stop watchers, `executor.shutdown()`.

## Deviations and decisions
- Added a lib target (`axiomd`) beside the binary so the wiring test can reach `build_router`; spec said "binary" only.
- The `settings/didChange` notification goes only to the requesting connection (the daemon serves exactly one connection in M1); it is sent via `after_response`, so it follows the response.
- `workspace/close` first checks the workspace exists (so `workspace_not_open` is returned before side effects).
- `settings/get` with explicit keys omits unknown, never-stored keys.
- Settings key `workspace.lastRoot` is written through the same transaction as `recent_touch`... as two store calls inside one `spawn_blocking` (not one SQL transaction).
- On stdin EOF `serve` returns Ok and the process exits with `std::process::exit` after `shutdown_background`, so a blocked stdin read cannot delay exit.

## Known defects / limitations
- Tasks' event forwarder drains the receiver but does not stop the task when the connection drops; `shutdown` hook (also run at EOF) cancels all.
- Multi-connection `settings/didChange` broadcast is not implemented (single connection in M1).
