# M1-WS-002: File watching

## Objective
`Workspace` can report debounced, deduplicated, ignore-filtered file changes
matching the protocol's `fs/didChange`.

## Context
Read: `docs/protocols/ipc.md` §`fs/didChange`; `crates/protocol/src/fs.rs`
(`DidChangeParams`, `FileChange`, `ChangeKind`).

## Implementation requirements
```rust
impl Workspace {
    /// Subscribes to changes (recursive), delivered as batches. Each handle
    /// is an independent subscriber that receives every batch emitted while
    /// it exists. One OS watcher is shared by all handles of a workspace: it
    /// is started by the first `watch()` and stopped when the last handle
    /// is dropped.
    pub fn watch(&self) -> Result<WatchHandle, WsError>;
}
pub struct WatchHandle { pub changes: tokio::sync::mpsc::Receiver<Vec<FileChange>>, /* guard */ }
```
1. Use `notify` 8.x `RecommendedWatcher`, recursive on the root.
2. Convert host paths to `WorkspacePath` (strip root, `/` separators); drop
   events outside the root.
3. Filter exactly as `ipc.md` §`fs/didChange` says: drop an event if the
   path is `.git`, is under `.git`, or is **under a directory** that the
   ignore rules mark ignored (reuse the matcher from M1-WS-001). An ignored
   *file* in a non-ignored directory, and an ignored directory entry itself
   being created or removed, ARE reported: the explorer lists them, so it
   must hear about them.
4. Debounce: collect for 100 ms after the first event of a batch, then emit
   one `Vec<FileChange>` sorted by path. Merge rules per path within a batch:
   `created`+`modified` → `created`; anything + `removed` → `removed`;
   `removed`+`created` → `modified`. Renames are reported as `removed` (old)
   and `created` (new).
5. On watcher error/overflow (`notify` rescan flag or error event): emit a
   batch containing exactly `FileChange { path: "", kind: Modified }`.
6. When an ignore file (`.gitignore`, `.ignore`) changes, invalidate the
   matcher cache for its directory.

## Constraints
Dependencies added: `notify` (8.x stable; not a 9.0 release candidate).

## Acceptance criteria
Tests (allow up to 5 s for an event before failing; assert on eventual
content, not on exact batch boundaries):
- create, modify, remove a file → corresponding kinds;
- create then immediately modify → single `created`;
- change inside `.git/` and inside an ignored directory → no batch within 500 ms;
- an individually ignored file (`debug.log` with `*.log` ignored) in a
  non-ignored directory → reported;
- two handles both receive a batch; dropping one leaves the other working;
- rename → `removed` + `created`;
- dropping the handle stops delivery;
- a write through `Workspace::write_text` produces a `modified`/`created`.

## Tests
`scripts/check.sh rust`; run `cargo test -p axiom-workspace watch` 20 times
in a loop to check for flakiness and report the count of passes.

## Failure conditions
Tests are flaky (any failure in 20 runs) → fix or report; do not add
retries that hide lost events.
