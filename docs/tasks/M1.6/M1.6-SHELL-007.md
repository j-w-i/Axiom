# M1.6-SHELL-007: Welcome, empty, loading and error states

## Objective
Every non-content state of `docs/design/workspace-spec.md` §6 is designed rather than
left as fallback text: Welcome, backend connecting and failed, workspace opening,
empty folder, listing error, no document, output empty, file too large, plus the
restyled banners. Copy follows the §6 rule: what happened, what it affects, and the
one action that fixes it.

## Context
- `docs/design/workspace-spec.md` §6 (table: the spec of record).
- `docs/design/design-system.md` §9 (`Banner`), §8 (disabled), §2.3 (faint text only
  for non-essential content).
- `motion-system.md` §5 (no shimmer; stepped LED while connecting).
- Current: `Welcome.tsx`, the `EditorArea.tsx` empty editor, banners in `App.tsx` /
  `shell/` (SHELL-001), the explorer empty and error rows.

## Required interfaces
- Data already in the stores: `daemon.state`/`message`, `ws.opening`, `ws.recent`,
  `ws.error`, `docs.banner`, `prefs.error`, tree error rows.
- `data-testid="welcome"` and existing banner behaviour (e2e: backend-failed banner,
  too-large banner E-4).

## Implementation requirements
1. **Welcome** (editor area, no workspace): a centred column 460 px wide, top-aligned
   at 22% of the area's height:
   - the brass mark at 32 px;
   - "Open a folder to start" (15/600);
   - one line of 13 px `--text-muted`: "Axiom opens folders through its backend,
     axiomd.";
   - a primary **Open Folder…** with `Mod O` keycaps, disabled with the tooltip
     "Waiting for the backend" until `ready`;
   - a "Recent" label (12/600 `--text-muted`, sentence case) and ≤ 8 rows of 28 px
     (name 13/500, path mono 11 `--text-faint`, home shortened to `~`), as flat rows
     with a `--hover` background.
2. **Backend connecting:** no overlay. The status bar LED is stepped `run`; Welcome
   actions are disabled as above.
3. **Backend failed:** a danger `Banner` under the title row (SYSTEM-004 styling:
   `--danger-soft` background, `--danger` glyph, message in `--text`, action
   **Restart backend**), with `role="alert"`.
4. **Opening workspace:** the tree area shows 6 static skeleton rows (22 px,
   `--hover` bars of 40–70% width, no animation) for up to 1 s, then the text "Still
   listing…" in `--text-faint`.
5. **Empty folder:** "This folder is empty" plus a quiet Refresh button.
   **Listing error:** a row with a danger glyph, the message and a quiet **Retry**
   (calls the existing refresh path).
6. **No document open:** the editor well shows four rows (label 13 `--text-faint`,
   keycaps right): Command palette `Mod K`, Go to file `Mod P`, Run command
   `Mod Shift R`, Toggle console `Mod J`. These are the existing four, restyled.
7. **File too large / binary / workspace and settings errors:** the existing warning
   banners in the new `Banner` style, with copy unchanged except removing exclamation
   marks.
8. Styles in `styles/components/states.css` and `welcome.css`, new tokens only.

## Constraints
- No new data, store fields or host calls. "Drop a folder here" is shown only if
  drag-and-drop opening exists (it does not in M1, so it is not shown).
- No spinners or shimmer for loading. Skeleton bars are static.

## Non-goals
- Onboarding tours or a Learn view (research §5: rejected); the conflict and unsaved
  dialogs (SURFACES-002 owns the settings dialog; dialogs are restyled by
  SYSTEM-004).

## Acceptance criteria
1. States S1, S2, S3 and the empty, error and opening tree states render as specified
   in both themes.
2. With the backend not ready, Open Folder… is disabled and its tooltip explains why.
3. The too-large banner (E-4) and backend-failed banner e2e checks still pass.
4. No running animation in any of these states except the stepped connecting LED
   (`document.getAnimations()` check).

## Tests
- e2e smoke: existing welcome, backend-failed and too-large checks green; new
  `welcome recent row opens workspace` (if not already covered) and
  `empty folder state shows refresh`.
- `pnpm test`: snapshot of Welcome markup for `ready=false` (disabled plus tooltip).
- `scripts/check.sh` green.

## Visual verification
S1, S2, S3, S14 (Welcome at 720×480), and the tree empty, error and opening states
(add them to the QA-001 state list as S1b–S1d) in dark and light. Reference
`docs/design/workspace-spec.md` §6; there is no prototype screenshot for these, so the
reviewer checks against the spec table. §7 checklist.

## Performance
P2 startup: Welcome is the first paint; cold/warm start → Welcome painted, before and
after (≤ baseline + 40 ms including fonts).

## Failure conditions
- Any invented action or data; any shimmer or spinner; copy with exclamation marks or
  without an action where an action exists.

## Documentation updates
`docs/design/workspace-spec.md` §6 (final copy strings); `docs/roadmap/current.md`.

## Handoff
The copy table as shipped, screenshots of each state, startup numbers.
