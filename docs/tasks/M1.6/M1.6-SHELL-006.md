# M1.6-SHELL-006: Console: output, prompt, stderr presentation, context menu

## Objective
The output panel becomes the **Console**: a flat panel header carrying the task
summary and tools, virtualised mono output in which stderr is marked but not painted
red (D6), a recessed `$` prompt with Run/Stop at its right, and the restyled context
menu. The command, history, streaming and Stop behaviour are unchanged.

## Context
- `docs/design/workspace-spec.md` §2.4 (the spec of record); `concepts.md` §1.3 item 5
  (why stderr must not be red) and §6 D6.
- `docs/design/design-system.md` §4 (recessed prompt), §5 (`--out-size` 12 /
  `--out-leading` 18).
- Prototype: `experiments/e5-visual-concepts/src/shared.tsx` (`Output`, `Prompt`),
  `src/concepts/a.css` (`.ca .out*`, `.ca .prompt*`).

## Required interfaces
- `TasksStore` (`rows`, `running`, `label`, `history`, `run`, `stop`); the existing
  virtualisation (`ROW_H = 18`) and stick-to-bottom logic.
- `data-testid`s `output-panel`, `output`, `command-input`, `run`, `stop`,
  `output-menu` (e2e smoke and parity). Keep them on the equivalent elements.
- The panel frame from SHELL-002 (`Panel`).

## Implementation requirements
1. Header (`Panel`, region `console`): the title "Console". **The view strip (Output /
   Problems / Terminal) is not rendered while Output is the only view** (governance
   rule 9; Problems arrives in M2, Terminal in M4). Meta: the task LED, the label
   (mono 12) and the elapsed time (muted; static text). Tools: Copy all, Clear, Hide
   console (Ctrl+J), as IconButtons with tooltips and `data-hint`.
2. Output rows: mono `--out-size` 12 / 18 px line height (unchanged `ROW_H`), padding
   0 12 px.
   - stdout `--text`;
   - stderr `--text-muted` with a gutter glyph `▏` in `--warn` at 55% opacity and the
     existing visually-hidden "stderr:" prefix (D6);
   - status rows: success `--ok-text` "✔ …", failure `--danger` "✖ …", errors
     `--danger`;
   - notices `--text-faint`.
   If D6 is rejected: stderr keeps `--danger` text and the gutter glyph in `--danger`.
3. Prompt (`--prompt-h` 30): recessed (`--surface-well`, `inset 0 1px 0 --line`).
   The `$` sigil uses `--accent-text` mono 600. The input is borderless mono 12.
   Right side: while running, a quiet danger **Stop** (`btn--danger-quiet`, stop
   glyph); otherwise a quiet **Run** (play glyph). While the prompt has focus, an
   inset 1 px `--accent-line` hairline marks it, and the input has no outline of its
   own. History with ↑/↓ and Enter-to-run are unchanged.
4. Empty output: "Run a command in this workspace" (`--text-faint`, UI font).
5. Context menu: Copy selection / Copy all through SYSTEM-004's `ContextMenu` if
   adopted; otherwise the existing menu restyled with the `Menu` styles. Ctrl+C copies
   the selection (unchanged).
6. All console CSS moves to `styles/components/console.css` with new tokens only;
   remove the `.panel__bar .input` full-width field and the purple Run button.

## Constraints
- Behaviour, row virtualisation and the 50k-line performance path are untouched.
- No new views, filters or search (no placeholder UI).

## Non-goals
- Problems view (M2), Terminal (M4), output search, ANSI colour rendering.

## Acceptance criteria
1. A `cargo build` style run (stderr progress lines) shows no `--danger` text except
   the failure status line; stderr rows are distinguishable by the gutter glyph and
   the screen-reader prefix.
2. The view strip is absent; the header shows the task meta while running.
3. Run/Stop toggle in the prompt follows `running`; F5/Shift+F5 still work.
4. All existing output e2e checks (stream order, stderr distinct, exit status, Stop
   kills the tree, context menu copy) pass unchanged.
