# 0019 Opening a file in the person's editor, and showing it in the system's file manager
**Decision** (D-3, as recommended). The host may start the person's own editor for a file of a session's folder, at a line, and show a file in Finder, Files or Explorer. Only because a person pressed the key that says so; never for an agent, never from what an answer, a file or a page says (SI-2).
**Which.** A fixed list, each with how it is told a line, from its own documentation: Visual Studio Code (`code -g FILE:LINE`), Cursor (`cursor -g`), Windsurf (`windsurf -g`), VSCodium (`codium -g`), Zed (`zed FILE:LINE`), Sublime Text (`subl FILE:LINE`), the JetBrains IDEs (`idea`, `pycharm`, `webstorm`, `goland`, `clion`, `rustrover`, `phpstorm`, `rubymine`: `--line LINE FILE`), Neovim and Emacs only in a terminal Axiom has (W-48). It is found as programs are (`harness/src/find.rs`): on the `PATH`, and on macOS also inside the application in `/Applications` or `~/Applications`, never in what an agent may write to. What is found is listed; a person picks one in Settings, or the first found is used. No command of a person's own: that is what a folder's commands are (W-37).
**How.** On the one spawn path (SI-7), outside the sandbox as the person's act (`Unsandboxed`, minted by the press), with the host's environment less what loads code (`Env::harness`). The file is one absolute argument that the host has made itself from the folder and a path within it, checked by handle to be a file there and not a link out of it; the line is a number. Nothing is passed through a shell. What it prints is not kept; it is not waited for.
**Showing a file:** macOS `open -R FILE` (`/usr/bin/open`, which reveals and opens nothing); Windows `explorer.exe /select,FILE`; Linux `xdg-open` on the file's folder, never on the file (T47); the file manager's own way to select a file (`org.freedesktop.FileManager1.ShowItems`) needs D-Bus, which can come later.
**What follows from it.** An editor may run what a folder's own settings say (`.vscode/tasks.json`, the editor's own trust of a workspace). That is the editor's, and Axiom starting it changes nothing that a person double-clicking the folder would not. Agents still never write those files (SI-11).
**Alternatives.** Opening by the system's association (`open FILE`): runs whatever is associated, which for an agent's file may be a program (T47). The client starting it: SI-14.
**Revisit.** When a person asks for an editor that is not on the list.
