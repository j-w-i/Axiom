# M3-MCP-001: MCP server and client

## Objective
`axiom mcp` / `axiomd --mcp` serve MCP over stdio as a protocol client of a daemon
(ADR-0015 §7); user-configured MCP servers' tools join a session's registry.

## Context
Epic 3.7. ADR-0015 §7; MCP spec (lifecycle, tools).

## Implementation requirements
1. Server: initialize (protocol version negotiation), `notifications/initialized`, `ping`,
   `tools/list` (from `agent/tools`, JSON schemas as given), `tools/call` (→ `agent/toolCall`,
   result as `content` text + `structuredContent`, `isError` for tool errors).
2. Client: start `agent.mcpServers` entries per session on first need, initialize, list, call;
   names `mcp.<server>.<tool>`; effect Execute+Network; processes stopped with the session.
3. Approvals: with an approving connection attached to the daemon, an `ask` from an MCP call
   surfaces there; otherwise denied with a hint.

## Acceptance criteria
1. A test MCP client (in-repo, speaking the spec) lists and calls `fs.read` and is refused
   `fs.applyPatch` under a deny rule; the audit log has both.
2. A fixture MCP server (in-repo test binary) provides a tool a scripted session calls.

## Tests
`cargo test -p axiom-agent mcp_`; `cargo test -p axiom-cli mcp`; `scripts/check.sh`.

## Failure conditions
An MCP call bypasses the gate.

## Documentation updates
`agents.md` §External agents and MCP; `docs/contributing/` usage note for connecting Claude Code / Codex.

## Handoff
Protocol versions accepted.
