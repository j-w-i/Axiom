# M1.6-SYSTEM-003: Control primitives, component gallery and the ui/ import-graph test

## Objective
`src/ui/primitives.tsx` provides the M1.6 control set in the approved material
grammar: Button, IconButton, Kbd/Keys, Badge, Led, Meter, Spinner, Field, Switch,
Segmented and Stepper, each with every state in `design-system.md` §8, styled from
one CSS file per component. A dev-only gallery renders them all in both themes, and
a test keeps `ui/` free of stores and Tauri.

## Context
`docs/design/design-system.md` §4 (material recipes), §8 (states), §9
(components, "Built in M1.6" column); `frontend-architecture.md` §2–§3 (layout,
CSS conventions), §7 (gallery); the prototype CSS
`experiments/e5-visual-concepts/src/concepts/{a,r}.css` (`.btn`, `.ibtn`, `.kbd`,
`.led`, `.switch`, `.seg`, `.field`, `.meter`) as the visual reference, not as code
to copy wholesale. The existing `Button`, `IconButton`, `Kbd` and `Segmented` APIs
are used by views: keep their props compatible.

## Required interfaces
- Tokens from SYSTEM-001 (`--raised-*`, `--recessed-*`, `--dur-press`, …).
- Current callers of `Button`, `IconButton`, `Kbd`, `Segmented`, `Banner`
  (`src/App.tsx`, `src/components/*`). Signatures stay source-compatible.

## Implementation requirements
1. `Button`: variants `default | primary | quiet | danger | danger-quiet`, `size?: "sm"`,
   `loading?: boolean` (stepped spinner replaces the leading icon, label kept,
   `aria-busy`, still focusable, click ignored). Raised recipe; pressed =
   inverted gradient + inset shadow + `translateY(.5px)` over `--dur-press`; focus =
   2 px `--focus` outline offset 1 px; disabled 42% opacity.
2. `IconButton`: mandatory `label` (type-enforced); optional `pressed` →
   `aria-pressed` and the recessed "engaged" recipe; 26×26, icon 16. The tooltip
   is wired in SYSTEM-004; until then keep `title`.
3. `Kbd` (single key) and `Keys` (`keys: string` like `"Ctrl Shift R"`, rendered as
   keycaps; `⌘` replaces `Ctrl` and `⌥` replaces `Alt` on macOS via `navigator.platform`): raised keycap
   recipe, 11 px, min width 16.
4. `Badge` (`neutral | accent`), `Count` (tabular-nums). No "mock" variant in production.
5. `Led` (`state: off | on | run | warn | err`, `label?` → `role="img"` +
   `aria-label`, else `aria-hidden`); `run` uses the stepped pulse
   `animation: led-pulse 1.6s steps(6) infinite` (`motion-system.md` §5).
6. `Meter`: determinate (`value` 0–1, `role="progressbar"`, label) and `RateMeter`
   (`levels: number[]` of 16 values 0–1, `role="img"` + label, 2×14 px bars,
   brass fill on `--line-mid`), with no tweening.
7. `Spinner`: 11 px ring, `animation: spin .8s steps(8) infinite`; static under
   `data-motion` reduced/off (a static three-quarter ring).
8. `Field` (`mono?`, `invalid?` → `aria-invalid` + danger border/ring,
   `describedBy?`), recessed; focus = `--accent-line` border + 2 px `--accent-soft` ring.
9. `Switch` (`role="switch"`, Space/Enter toggle), track recessed → brass when on,
   raised thumb sliding over `--dur-2`. `Segmented` (radiogroup; arrow keys move
   **and** select; a glide element with `translateX` over `--dur-2`). `Stepper`
   (− field +, Up/Down keys, min/max clamp, named buttons).
10. CSS: `src/styles/components/{button,icon-button,kbd,badge,led,meter,spinner,field,switch,segmented,stepper}.css`,
    imported by `primitives.tsx`; the corresponding rules are removed from `app.css`
    (callers keep working). State is expressed by ARIA/`data-*` attributes, not by
    state classes.
11. Gallery: `gallery.html` + `gallery/main.tsx` (a Vite dev entry, built only with
    `vite --mode gallery`): a grid of every component × every state of §8 (rest,
    hover forced via `data-force="hover"`, pressed, focus-visible, disabled,
    loading, engaged, invalid), with a theme toggle and a "Type" specimen section
    (all text tokens). `vite.config.ts` excludes it from `dist`.
12. `tests/ui-imports.test.ts`: fails if any file in `src/ui/` imports from
    `../state`, `../shell`, `../components`, `../daemon` or `@tauri-apps/*`.
13. Vitest component tests (React test renderer or `react-dom/server` +
    jsdom-free assertions): roles, names and ARIA states for each primitive.

## Constraints
- No new dependency. `ui/` stays store- and Tauri-free.
- Built only because M1 uses it (governance rule 9): no Select, no Mock badge.
- The visual grammar is strict: raised only for pressable, recessed for
  value/input/engaged.

## Non-goals
- Overlays (SYSTEM-004); restyling views (SHELL-*); motion presence (INTERACTION-001).

## Acceptance criteria
1. Every primitive exists with the states listed and is rendered in the gallery in
   both themes.
2. Existing views compile unchanged and the e2e suites (smoke, quit, geometry,
   parity) pass.
3. The import-graph test passes and fails on an injected bad import.
4. Keyboard: Switch toggles with Space; Segmented selects with arrows; Stepper
   changes with Up/Down (Vitest).
5. `vite build` output contains no gallery code (test).

## Tests
- `cd apps/desktop-tauri && pnpm test`: new `tests/ui-imports.test.ts`,
  `tests/primitives.test.tsx` ("IconButton requires a label and sets aria-pressed",
  "Button loading sets aria-busy and ignores clicks", "Segmented arrow keys select",
  "Switch toggles with Space", "Led with label has role img",
  "Keys renders platform modifiers"), `tests/gallery-excluded.test.ts`.
- `pnpm run check`, `pnpm run build`, `scripts/e2e.sh`, `scripts/check.sh`.

- `ui/` imports a store or Tauri.
