# M1.6-INTERACTION-002: Panel motion for the side bar and console

## Objective
Showing and hiding the side bar (Ctrl+B) and the console (Ctrl+J) carries continuity:
the region's box changes size in one frame, and its content slides and fades in or
out. Splitter drags stay free of animation and render no React commit per pointer
event.

## Context
`docs/design/motion-system.md` §3 rules 2 (layout changes once), 3 (input never
delayed), 4 (interruptible), 5 (no animation during drag); §4 rows "Side bar show /
hide", "Console show / hide", "Splitter hover". Prototype: the `motion-in-left` /
`motion-in-up` choreography in `experiments/e5-visual-concepts/src/base.css` and the
`useResize` CSS-variable drag in `src/workbench.ts`, which measured 0 frames > 20 ms
(`docs/design/concepts.md` §4).

## Required interfaces
- `usePresence`, motion tokens and `data-motion` from M1.6-INTERACTION-001.
- `Workbench.tsx`, `Panel`, `Splitter` and layout persistence from M1.6-SHELL-002.

## Implementation requirements
1. Side bar: when hidden, keep it mounted for `--dur-1` (90 ms) with
   `data-phase="out"` on its content wrapper (`out-left`: opacity → 0,
   `translateX(-8px)`, `--ease-in`), then remove its column in one commit. When shown,
   add the column in one commit and play `in-left` (from opacity 0,
   `translateX(-8px)`) over `--dur-2` (140 ms) with `--ease-out`.
2. Console: the same with `in-up`/`out-up` (`translateY(8px)`).
3. Only the content wrapper animates (transform + opacity). The panel box, the
   Monaco container and the splitter never animate; Monaco gets one layout per toggle.
4. Interruptible: toggling during an exit re-enters immediately from the rendered
   state (`usePresence` reopen); toggling 5 times in 300 ms ends in the correct final
   state with no stuck `data-phase`.
5. Focus: hiding a region that contains focus moves focus to the editor (existing
   behaviour, if any, is kept; otherwise move to the editor) on the input frame,
   before the exit animation.
6. Splitter drag: write `--side-w` / `--panel-h` on the workbench element inside a
   `requestAnimationFrame`-coalesced pointermove handler; commit to layout state once
   on pointerup (one React commit per drag). Keyboard resizing (arrows ±16, Shift ±48,
   Home resets) and double-click reset keep working and do not animate.
7. Splitter hover: the seam's `::before` highlight (`--accent-line`) fades in over
   `--dur-1` after a 120 ms `transition-delay`; no delay when dragging.
8. Reduced: fade only, 80 ms; off: instant (handled by tokens).

## Constraints
- Never animate `width`, `height`, `flex-basis` or `grid-template-*`.
- Layout persistence keys unchanged from SHELL-002.

## Non-goals
- Agent dock motion (M3; no dock in M1.6).
- Panel docking, undocking or drag-to-rearrange.

## Acceptance criteria
1. Ctrl+B and Ctrl+J animate as specified in Standard, fade in Reduced, and are instant in Off.
2. Rapid toggling never leaves a region half-visible or a stale `data-phase`.
3. One React commit per splitter drag (dev profiler hook count).
4. No frame over 25 ms and p95 ≤ 17.5 ms during toggles and drags (bench `panel-toggle`, `splitter-drag`).
5. Existing geometry and smoke e2e suites pass; `scripts/check.sh` green.

## Failure conditions
- Any frame > 25 ms during the scenarios on the reference machine.
- Monaco re-lays out more than once per toggle (count `onDidLayoutChange`).
- Layout properties animated.
