# M2-ENV-001: crates/env: provider registry, validation and detection

## Objective
`crates/env` loads and validates provider manifests from the three locations, detects which providers apply to a workspace and which tools are present (PATH and managed roots, version via regex), and `axiomd` serves `env/providers` and `env/detect`. The provider contract suite (items 1–5 of `providers.md` §Contract tests) runs over `providers/*`. This task freezes the provider contract.

## Context
Epics 2.1 and 2.2. `providers.md` (all); ADR-0014 §3–§5; `docs/research/toolchains.md` §rustup.

## Required interfaces
- `ProviderManifest` and friends (`crates/protocol/src/provider.rs`), frozen by M2-ARCH-001.
- `axiom-store` for the per-workspace trust flag.
- Handler rule: thin handlers in `axiomd` (`modules.md`).

## Implementation requirements
1. `Registry::load(builtin_dir, user_dir, workspace_dir: Option<&Path>, trusted: bool)`: later sources override earlier ones by `id`; invalid manifests are reported (path, error) and skipped; workspace providers are listed untrusted and not loaded until trusted.
2. Validation beyond serde: id format, `version_regex` compiles with exactly one capture group, templates use only `${version}`, `${root}`, `${workspace}`, every archive artifact has a checksum source.
3. Project detection: `project.any_file` globs against the workspace root (and its first-level directories); returns the applying providers.
4. Tool detection: look up `program` on PATH and in each managed root (`<data dir>/toolchains/<provider>/<version>/<bin_dirs>`), run `version_args` with a 5 s timeout through `exec`-equivalent spawning (no shell), extract the version; report found (version, location) or missing.
5. `axiomd`: `env/providers`, `env/detect` handlers.
6. `crates/env/tests/provider_contract.rs`: items 1–5 for every manifest under `providers/`.

## Constraints
- ADR-0014 (accepted) is the decision record; do not reopen its decisions in this task.
- Frozen contracts (IPC 0.1 meanings, editor bridge 1) unchanged; additive protocol changes only where this spec says so.
- `scripts/check.sh` green; no test deleted, weakened or skipped.
- No network access in this task. No install code.
- Detection never modifies anything; it only runs the declared version commands.

## Acceptance criteria
1. `env/detect` on a Cargo workspace reports `rust` with `cargo`/`rustc` found (on a machine with Rust) or missing (with PATH emptied in a test).
2. An invalid manifest is reported with its error and does not stop others loading.
3. A workspace provider is listed untrusted and not applied until trusted.
4. Contract suite passes on Linux, macOS and Windows CI.

## Tests
- `cargo test -p axiom-env` (cases: `override_order`, `invalid_manifest_reported`, `regex_one_group`, `template_vars`, `detect_found_and_missing`, `untrusted_workspace_provider`).
- daemon integration test for `env/detect`.
- `scripts/check.sh`.

## Failure conditions
- Detection needs a shell or modifies the environment.
- A manifest can cause execution of anything other than its declared version command.

## Documentation updates
`docs/protocols/providers.md` (state: **frozen**), `docs/architecture/modules.md` (env status), `docs/roadmap/current.md`.

## Handoff
Detection timings on the CI hosts; any manifest field found unnecessary or missing.
