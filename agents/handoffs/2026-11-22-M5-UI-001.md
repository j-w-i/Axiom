### The Inspector
- A rail destination (the "inspect" icon) whose page fills the side bar. The editor stays in the
  main area, so a source jump opens beside it.
- `lib/state/inspector.dart` (`InspectorStore`):
  - tracks the folder's preview through `preview/list`, `preview/start`, `preview/stop` and
    `preview/state`;
  - drives inspect mode (`ui/inspectMode`);
  - keeps the person's selection (`ui/selected`), its details (`ui/nodeDetails`) and the hovered
    node;
  - selecting an ancestor highlights it (`ui/highlight`);
  - keeps the latest `ui.verify` report an agent ran: it follows `agent/event` and matches each
    `ui.verify` tool call with its result's output.
  - Wording helpers, unit-tested:
    - `isExact` (a build stamp at full confidence, not generated);
    - `candidateLabel` (for example "Uncertain: rendered by src/App.jsx:7:5 (50% confident)");
    - `nodeLabel`, `verdictLabel`.
- `lib/inspector/inspector_page.dart` (`InspectorSide`), in sections:
  - **Preview:** Start preview; Waiting for the page / Page connected; the URL; Open in browser
    (the system browser, `openExternal`); Stop preview.
  - **Inspect mode:** a toggle, enabled once a page is connected, and the element under the
    pointer.
  - **Selected element:** the element and its box.
  - **Ask AI about this element:**
    - attaches the element's best source (from its line, 20 lines) to the next chat message;
    - seeds the dock's composer with the element, its stable key and its location;
    - opens the dock (`AppState.showDock`, set by the shell).
  - **Source:**
    - an exact location is "Open src/App.jsx:11:9" and opens at its line and column;
    - a guess is "Open …, uncertain", with the candidate in words as its hint.
  - **Hierarchy:** the ancestors; selecting one highlights it in the page.
  - **Properties:** the `css.*` values from the page.
  - **Last verification:** the verdict, and a dot and summary for each check.
- **Chat:**
  - `AgentStore` has `context`: attachments for the next message, each with a label. They are
    sent as `SendParams.attachments` and cleared once sent or when the folder changes.
  - It also has `composerSeed`, which the dock takes once.
  - The composer shows each attachment as a removable chip ("Attached: …").

### A daemon fix found here (`axiom-inspect`)
- **Bug:** `ui/nodeDetails` normalised a node without its owner. An element with no stamp of
  its own (the library's `em`) therefore got a heuristic text match (`15:38`) instead of its
  owner (`7:5`).
- **Fix:** details now walk up the parents (at most 32 `inspect/nodeDetails` requests) to the
  nearest stamped ancestor, as hit-test chains do.
- **Test:** a new case in `crates/inspect/tests/adapter.rs`; the fake adapter now answers
  `nodeDetails` by node id.
- `inspection.md` records the rule.

### The end-to-end suite
- The test plays the person's browser: headless Chrome with a throw-away profile, and clicks
  sent over Chrome's debugging port (`Input.dispatchMouseEvent`).
- The product itself uses no CDP (ADR-0019 §1). The suite never presses "Open in browser",
  which would reach the developer's real browser.
- CI: the Flutter job installs the fixture with pnpm, and sets `AXIOM_REQUIRE_PREVIEW=1` on
  Ubuntu, where the suite fails instead of skipping.
