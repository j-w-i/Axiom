# M3-UI-001: Chat surface and the shared conversation components

## Objective
ADR-0017. Two parts:
- **Design.** `workspace-spec.md` §5.4 "Chat" written first: layout, states, keyboard,
  accessibility, reading measure, in the M1.6 material grammar and tokens.
- **Build.**
  - A full-window **Chat** destination (rail entry and Welcome action) that works with no
    folder open: the conversation list in the side bar (search, rename, delete), the
    conversation, the composer.
  - The components are shared with the dock (UI-002): message views with Markdown
    (react-markdown + remark-gfm, no raw HTML, links to the system browser through the host)
    and code blocks (Monaco `colorize`, Copy, Insert into editor when a workspace is open).
  - Streaming at frame rate with follow/"Jump to latest"; Stop; Edit (user message, via
    `fromTurn`); Regenerate; Copy.
  - Image attachments by paste, drop or picker (with a capability note).
  - A model/agent picker (API models, ACP agents).
  - Tool rows (state, name, target, meta).

## Context
ADR-0017, ADR-0015 §10, ADR-0016; `workspace-spec.md` §5.2; `design-system.md`;
`motion-system.md`; `frontend-architecture.md`.

## Implementation requirements
1. **`state/agent.ts`:**
   - sessions by workspace or none;
   - events by seq (replay from `sessionOpen`, dedupe, rewind branches);
   - deltas coalesced per animation frame;
   - pending approvals.
2. **Chat is a workbench destination.** Layout persists (layout v2); it is reachable with no
   workspace, and Welcome offers "Start a chat".
3. **Keyboard:**
   - Enter sends, Shift+Enter is a newline, Esc stops a running turn;
   - ↑ in an empty composer edits the last message;
   - Mod+N is a new chat (in Chat);
   - every control is reachable by Tab, with visible focus.
4. **Accessibility:** the log is `role=log`; the turn end is announced politely; every control
   is named.
5. **No literal colours; no shimmer or typewriter effects.** Long conversations stay smooth:
   virtualise past 200 messages.

## Acceptance criteria
1. **vitest:** store (replay, dedupe, deltas, rewind, multiple sessions) and Markdown rendering
   (GFM table, code block, no HTML injection, links routed to the host).
2. **e2e smoke (scripted model, no folder open):**
   - open Chat;
   - send and see streamed Markdown with a code block, then Copy;
   - edit the first message and see the branch replaced;
   - regenerate;
   - attach an image (the scripted model checks it arrived);
   - rename and delete a conversation.
3. **a11y suite passes on Chat; shots captured dark/light (empty, conversation, streaming).**

## Tests
`pnpm exec vitest run`; e2e smoke/a11y/shots; `scripts/check.sh`.

## Failure conditions
Placeholder UI; HTML from a model rendered; the webview speaking the wire protocol directly.
