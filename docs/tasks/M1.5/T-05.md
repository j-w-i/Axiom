# T-05: Complete the test-parity port from the Qt suites

## Objective
Every test function of the Qt suites in `apps/desktop/tests` is mapped to a
Tauri test (bridge, store, or E2E) or waived with a reason. The mapping table is
complete (115 rows) and the untested branches named in feature-parity.md (E-6,
E-8) are covered.

## Context
Source: implementation-roadmap.md §1 (wave B), §2 (T-05). Gap rows: E-6
(conflict Reload/Cancel), E-8 (unsaved prompt Save/Cancel and window close) in
`docs/migration/qt-to-tauri/feature-parity.md` §Documents and editor and the
summary table. The Qt suites are the source inventory (`apps/desktop/tests/*`,
9 executables, 115 functions, per architecture.md §1.1). The Tauri store tests
live in `apps/desktop-tauri/tests/stores.test.ts`.

## Required interfaces
- `apps/desktop-tauri/tests/stores.test.ts` and `tests/support/node-transport.ts`
  (test transport against the real daemon).
- `apps/desktop-tauri/src/state/` stores (read only; this task adds no production
  behaviour — a failing ported test is a defect to report, see Failure conditions).
- `docs/migration/qt-to-tauri/feature-parity.md` evidence column (update
  evidence paths).
- Qt suites `apps/desktop/tests/*` (read only).

## Implementation requirements
1. Produce the mapping table in the task handoff and in
   `apps/desktop-tauri/tests/PARITY.md` (new file, test inventory): one row per
   Qt test function (115) with columns: Qt suite::function, Tauri test name or
   `waived`, reason for waiver.
2. Each mapped function becomes a Vitest test in `stores.test.ts` (or an E2E
   check in `apps/desktop-tauri/e2e/smoke.mjs` where the behaviour needs a real
   webview). Test names keep the Qt function name as a suffix.
3. Port the E-6 cases (`conflictReload…`, `conflictCancel…`) and E-8 cases
   (`closingADirtyDocumentPrompts…` for Save and Cancel choices; window-close
   path) from `tst_documents`.
4. Waivers are allowed only with a reason that is one of: the behaviour is the
   daemon's and is covered by `crates/desktop-bridge` tests; the behaviour is
   Qt-specific (e.g. QML focus). Each waiver names the replacement test if one
   exists.
5. Update `feature-parity.md` evidence paths: the bridge evidence moves from
   `apps/desktop-tauri/bridge/tests/bridge.rs` to `crates/desktop-bridge/tests/`
   (T-02 move), and E-6, E-8 rows change from 🟠 to ✅ only if their tests pass.
6. No test is `skip`, `it.todo`, `.only`-less `skipIf`, or `#[ignore]`.

## Constraints
- Test-only work. Production code under `apps/desktop-tauri/src/` is not changed
  here; T-06 owns UI gaps.
- The 43 editor Vitest tests in `editor/` keep running unchanged.
- Tests use real daemon processes and temp directories, never the user profile
  (`AXIOM_DATA_DIR`).
- Only `feature-parity.md` evidence cells are edited in that document; statuses
  change only for rows named in req. 5.

## Acceptance criteria
1. `PARITY.md` has 115 rows, each mapped or waived with reason (req. 1, 4).
2. Ported tests for E-6 (Reload, Cancel) and E-8 (Save, Cancel, window close)
   exist and pass (req. 3).
3. `grep -rn "skip\|todo\|ignore" apps/desktop-tauri/tests` finds no disabled
   test (req. 6).
4. The mapped tests pass 20 consecutive runs (roadmap T-05 acceptance).
5. E-6 and E-8 rows in `feature-parity.md` state their new status with evidence
   (req. 5).

## Tests
- `cd apps/desktop-tauri && pnpm test` — all tests pass.
- `for i in $(seq 20); do (cd apps/desktop-tauri && pnpm test) || break; done` — 20 runs.
- `apps/desktop-tauri/scripts/e2e.sh` — for any E2E check added (run under
  `headless.sh` on Linux).
- `scripts/check.sh` — green.

## Failure conditions
- A Qt test is waived without a reason, or a waiver reason is "not needed".
- A test is weakened to pass (e.g. assertion removed) — governance rule 7.
- A ported test fails: the task stops and reports the defect; it is not marked
  tested with the test removed. Production fixes belong to the task owning the
  scope (T-06 for UI, or a CR).
- Fewer than 20 consecutive green runs.
- Count of mapped plus waived rows is not 115.

## Documentation updates
- `docs/migration/qt-to-tauri/feature-parity.md` — evidence paths and E-6/E-8
  status (the document is listed in this task's scope).
- `docs/roadmap/current.md` (governance rule 10).

## Handoff
The mapping table counts (mapped / waived), the list of waivers with reasons,
the 20-run result, and the feature-parity rows whose status changed.
