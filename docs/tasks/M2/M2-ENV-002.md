# M2-ENV-002: Managed archive installation: download, verify, extract, publish, uninstall

## Objective
Archive installs work end to end into `<data dir>/toolchains/<provider>/<version>/`: version listing, an immutable `InstallPlan` with a `planId`, streamed downloads into a content-addressed cache with SHA-256 verification before extraction, safe extraction (no path traversal, no symlinks escaping the root), staging + verify + atomic rename, progress notifications, and uninstall that removes exactly that directory.

## Context
Epic 2.3. ADR-0014 §2–§3; `providers.md` §Core data; `security.md` §Managed installs.

## Required interfaces
- `InstallMethod::Archive`, `VersionSource`, `Artifact`, `Checksum` (provider.rs).
- M2-ARCH-001 types `InstallPlan`, `Step`, `InstallProgress`.

## Implementation requirements
1. `versions(provider)`: `Static`, `Json{url, pointer}`, `GithubReleases{repo, tag_prefix}` sources; cached 1 h.
2. `plan_install(provider, version, platform) -> InstallPlan`: resolves the artifact for the host, expands templates, lists every step; issues a `planId` valid 10 minutes; plans are immutable.
3. `install(planId)`: rejects unknown/expired/altered plans (`approval_denied`); downloads with `reqwest` (rustls) into `<data dir>/cache/<sha256>`; verifies SHA-256 (from the manifest or the checksum URL) **before** extraction (`checksum_mismatch` otherwise); extracts into a sibling temp dir with traversal and symlink checks; runs `Verify` (tool detection inside the staged root); atomic rename; emits `env/installProgress` (bytes, step) and a final result.
4. Cancellation (`$/cancel`) stops cleanly and removes the staging directory.
5. `uninstall(provider, version)`: removes only that version directory; refuses paths outside the toolchains root.
6. Test fixture: a local HTTP server serving a small tar.gz/zip with known digests (no internet in tests).

## Constraints
- ADR-0014 (accepted) is the decision record; do not reopen its decisions in this task.
- Frozen contracts (IPC 0.1 meanings, editor bridge 1) unchanged; additive protocol changes only where this spec says so.
- `scripts/check.sh` green; no test deleted, weakened or skipped.
- Network only to URLs from a validated manifest. No redirects to other schemes; HTTPS only (test server excepted by a test-only flag).
- Nothing outside `<data dir>/toolchains` and `<data dir>/cache` is written.

## Acceptance criteria
1. An install from the fixture server publishes the root atomically and verifies the tool.
2. A wrong digest fails with `checksum_mismatch` and leaves nothing behind.
3. An archive containing `../x` or an escaping symlink is rejected.
4. Uninstall leaves the version directory absent and nothing else changed (directory snapshot before/after).
5. A plan cannot be executed after expiry or with any field changed.

## Tests
- `cargo test -p axiom-env` (cases: `install_publishes_atomically`, `checksum_mismatch_cleans_up`, `traversal_rejected`, `symlink_escape_rejected`, `uninstall_removes_only_root`, `plan_immutable_and_expiring`, `cancel_removes_staging`).
- `scripts/check.sh`.

## Failure conditions
- Anything is extracted or executed before its checksum is verified.
- An uninstall can remove a path outside the version directory.

## Documentation updates
`docs/architecture/security.md` (managed installs, as built), `docs/protocols/providers.md` (as built notes), `docs/roadmap/current.md`.

## Handoff
Download cache layout, plan lifetime, and the security checks with their tests.
