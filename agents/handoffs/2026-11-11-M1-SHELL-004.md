## Behaviour implemented
- `TaskController` (`tasks`): `running`, `currentLabel`, `lastStatus` (`{outcome, exitCode, durationMs}`), `statusText`, `history`, `canRun`; `run(commandLine)` sends `task/start { command: { shell } }` with the line verbatim; one task at a time (`run` is refused while running or without a workspace); `stop()` → `task/cancel` (a stop pressed before the id is known is applied when it arrives); `clear()`; `rerunLast()`. History: most recent first, de-duplicated, max 20, saved in workspace state `run.history`, loaded when a workspace opens and merged with anything run before it arrived. Closing the workspace or losing the daemon drops task state (the daemon cancels the process).
- `TaskOutputModel`: chunks applied in `seq` order (early ones wait, duplicates ignored), per-stream partial trailing lines, `\r` progress lines keep the last segment, CSI/OSC/two-byte escapes and stray control characters stripped, cap 10 000 lines with a first row "… earlier output truncated (N lines)", status row (`✔ Succeeded in 1.2 s`, `✖ Failed with exit code 3 in 0.4 s`, `■ Cancelled`), `error` row for `spawn_failed` and other start errors. Rows are published in batches of ≤ 500 on a 16 ms timer; rows beyond the cap are dropped before reaching views.
- QML: `OutputPanel` (editable `AxComboBox` with history, Enter or Ctrl+Enter runs, **Run**, **Stop** enabled only while running, **Clear**; `ListView` in the mono font, stderr rows in `danger` with a `!` gutter marker (never colour alone), failed status rows bold danger with text, auto-scroll unless the user scrolled up, click/drag row selection, Ctrl+C copies the selection, Ctrl+A selects all, right-click Copy / Copy all), new `AxComboBox`; Run menu (Run Command Ctrl+Shift+R focuses the field, Rerun Last F5, Stop Shift+F5); status bar shows `Running: <cmd>` then `<cmd>: succeeded | failed (n) | cancelled`.
- Real bug fixed along the way (WorkspaceController): `close()` followed immediately by `openFolder()` of the same root sent `workspace/open` before `workspace/close`; the daemon returned the closing id and then closed it. Opens now wait for a pending close (`m_pendingClose`/`m_deferredOpen`).

- An escape sequence split across two chunks is not reassembled (a chunk ending mid-sequence would leave its tail visible); the daemon's chunk boundaries are arbitrary, so this can happen in rare cases.

## Deviations and decisions
- The panel placeholder text appears in the empty list ("Run a command to see its output here"); the previous static "Output" body was replaced.
- `Clear` while a task runs empties the output but keeps the run state.
- Selection is by whole rows (like a log), not by characters; text selection of partial lines is not supported.
- `run()` trims only for the empty check and for the history label; the line sent to the daemon is the untrimmed original.
- `signals` is a Qt macro, so the test counter is called `insertBatches`.

## Known defects / limitations
- Output from before a cap overflow cannot be recovered; "Copy all" copies what the model still holds.
- Very long single lines wrap anywhere (`WrapAnywhere`); no horizontal scrolling.
