# M1.6-SYSTEM-004: Overlay primitives: menu, context menu, tooltip, dialog, sheet, toast, banner

## Objective
`src/ui/overlays.tsx` provides the restyled Menu, ContextMenu, Tooltip, Dialog,
Sheet, Toast (with a toast queue) and Banner in the overlay material (flat
surface lifted by the single popover shadow, no blur). Every existing dialog and
menu in the shell renders through them, and icon buttons expose their names on
keyboard focus.

## Context
`docs/design/design-system.md` §4 (overlay recipe), §9 (Menu, ContextMenu,
Tooltip, Dialog, Sheet, Toast, Banner rows); `motion-system.md` §4 (menu,
dialog, tooltip and toast choreography; presence comes in INTERACTION-001, so this
task ships static open/close and leaves `data-phase` hooks); D8 (Tooltip
library). Existing: `Dialog`, `Sheet`, `Menu`, `Banner` in `src/ui/primitives.tsx`
(Radix Dialog and DropdownMenu) and the hand-rolled output context menu in
`src/components/OutputPanel.tsx`.

## Required interfaces
- Radix `@radix-ui/react-dialog` 1.3.1 and `@radix-ui/react-dropdown-menu` 2.2.1 (existing).
- If D8 is approved: `@radix-ui/react-tooltip` (MIT, exact version pinned, the
  same release line as the existing Radix packages). If D8 is rejected: Tooltip is
  a thin wrapper that sets `title` and `aria-describedby`-free names; skip
  requirement 3's library parts.
- `ConflictDialog`, `UnsavedDialog`, `SettingsSheet` and `AboutSheet`
  (`src/components/Dialogs.tsx`) and the e2e checks that drive them (parity suite:
  `data-testid`, `data-action` attributes must be preserved).

## Implementation requirements
1. Move `Dialog`, `Sheet`, `Menu` and `Banner` to `src/ui/overlays.tsx` (re-export
   from `primitives.tsx` for compatibility until QA-006) and restyle them: overlay
   bg `--surface-overlay`, 1 px `--line` border, radius `--r-3` (6),
   `--overlay-shadow` plus `inset 0 1px 0 --edge-strong`; scrim `--scrim`, **no
   `backdrop-filter`**. Dialog width `min(460px, 100vw − 32px)`, padding 20,
   title 15/600, body 13 muted; buttons right-aligned, primary last, the safe default
   focused (existing `autoFocus` rule).
2. Menu: 4 px padding, items 26 px, 13 px, keycaps (`Keys`) right-aligned,
   heading 11 faint, separator `--line` + 1 px `--edge`, highlighted item =
   `--selected`; disabled = faint, no hover.
3. Tooltip: 500 ms delay, 0 ms when moving between tooltips within 300 ms
   (Radix `TooltipProvider delayDuration=500 skipDelayDuration=300`); content
   `--surface-overlay`, 12 px, max width 280, shows the label and, when the
   control has a shortcut, `Keys`; also opens on keyboard focus. `IconButton` now
   wraps its button in a Tooltip and stops setting `title`.
4. ContextMenu: if D8 is approved and a second context menu exists in M1.6
   scope, use `@radix-ui/react-context-menu`; otherwise a `ContextMenu` component
   built on the existing approach (pointer position, Escape, outside click,
   `role="menu"`, arrow keys, Enter) styled exactly like Menu. Port the output
   panel's "Copy selection / Copy all" menu to it without behaviour change (T-9
   parity checks must still pass).
5. Toast: `useToasts()` store in `ui/` (no app-store import); `toast({ tone:
   "ok"|"err", text, action? })`; a stack bottom-right, 16 px from the edges, above
   the status bar; height 34; `role="status"` (ok) or `role="alert"` (err); never
   takes focus; auto-dismiss after 4 s, paused on hover or focus-within; max 3
   visible. Used in M1.6 for: "task finished while the console is hidden" and
   "save failed" (wired by SHELL-006 and the documents banner owner, not here).
6. Banner: danger/warning/info with an action button (`Button size="sm"`); 32 px
   min height; tint `--danger-soft`/`--warning-soft`/`--accent-soft` + 2 px left
   rule in the tone colour + text `--text`; roles unchanged.
7. Gallery sections for each overlay, opened statically (`open` forced) in both
   themes.
8. Leave hook points for INTERACTION-001: each overlay root carries
   `data-phase` controlled by a `phase` prop defaulting to `"in"`.

## Constraints
- Dependency additions only as listed; record licence and size in the handoff
  (governance rule 1).
- Behaviour of existing dialogs (actions, dismiss action, focus trap, Escape) is
  unchanged: the parity and smoke suites prove it.
- No glass, blur or multiple shadow levels.

## Non-goals
- Entrance/exit motion (INTERACTION-001/003); the settings redesign (SURFACES-002);
  the command palette (SURFACES-001).

## Acceptance criteria
1. All overlays render from `ui/overlays.tsx` in the new material; the gallery shows
   each in both themes.
2. Keyboard: Tab to any IconButton shows its tooltip with name and shortcut; Escape
   closes menus, dialogs and the context menu; focus returns to the trigger.
3. The output context menu behaves as before (T-9 checks green).
4. Toasts announce through `role="status"`/`alert` and never move focus (Vitest + e2e).
5. All e2e suites and Vitest pass; `scripts/check.sh` green.

## Failure conditions
- An existing dialog loses its default focus or dismiss action.
- A tooltip is the only way to learn a control's name (it must also be the
  `aria-label`).
