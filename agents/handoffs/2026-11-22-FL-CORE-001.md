## Result
Task status: **implemented** (Linux, against the real daemon; CI pending).

- **`lib/daemon/client.dart`**: `DaemonClient` with the bridge's behaviour.
  - `locateDaemon` order: explicit, `$AXIOMD`, sibling, `PATH`.
  - Spawn with `--data-dir`; `initialize` within 10 s (protocol 0.4, `approvals`).
  - Every request is answered once: a result, the daemon's error as `DaemonException(kind)`,
    `timeout` (then `$/cancel`), or "Backend stopped".
  - `CancelToken` sends `$/cancel`.
  - Typed notifications (`on`) and raw ones (`onRaw`).
  - A crash gives `failed` with the stderr tail; `restart`; a bounded `shutdown`.
  - A malformed handshake answer gives `failed` rather than an exception.
- **Wire order.** Lines are handled in order. After a response the event loop turns once, so
  code awaiting it runs before a later notification is dispatched: the guarantee the bridge's
  single event channel gives.
- **`tool/gen_types.dart`** writes `lib/daemon/protocol.g.dart` from `schemas/`:
  - 170 definitions: classes, enums, sealed unions tagged by `type`/`kind` or by key;
  - `Methods.*` and `Notifications.*` descriptors;
  - `--check` for freshness, in check.sh.
- **The gate.** `check.sh flutter` builds axiomd, checks the types are fresh, formats `tool/`
  too. CI's Flutter job gets a Rust toolchain.
