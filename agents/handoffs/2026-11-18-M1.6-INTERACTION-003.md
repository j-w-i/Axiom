## Found, not fixed (outside this task's scope): task output can be dropped
- **Symptom:** `tests/stores.test.ts` "clear empties the output, rerunLast …" times out about 1 run in 3 under heavy parallel load. This is the likely source of the rare unexplained gate failures.
- **Cause, in `src/state/tasks.ts` + `src/daemon/client.ts`:**
  - IPC 0.1 guarantees the `task/start` response is sent before that task's notifications.
  - But the client resolves the response's promise, whose continuation is a microtask, and dispatches notifications synchronously.
  - When the response and the first `task/output` / `task/exited` arrive in one batch, the handlers run while `taskId` is still empty and drop them.
  - For a fast command the store then never sees its output or exit and stays "running".
- **Exposure:** the Node test transport delivers lines in batches. Whether Tauri's event delivery ever batches them is unverified.
- **Fix (small, a task of its own):** buffer notifications for an unknown task id while a start is pending, and replay them once `task/start` answers.
