# T-09: CI: build and test the Tauri shell on three OSes

## Objective
A `tauri` job in `.github/workflows/ci.yml` runs on ubuntu, macos and windows:
bridge tests, Vitest, and E2E (tauri-driver on Linux and Windows; WebdriverIO
embedded driver on macOS). `scripts/check.sh` runs the Tauri gates. Screenshots
are uploaded as artifacts.

## Change record (2026-11-12): end-to-end driver per OS

Requirement 2 named tauri-driver on Windows. CI showed it cannot work with the
pinned stack (KD-WIN-2, `docs/roadmap/verification/M1.5.md` §5c): msedgedriver
needs a DevTools endpoint the WebView2 host never opens, because wry 0.57's
Windows `set_allows_automation` is a no-op. Tauri's documentation recommends
WebdriverIO's embedded server for exactly this, and for macOS. Replacement,
approved by the project owner (2026-11-12):

| OS | Driver | Proves |
|----|--------|--------|
| ubuntu | tauri-driver → WebKitWebDriver **and** embedded | trusted key events; the embedded path compared against it |
| windows | embedded (`tauri-plugin-wdio-webdriver`) | everything except "keys are OS-level" (reported N/A) |
| macos | embedded | same; plus the crash kill is N/A (WebContent is not a descendant) |

The embedded server is test-only: `e2e` Cargo feature, 127.0.0.1, guarded by
`src-tauri/tests/release_guard.rs` and `scripts/bundle.sh`
(`docs/architecture/security.md` §Test-only code). Scope grows accordingly:
`apps/desktop-tauri/e2e/`, `apps/desktop-tauri/scripts/{e2e,bundle}.sh`, the
host's `Cargo.toml`/`lib.rs` (feature + macOS crash hook) and its tests.

## Context
Source: implementation-roadmap.md §1 (wave C), §2 (T-09), exit criterion 4 of M1.5.
Existing CI: `.github/workflows/ci.yml` jobs `rust`, `deny`, `editor`, `desktop`
(Qt, retained until T-15). Gate: `scripts/check.sh` and `docs/architecture/testing.md`.
Known defect precedent: KD-WIN-1 (`agents/handoffs`, `docs/roadmap/verification/M1.md`).
Headless Linux runs: `apps/desktop-tauri/scripts/headless.sh` (AGENTS.md).

## Required interfaces
- `.github/workflows/ci.yml` (existing jobs must keep their names and steps).
- `scripts/check.sh` — the `tauri` branch (`scripts/check.sh tauri` plus the
  `all` default); the Qt `desktop` branch is unchanged.
- `apps/desktop-tauri/scripts/e2e.sh`, `headless.sh`, `sysroot.sh`, `env.sh`.

## Implementation requirements
1. Add a `tauri` job to `ci.yml` with a matrix `[ubuntu-latest, macos-latest,
   windows-latest]`. Each cell runs: bridge tests (`cargo test -p axiom-desktop-bridge`),
   host tests (`cargo test -p axiom-desktop-tauri`), `pnpm install --frozen-lockfile`
   in `apps/desktop-tauri`, `pnpm run check`, `pnpm test`, and the E2E step.
2. E2E driver: tauri-driver on ubuntu and windows; WebdriverIO embedded driver on
   macOS. The driver choice is recorded in the job's step names.
3. `scripts/check.sh` gains a `tauri` section that runs the same commands locally
   (Linux) and is included in the `all` default when `apps/desktop-tauri/package.json`
   exists.
4. Job timeout: `timeout-minutes: 45` or less.
5. Upload screenshots from E2E runs as workflow artifacts (`actions/upload-artifact`).
6. Linux steps install the WebKitGTK 4.1 / GTK 3 development packages (or call
   `apps/desktop-tauri/scripts/sysroot.sh`); Windows and macOS steps install
   WebView2 and Xcode CLT as needed by the runner.
7. The existing `rust`, `deny`, `editor`, `desktop` jobs are not removed or
   weakened; `desktop` (Qt) is retained until T-15.
8. A red cell must be either fixed or recorded as a known defect with an owner
   (roadmap T-09 acceptance; the KD-WIN-1 precedent).

## Constraints
- Only `.github/workflows/ci.yml` and `scripts/check.sh` change (scope).
- No new third-party GitHub Action without a pinned version (commit SHA or tag).
- The E2E scripts refuse to run without the headless wrapper on Linux; CI uses
  the same wrapper, not a visible display.
- Governance: CI is the verifier for macOS and Windows behaviour (governance
  "Task states" section).

## Acceptance criteria
1. The `tauri` job exists with the three-OS matrix (req. 1).
2. All three cells green, or each red cell is recorded as a known defect with an
   owner in the job summary and in `docs/roadmap/current.md` (req. 8; roadmap
   T-09 acceptance).
3. Job duration ≤ 45 min per cell (req. 4).
4. Screenshot artifacts are present for the E2E run on each OS (req. 5).
5. `scripts/check.sh` runs the Tauri section locally on Linux and passes (req. 3).
6. Existing jobs `rust`, `deny`, `editor`, `desktop` still run (req. 7).

## Tests
- `scripts/check.sh` — passes locally on Linux, including the `tauri` section.
- Push a branch and run CI: `gh run view <id> --json jobs` (read-only) shows the
  matrix status per OS.
- `apps/desktop-tauri/scripts/e2e.sh` — on Linux locally under `headless.sh`.

## Failure conditions
- A cell is green while its E2E step was skipped.
- Any OS is not exercised and the task is still reported as Tested: report
  "unverified on <OS>".
- The job timeout exceeds 45 minutes.
- Existing jobs are removed or made optional to get green.
- A GitHub Action is referenced without a pinned version.

- `docs/roadmap/current.md` (governance rule 10).

The CI run URL, per-OS result table (green / red with defect owner), job
