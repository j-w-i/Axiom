# 0022 A person's own terminal, in the host
**Decision.** A person can open terminals in a session's folder (W-48), and a folder's commands run in one (W-37). A terminal is the person's, not an agent's: their login shell, outside the sandbox, as their own act (`PersonsOwn::Terminal`, on the one spawn path, SI-7), exactly what the system's own terminal would give them. No agent can open, read, write or close one, and nothing an agent says is typed into one (SI-2).
**In the host.** The shell runs on a pseudo-terminal that `axiom-spawn` makes (the only crate with `unsafe`), in a session of its own, so that it and all it starts end with the terminal (SI-24). The host reads it and keeps the screen with a terminal emulator of its own (`vt100`, MIT): the client is sent rows of text with their colours, never the bytes a program wrote, so no escape sequence reaches a renderer (T42). What the emulator does not know is dropped: no clipboard (OSC 52), no links (OSC 8), no answers to queries beyond what it answers itself, no pictures. A title a program sets is shown as text only.
**It outlives the window**, not the host: it is kept while the host runs, and a window that comes back finds it. It ends when its person closes it, asked first while something runs in it, and when the host stops.
**Where it is.** In the panel, as a file or a search is: one place, no second canvas, no key in the bar (the owner, 2026-11-25). Several, one at a time; not split (the owner: no split canvases).
**What a person may take from it.** Selected text goes into the draft as output, labelled as from the terminal (W-47, SI-17). A path in it opens the file (W-19).
**Commands of a folder** are written by the person and kept by Axiom (`folders.json`); they are never read from the repository, so no approval by text is needed (SI-5). Each runs in a new terminal of its folder, typed into its shell as the person would.
**Not on Windows** yet: a pseudo-terminal there is ConPTY, which `axiom-spawn` does not make. It says so.
**Alternatives.** A terminal emulator in the client (xterm.dart): Material, and the bytes of any program in the renderer. Running the shell in the sandbox: no network, no keychain, no `ssh-agent`; signing in to a program, the reason item 48 gives, would not work.
**Risk.** Whatever the person types runs as they do. That is a terminal.
