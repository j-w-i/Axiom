## Deviations and decisions
- **Recipes as tokens:** the controls' shadows and gradients contain literal colours, which the guard allows only in `tokens.css`, so `--raised-bg-hover`, `--pressed-shadow`, `--engaged-shadow`, `--primary-*`, `--keycap-shadow`, `--track-shadow`, `--thumb-bg/-shadow`, `--glide-shadow`, `--meter-shadow`, `--led-off/-off-shadow/-ring` were added to the hand-written materials blocks (both themes). The thumb gradient and LED-off colours are literal per theme (from the prototype), not generated.
- `tests/tokens.test.ts` guard (c): a custom property set inline by a component (`"--seg-n": …`) now counts as defined; everything else still has to be in `tokens.css`.
- Outside the declared scope: `tokens.css` (above), `vite.config.ts` (gallery mode, `.tsx` tests), `tsconfig.json` (gallery type-checked), `package.json` (`gallery`, `build:gallery`), `.gitignore` (`dist-gallery/`), `e2e/shots.mjs` (S17), `README.md`.
- `Count` is built (the task lists it) though no M1 surface uses it yet; the "mock" badge is not built.
- Keyboard handling is exported as pure functions (`segmentedTarget`, `stepperTarget`, `isToggleKey`, `keyLabels`) and the components are hook-free, so the tests drive the real handlers without a DOM.
- `Switch` handles Space/Enter itself and cancels the button's native activation (keydown/keyup) so a key press toggles once.
- `data-force="hover|pressed|focus"` selectors exist in the component CSS for the gallery's forced states; inert in the app.
