# 0016 A person's own programs: which, where, with what
**Decision.** A person can add any program that speaks ACP, by name, path and arguments (W-8), and say of any program, also of one account of it, where it is, with what further arguments and variables it is started (W-9). It is kept in Axiom's own folder, and said by a client with the token; never by a workspace (SI-5) and never by an agent. Nothing of it starts anything: each start is asked about as before (0006), and the question shows the whole command as a shell would have it, variables first, a secret one by its name.
**One of the person's own.** It is spoken to as ACP. Of its modes nothing is known, so "ask first" is all there is; nothing holds it back, which is said (SI-26). It may not be called what another is called (PR-12).
**Where it is.** A whole path, through the same checks as what is found by name: a real file that can be run, not in anything an agent may write to, not changeable by anyone. Its folder is looked in first for other programs, because what nvm and the like install starts an interpreter that lies beside it; so that folder must not be in what agents write to or open to anyone either. This settles K45.
**Arguments.** Of a program whose boundary Axiom relies on or shows (Claude Code, Codex) only those are passed on that cannot move it: a list, from its documentation. The rest are refused in words, because a flag that comes later may win over Axiom's. Of ACP programs any, but for words that let go (T34). None that is named like a secret: arguments are seen by every user of the computer.
**Variables.** A value is either shown, or a secret: then it goes to the system's store, is never shown again, and reaches the environment of that one program, which SI-3 allows. One whose name says so is a secret whether or not its person said it. It is on record by its name. What the program says back is searched for it before it is journalled, and it is taken out; a value that comes in pieces is not found. Claude Code is told, as it documents, to keep such variables from the commands it runs.
**Refused as variables**, for every program: what makes a loader, an interpreter, git or ssh run or trust something (`LD_*`, `NODE_OPTIONS`, `PYTHON*`, `GIT_*`, …); what Axiom sets itself; another address, proxy, header or certificate (a credential would go where its owner did not send it, and a plan's program could be put before another's service: 0007); a plan's login (`*OAUTH*`, `ANTHROPIC_AUTH_TOKEN`, …); who it says it is (`*ENTRYPOINT*`, `*USER_AGENT*`, …); what names a program (`*_HELPER`, `*_SHELL`, …); what holds it back (`*SANDBOX*`, `*PERMISSION*`, …). By what the name contains, so more than is needed. Left are those its documentation describes for a person's own account elsewhere: Bedrock and Vertex for Claude Code (`CLAUDE_CODE_USE_BEDROCK`, `AWS_*`; `CLAUDE_CODE_USE_VERTEX`, `GOOGLE_APPLICATION_CREDENTIALS`, …), limits, switches. A value that is a path into what agents write to is refused at the start.
**Alternatives.** A list of allowed variables: safer and useless for programs nobody here knows. Handing the host's own environment on: what is in it nobody chose (SI-11).
**Risk.** A variable nobody here knows may change where a program sends what. Its person said it, and it is shown at each start.
**Revisit.** When a program documents how it is told of an account.
