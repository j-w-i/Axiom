## Verification (Linux only — stated, not implied)

- `scripts/check.sh` (rust + editor + tauri + desktop): see the pasted result in
  the final message. Rust workspace: **253 tests pass**. Editor: 43. Tauri UI:
  31 + 3 token guards + 5 host-surface. Qt shell: 9 executables, 107 functions.
- End-to-end: **21/21**, three consecutive runs, on a private Xvfb.
- Benchmarks (Qt vs Tauri, same machine, interleaved): startup 866 → 421 ms,
  idle memory 446 → 282 MiB, typing p95 22.8 → 18.8 ms, package 337 MB → 8.5 MiB.
  See `performance.md`.

## Defects found while doing this (all fixed, each with a regression test)

1. **The macOS-gated menu code is not compiled on Linux by default** — it is
   now covered by `scripts/cross-check.sh` (both foreign targets pass
   `cargo check --all-targets`), which is why T-07 is `implemented` rather than
   untested-by-anyone; only *running* it is missing.
2. **Switching workspaces kept the old tabs** (real parity bug): the store only
   cleared documents on the `closed` event, not on the workspace id going away.
   Fixed in `DocumentsStore`; test `switching workspaces closes the documents of
   the old one`.
3. **A reloaded page never learned the daemon was ready** (test transport):
   subscribing again must replay the current state — the host already did.
4. **The heartbeat alone is unreliable**: WebKit throttles timers in a
   backgrounded page, so a strict lease would reload the app while the user is
   elsewhere. Fixed with the engine signal on Linux + visibility gating.
5. **The new E2E runner used the inherited `DISPLAY`** and opened a window on
   the developer's screen. Fixed: a private Xvfb is mandatory on Linux, an
   inherited `DISPLAY` is ignored unless `AXIOM_ALLOW_EXISTING_DISPLAY=1`.
6. **`comm` is truncated to 15 characters** (`WebKitWebProces`), so the crash
   test found no process. Fixed and made descendant-only (never touch another
   app's web process).

## CI (pushed, PR #1)

`rust` is green on Linux, macOS and Windows; `editor` green; the new `tauri`
job is green on Linux and macOS including the full end-to-end suite; the Qt
`desktop` job is green on Linux and macOS. Two Windows defects are recorded,
not silenced: **KD-WIN-2** (the end-to-end session cannot start: tauri-driver
reaches msedgedriver, the app never opens a DevTools port) and **KD-WIN-1**
(the Qt shell's Windows suite, carried over from M1). Four CI iterations were
needed and every one found something real - see `verification/M1.5.md` §5c.

## What is NOT done (honest list)

- **Windows verification**: build, tsc, Vitest and the host's Rust tests pass
  there in CI, but the end-to-end suite does not start (KD-WIN-2) and no
  Windows package has been built or run.
- **No real-GPU, IME, clipboard, DnD, HiDPI or screen-reader verification** on
  any OS.
- **T-11 (editor isolation) measurement** and **M5-PRE-001 (preview engine)**
  were not run. The latter is the main open technical risk of ADR-0012: M5's
  preview needs an engine with CDP, which Tauri does not provide on Linux or
  macOS.
- **Windows/macOS packages** were not built.
- **Nothing was committed**: the working tree holds the work (see below).
