# M1.6-QA-005: Cross-platform visual and interaction review (macOS, Windows)

## Objective
The redesigned shell is captured with the QA-001 harness and reviewed by a person
on **real macOS and Windows hosts** (or, for the automated parts, CI runners), with
results recorded per OS: WKWebView and WebView2 rendering, native title-bar
integration (D3), fonts, scaling, forced colours, screen readers and the motion
interactions.

**Blocker inherited from M1.5.** This environment has no macOS or Windows machine,
and the GitHub Actions budget was exhausted on 2026-11-12
(`docs/roadmap/current.md` §Blockers). This task **must not be marked tested**
without real macOS and Windows runs: a manual run on hardware, or a CI run with
its run id for the automated parts. Until then it stays `planned`/`blocked` with
"unverified on macOS / Windows" in the record.

## Context
`docs/design/visual-qa.md` (all); `frontend-architecture.md` §6 (platform
integration); `agents/MANUAL_VERIFICATION.md` (the per-OS manual protocol from
M1.5, items still open there: IME, screen readers, HiDPI, drag and drop);
`docs/roadmap/verification/M1.5.md` (the CI matrix and the Windows typing fix
`editContext: false`).

## Required interfaces
- `scripts/e2e.sh shots.mjs` with the embedded WebDriver provider (macOS and
  Windows), and `shots-compare.mjs`.
- The packages from T-13 (deb/rpm/.app/NSIS) for an installed-app review.

## Implementation requirements
1. On each of macOS (latest, Apple Silicon) and Windows 11, at 100% and 200%
   (Retina / 200% display scale): run `scripts/e2e.sh shots.mjs`; store the set in
   `e2e/shots/<os>/` and commit the 100% set to
   `docs/roadmap/verification/M1.6/<os>/`.
2. Compare each set with the Linux set: expected differences are font smoothing and
   native chrome only. Anything else (layout shift, clipped text, a missing border or
   wrong colour) is a defect on the owning task.
3. Review each set against `visual-qa.md` §5 with these platform items:
   - macOS: overlay title bar (D3), traffic lights vertically centred on the 38 px
     title row, drag region works, double-click on it zooms, full screen hides the
     inset; `-webkit-font-smoothing` applies.
   - Windows: native title bar themed to match (dark and light, following the
     setting); Snap Layouts on hover of maximise; ClearType rendering of Plex at
     13 px; **forced colours** (High Contrast "Night sky"): focus rings, borders and
     LEDs remain visible.
   - Both: keycaps show ⌘/⌥ (macOS) or Ctrl/Alt (Windows); menus and shortcuts work.
4. Manual interaction pass (`visual-qa.md` §6) at Standard, Reduced (OS setting)
   and Off: palette, side bar, console, tabs (glide, reorder if D7), menus,
   toasts, splitter drag.
5. Screen readers: VoiceOver (macOS) and NVDA (Windows) with the same script as
   QA-003's Orca pass; record what is announced.
6. Performance spot-check on each OS: `bench/run.sh --runs 3` for P1, P3, P8 where
   the bench supports the OS; otherwise record "not measured".
7. Record everything in `docs/roadmap/verification/M1.6.md` §Platforms with the
   host model, OS build, display scale, engine version and the CI run ids.

## Constraints
- Evidence comes from real hosts or CI runs; emulation or screenshots from
  another engine do not count.
- Fixes are made in the owning tasks, then re-checked here.

## Non-goals
- New features; Linux (covered by the other QA tasks).

## Acceptance criteria
1. Shot sets for macOS and Windows at 100% and 200% exist and are reviewed, with
   every deviation from Linux explained or fixed.
2. The platform items in requirement 3 are each ✅, or a defect is filed.
3. The screen-reader and motion passes are recorded per OS.
4. If either OS could not be run, the record says "unverified on <OS>", and the
   task is not marked tested.

## Tests
- `scripts/e2e.sh shots.mjs` and all suites, per OS (CI or local); the run ids
  are quoted.

## Visual verification

## Performance
P1, P3 and P8 per OS where the bench runs; otherwise "not measured on <OS>".

## Failure conditions
- Marking tested without real macOS and Windows evidence.
- Treating a Linux screenshot as evidence for another OS.

(the M1.6 additions: title-bar theme, forced colours, motion levels).
