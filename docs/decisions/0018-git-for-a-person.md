# 0018 Git for a person: commit, branch, push and pull, in the host
**Decision** (D-1 of `../product/worth-building.md`, as recommended there). A **person** may have Axiom commit what is in a folder, make a branch, fetch, pull and push. An agent may do none of it, as before: it never writes `.git` (SI-11) and never reaches a remote (0014). Reading (status, log, one commit, a comparison) needs no decision and is the same code.
**One wrapper.** Every git that Axiom runs goes through `host/src/git.rs`: the program of the system's `PATH` outside the home folder (SI-22), `--no-optional-locks --no-pager`, `core.fsmonitor=false`, `core.hooksPath=/dev/null`, `diff.external=`, no text conversion, no system configuration, a limit on what it says and on how long. Only the host calls it, and only for a call of a client with the token.
**Local acts run in the sandbox,** without a network, because no flag turns off every key a repository can set (filters, includes: T3). Reading: as today, nothing written but the scratch folder. A commit or a new branch: the repository's own git folder is writable and nothing else of the folder; inside it `hooks`, `config`, `info` and what submodules keep of the same stay protected (`Profile::git`, made by the host for a person's act and never from what an agent may). A fast-forward after a fetch: the folder too, but where it would change a protected name it is refused before it begins, because the sandbox would stop it half done.
**Hooks do not run.** Neither the repository's nor `core.hooksPath`'s. Where a repository has any (`.git/hooks` beyond the samples, `.husky`, `.pre-commit-config.yaml`, a hooks path in its configuration), the person is told so before they commit or push: what a hook would have checked is not checked. Running them in the sandbox was considered: a hook that formats or tests needs the network, the home folder or the folder itself, and would fail in ways that look like the change's fault.
**What goes in is what was shown.** The person chooses files from the list of changes; each goes with the digest of what they saw. The host reads each by handle (SI-9) and refuses one that is not that any more; then `git commit --only --no-verify -F - -- <paths>`, the message on standard input, never on a command line. Other files that were staged stay staged and are not committed. A commit to the default branch (the remote's `HEAD`, or `main`/`master` without one) is asked about once more. Who commits is the person's `user.name` and `user.email` from `~/.gitconfig` (read by the host, nothing else of that file is used); without them the form asks, for that commit only. A configuration that asks to sign commits is not followed (no key reaches the sandbox), and that is said beside the key.
**Push and fetch** need the person's credentials and the network, so they run outside the sandbox, as the person's own act, on the one spawn path with a token minted by their press (`Unsandboxed`, SI-7). So that no repository runs code there: its own configuration (the local and worktree scopes, and what they include) may hold only keys of a short list: remotes' `url`, `pushurl` and `fetch`, branches' `remote` and `merge`, `core.*` of the layout (`repositoryformatversion`, `filemode`, `bare`, `logallrefupdates`, `ignorecase`, `precomposeunicode`, `symlinks`, `autocrlf`, `eol`), `extensions.*`, `user.*`, `pull.*`, `push.default`, `init.*`, `gc.*`, `fetch.prune`, `lfs.*` (data only; LFS's hooks do not run). Any other key there refuses the push and names it; a terminal can still do it. `include` and `includeIf` refuse too. Only `https` and `ssh` are allowed as protocols. `GIT_TERMINAL_PROMPT=0`: git asks nobody, so a credential is whatever the person's own helper, agent or keychain gives git, and Axiom reads none of it (T17). The remote and its address are shown before. Push is never forced: only a fast-forward of the branch to the same name. Pull is a fetch and then `merge --ff-only`; what is not a fast-forward is refused in words. Submodules are not fetched.
**Ahead and behind** are counted against the upstream as git knows it since the last fetch, and say so.
**Several repositories in a folder** are each found once (at most two levels down, never into an ignored folder or a protected name) and each has its own branch, changes and commit.
**A suggested message** (W-43) comes from a model the person chose for short texts in Settings, off until they choose one; it is sent the diff of what is chosen and the last few subjects, and is said to go there (PR-2). It is always put into the box to change, never committed by itself.
**Audit.** Each commit, branch, fetch, pull and push is on record before it is done (SI-23), with the repository, the remote and the files.
**Alternatives.** A git library in the host (gitoxide): another large dependency, and filters and LFS would not be the person's own. Running push in the sandbox: credentials would have to be handed in, which is what T17 refuses. Letting agents commit in their copies (K48): a person brings in what they were shown; the person then commits it.
**Risk.** A credential helper or `ssh` of the person's own runs outside the sandbox when they push: it is theirs. A key of a repository's configuration that git adds later is refused by the list, not let through. Files that change while git reads them are committed as git read them; that is said when a digest after the commit differs.
**Revisit.** When git gains a way to read no repository configuration but its remotes, or when agents should commit (M5).
