# M1.6-SHELL-004: Explorer tree restyle

## Objective
The explorer adopts the recommended tree design: 22 px rows, 14 px indent with
1 px guides, rotating chevrons, neutral folder icons, file-type glyph chips, a
selection marker that turns brass when the tree has focus, a focus ring on the
keyboard-focused row, and an unsaved dot for documents dirty in the editor. The
keyboard model and virtualisation are unchanged.

## Context
- `docs/design/workspace-spec.md` §2.2; `design-system.md` §7 (glyph chips), §8
  (Selected, Focus-visible).
- Prototype: `experiments/e5-visual-concepts/src/shared.tsx` (`Tree`),
  `src/base.css` (`.row*`), `src/concepts/a.css` (`.ca .row*`, `.glyph*`).
- Current: `apps/desktop-tauri/src/components/Explorer.tsx` (virtualised
  `role="tree"`, `aria-activedescendant`).

## Required interfaces
- `WorkspaceStore` rows (unchanged); `DocumentsStore` snapshot `docs[].dirty` (read
  only) for the unsaved dot.
- `data-testid="explorer"` and the row attributes used by `e2e/smoke.mjs` and
  `e2e/parity.mjs`: keep them.

## Implementation requirements
1. Rows: height `--row-h` 22; left padding `var(--s-2) + depth × --indent (14)`;
   `--text-body` 13; ellipsis; `title` = full path.
2. Indent guides: one 1 px `--tree-guide` line per ancestor level at
   `x = 8 + level × 14 + 7` px, the full row height.
3. Chevron: 16 px box, 13 px glyph, `--text-faint`, rotated 90° when open with a
   `transform` transition of `--dur-1` `--ease-out`.
4. Icons: folders `Folder`/`FolderOpen` in `--icon-folder`; files as glyph chips
   (15×15, 3 px radius, mono 8.5 px/700): `rs` → `--glyph-rs-bg`/`--glyph-rs`; `md`
   → steel; `toml` and `lock` → verdigris; anything else neutral, two letters from the
   extension. The tokens come from SYSTEM-001 (`--glyph-*`); add them there via a
   change request if they are missing, and do not hard-code them.
5. States: hover `--hover`; selected `--selected` plus a 2 px left marker (inset
   3 px top/bottom) in `--text-faint`, which becomes `--accent` while the tree has
   `:focus-within`; the keyboard-focused row has `inset 0 0 0 1px --accent-line` when
   the tree is `:focus-visible`; ignored rows use `--text-faint`.
6. Trailing status: a 9 px `●` in `--text-muted` on rows whose document is open and
   dirty. Its accessible name is appended to the row label as ", unsaved".
7. The error row (`tree-row--error`) and the empty state keep their logic; their
   styling follows SHELL-007's error and empty specs.
8. Move all tree CSS from `app.css` to `styles/components/tree.css` and drop the
   legacy aliases there.

## Constraints
- Keep the row height fixed (virtualisation depends on it) and keep the full keyboard
  model (arrows, Home/End, PgUp/PgDn, Enter/Space, Left to parent).
- No new store fields; no problem counts (M2).

## Non-goals
- Colour tags on folders (Concept B, not recommended); git status (M4); drag and
  drop of files.

## Acceptance criteria
1. Rows are 22 px, and guides align to the chevron centres at depths 0–5 (200%
   screenshot).
2. Selection marker: faint when the tree is unfocused, brass when focused (S15).
3. Editing a file shows the unsaved dot on its row; saving removes it. The screen
   reader name includes "unsaved".
4. Explorer settle (5,000 entries) and wheel budgets stay within their existing
   values (P11).
