# M1.6-SYSTEM-001: Generated theme tokens, material and motion tokens, extended guard tests

## Objective
`tokens.css` carries the approved design system: generated primitive and semantic
colour tokens for dark (graphite) and light (aluminium), type, space, shape,
material and motion tokens. **Legacy aliases** keep every existing component
rendering correctly, and the guard test enforces the new contrast, coverage and
motion rules. A freshness check in `scripts/check.sh` fails when the generated
blocks are stale.

## Context
`docs/design/design-system.md` §2 (colour, semantic table §2.2, contrast §2.3),
§3 (generation), §4 (material recipes), §5–§6 (type, space); `motion-system.md` §2
(tokens); `frontend-architecture.md` §2–§3 (files, guard rules). The delivery
strategy is D9: restyle in place, with aliases until QA-006.

## Required interfaces
- `src/styles/tokens.css` (existing 3-layer structure; `:root,[data-theme="dark"]`
  and `[data-theme="light"]` blocks are parsed by `tests/tokens.test.ts`).
- `src/editor/surface.ts` reads `--bg`, `--bg-hover`, `--text-faint`,
  `--text-muted`, `--bg-elevated`, `--border-strong`, `--accent-line` and
  `--scrollbar` (must keep working through aliases).
- ADR-0013 (approved values and any owner changes).

## Implementation requirements
1. Add `src/styles/themes.json` with exactly the inputs in `design-system.md` §3
   (dark: base hue 70, chroma 0.006, accent hue 80/chroma 0.10/lightness 0.74;
   light: base hue 75, chroma 0.008, accent 78/0.11/0.60; tone warm; contrast 1.0).
2. Add `scripts/gen-themes.mjs` (Node, no dependencies): OKLCH → sRGB conversion,
   WCAG contrast, and a solver that places text tiers at their minimum contrast
   against the worst surface (§2.3). It writes the primitive (`graphite-*`,
   `brass-*`, `sage`, `ember`, `brick`, `steel`) and semantic blocks between
   `/* <generated:dark> */ … /* </generated:dark> */` (and `light`) markers as
   `#rrggbb` or `rgb(r g b / a)`. Modes: default (write) and `--check` (exit 1 if stale).
3. Calibrate the generator so every semantic token of `design-system.md` §2.2
   reproduces the listed hex within ΔE2000 < 2. Exceptions are recorded per token
   in a comment block. Light `--warn` must reach ≥ 4.5:1 on `--surface-editor` and
   `--surface-panel` (target `#a8520f`).
4. Hand-written (non-generated) blocks in `tokens.css`: type (`--font-ui`,
   `--font-code` with the fallback stacks of §5; `--text-title/body/small/tiny`,
   `--code-size/leading`, `--out-size/leading`, weights), space and size (§6 table,
   exact values), radii (`--r-1/2/3` = 3/4/6), `--focus-w` 2, `--led` 7, material
   recipes as custom properties (`--raised-bg`, `--raised-shadow`,
   `--recessed-bg`, `--recessed-shadow`, `--overlay-shadow`, per theme), motion
   tokens (`--dur-press` 60ms, `--dur-1` 90ms, `--dur-2` 140ms, `--dur-3` 200ms,
   `--travel` 8px, `--ease-out` `cubic-bezier(.2,.8,.2,1)`, `--ease-in`
   `cubic-bezier(.4,0,1,1)`, `--ease-in-out` `cubic-bezier(.45,0,.2,1)`), with
   `[data-motion="reduced"]` and `[data-motion="off"]` overrides per
   `motion-system.md` §2 and `@media (prefers-reduced-motion: reduce)` = reduced.
4b. Component colour tokens used by later tasks are part of the semantic block
   (generated, both themes): `--glyph-{rs,md,toml,other}` and `--glyph-*-bg`,
   `--icon-folder`, `--tree-guide`, with the values in `design-system.md` §2.2
   (SHELL-004 consumes them; a missing one would force a hard-coded colour).
5. **Legacy aliases** block (marked `/* legacy: removed by M1.6-QA-006 */`):
   `--bg`→`--surface-editor`, `--bg-subtle`→`--surface-chrome`,
   `--bg-elevated`→`--surface-overlay`, `--bg-hover`→`--hover`,
   `--bg-active`→`--press`, `--bg-selected`→`--selected`,
   `--bg-input`→`--surface-well`, `--border`→`--line-mid`,
   `--border-strong`→`--line-strong`, `--accent-line`→`--accent`,
   `--accent-hover`→`--accent-lo`, `--text-on-accent`→`--on-accent`,
   `--danger-soft`, `--warning`→`--warn`, `--warning-soft`, `--success`→`--ok`,
   `--shadow-popover`→`--overlay-shadow`, `--shadow-raised`, `--scrollbar`,
   `--scrim`, `--space-*`→`--s-*`, `--radius-s/m/l`→`--r-1/2/3`,
   `--dur-fast/normal`→`--dur-1/2`, `--ease`→`--ease-out`, and
   `--control-h`, `--row-h`, `--tab-h`, `--titlebar-h`, `--statusbar-h`, `--icon`
   kept under their names with the new values. The current UI must render with no
   missing variable (checked by test 4 below).
6. `tests/tokens.test.ts`: keep the three existing tests (adapting block lookup to
   the markers) and add: (a) every pair in `design-system.md` §2.3 meets its
   minimum in both themes; (b) `--focus` is ≥ 3:1 against `--surface-editor`,
   `--surface-panel` and `--surface-chrome`; (c) every `var(--x)` referenced
   anywhere in `src/**/*.{css,ts,tsx}` is defined in `tokens.css`; (d) no CSS
   `transition` or `animation` on `width|height|top|left|right|bottom|grid-template`
   and no `backdrop-filter`/`filter:` in `src/styles/**`; (e) every `animation:` or
   `transition:` duration in `src/styles/**` is a `var(--dur-*)` (except `0s`).
7. `scripts/check.sh`: one step, `node apps/desktop-tauri/scripts/gen-themes.mjs --check`,
   next to the schema-freshness step.

## Constraints
- No component CSS changes beyond what the aliases require (restyles are other
  tasks). `app.css` stays as it is.
- Literal colours only inside `tokens.css` (existing guard).
- No new dependency.

## Non-goals
- Fonts (SYSTEM-002); components (SYSTEM-003/004); a user theme editor (later milestone).

## Acceptance criteria
1. `gen-themes.mjs` regenerates `tokens.css` byte-identically on a second run, and
   `--check` passes; editing `themes.json` without regenerating makes `--check` and
   `scripts/check.sh` fail.
2. All §2.2 tokens exist in both themes, within ΔE < 2 of the documented values or
   with a recorded exception.
3. The new guard tests (a)–(e) pass, and each fails on a deliberately broken
   fixture (shown in the handoff).
4. The current UI renders without missing variables: the e2e smoke suite passes,
   and a new e2e check asserts that `getComputedStyle` of `.shell`, `.tab`, `.tree-row`
   and `.statusbar` has no empty value for any alias.
5. 51+ Vitest tests and all e2e suites (smoke, quit, geometry, parity) pass.

## Tests
- `node apps/desktop-tauri/scripts/gen-themes.mjs && node apps/desktop-tauri/scripts/gen-themes.mjs --check`
- `cd apps/desktop-tauri && pnpm test` — new cases in `tokens.test.ts`: "§2.3
  contrast pairs (dark|light)", "focus ring ≥ 3:1", "every referenced token is
  defined", "no animated layout properties or filters", "durations use tokens".
- `apps/desktop-tauri/scripts/e2e.sh` (all suites); `scripts/check.sh`.

## Failure conditions
- Hand-edited values inside the generated markers.
- A contrast test weakened or skipped to pass.
- Any existing component loses a colour (an alias missing).
