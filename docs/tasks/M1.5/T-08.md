# T-08: Recover from a webview crash without losing unsaved text

## Objective
If the web process that renders the UI and Monaco terminates, the host reloads
the page and the unsaved text of each dirty document comes back marked dirty.
The outcome matches Qt's `tst_smoke_editor::unsavedTextSurvivesARendererCrash`.
This closes parity row E-12, the highest-severity gap in
`docs/migration/qt-to-tauri/feature-parity.md`.

## Context
Source: implementation-roadmap.md §1 (wave C), §2 (T-08). Design:
`docs/migration/qt-to-tauri/architecture.md` §3.5 (crash recovery).
Rule: `docs/protocols/editor-bridge.md` line on `textSnapshot` (sent at most
once per second per dirty document; shell keeps the latest snapshot in memory)
and the renderer-crash row (reload, then `openDocument` with `dirty: true` from
snapshot). The bridge-1 message set is frozen.
Note: this task's scope names the bridge path `apps/desktop-tauri/bridge/` which
moved to `crates/desktop-bridge` in T-02; the bridge is not changed for the
crash logic unless the move left an old path. Record the path actually used.

## Required interfaces
- `editor/src/documents.ts` (shared, read only for rules).
- Bridge-1 `textSnapshot` (`{path, text}`) and `openDocument`
  (`{path, text, version, activate, dirty}`) in `docs/protocols/editor-bridge.md`.
- Tauri 2 web-process termination events: WebKitGTK `web-process-terminated`,
  WebView2 `ProcessFailed`, WKWebView `webViewWebContentProcessDidTerminate`
  (roadmap §2 T-08).
- `apps/desktop-tauri/src/state/documents.ts` (store, `ready` handshake).

## Implementation requirements
1. The host (`src-tauri/`) receives `textSnapshot` messages and holds the latest
   snapshot per document path in memory only; no snapshot is written to disk.
2. The host detects web-process termination on Linux (WebKitGTK), Windows
   (WebView2) and macOS (WKWebView) and reloads the main webview.
3. After reload, the page sends `ready` (existing handshake). The store answers
   by reopening each document that has a snapshot with `openDocument` carrying
   `dirty: true` and the snapshot text; the others reopen from disk with
   `dirty: false`.
4. A snapshot is discarded when the document is saved or closed clean.
5. Snapshots are bounded by the 16 MiB file limit per document and are not
   included in any protocol request (no protocol change).
6. Tests for the store logic live in `apps/desktop-tauri/tests/stores.test.ts`.

## Constraints
- Bridge-1 message set and semantics unchanged (frozen).
- Protocol 0.1 unchanged; no new protocol method.
- The host holds no workspace file logic: snapshot text is never written to disk
  by the host and never used to read a path (governance rule 5/6).
- No new host command beyond the seven in architecture.md §2.3; the crash signal
  is internal to the host.

## Acceptance criteria
1. E2E test kills the web process and asserts the unsaved text returns marked
   dirty on Linux and Windows (roadmap T-08 acceptance; req. 2–3).
2. On macOS the same check is performed manually and recorded as manual (roadmap
   T-08: "macOS: manual").
3. A clean document reopens from disk and is not dirty after the crash.
4. Snapshots are not persisted to disk (req. 1, 5): reviewer confirms no write path.
5. E-12 row in feature-parity.md is ✅ with the E2E check number only when the
   Linux and Windows runs pass.

## Tests
- `cd apps/desktop-tauri && pnpm test` — store tests for snapshot hold, replay and discard.
- `apps/desktop-tauri/scripts/e2e.sh` — crash case; on Linux under
  `apps/desktop-tauri/scripts/headless.sh`.
- Windows: the same E2E case in CI (T-09).
- `cargo test -p axiom-desktop-tauri` — host unit tests for snapshot holding.

## Failure conditions
- Recovery is shown to work on Linux only and the row is marked ✅ for all OSes.
- The crash test is replaced by a unit test that does not kill the web process.
- Unsaved text is written to disk or to a protocol request.
- Crash detection is missing on any of the three engines without a recorded
  reason; the macOS case is "manual" only if it is recorded as such.
