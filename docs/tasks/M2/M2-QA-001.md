# M2-QA-001: M2 exit: the clean-machine scenario and the provider suite on every OS

## Objective
The M2 exit criterion is shown end to end: on a machine without Rust, open a Cargo project → Axiom reports Rust missing → shows an install plan → installs a managed toolchain → `cargo build` runs inside it → a compile error appears in Problems → clicking it opens the file at the line → uninstall removes the directory and nothing else. The provider contract suite passes for all bundled providers on Linux, macOS and Windows.

## Context
`docs/roadmap/milestones.md` §M2 exit; ADR-0014 §8.

## Required interfaces
- Everything above; the e2e harness (private Xvfb, isolated profiles).

## Implementation requirements
1. CI job in a clean container (no Rust on PATH) running an e2e suite `env.mjs` that performs the whole scenario through the UI and asserts each step, plus a directory snapshot before/after uninstall.
2. Provider contract suite as a CI matrix (Linux, macOS, Windows).
3. Once by hand on the owner's machine; record in `docs/roadmap/verification/M2.md`.
4. Performance: P2/P7 unchanged by M2 (bench `--ab` against the M1.6 build).

## Constraints
- ADR-0014 (accepted) is the decision record; do not reopen its decisions in this task.
- Frozen contracts (IPC 0.1 meanings, editor bridge 1) unchanged; additive protocol changes only where this spec says so.
- `scripts/check.sh` green; no test deleted, weakened or skipped.

## Acceptance criteria
1. `env.mjs` passes in the clean container; the snapshot diff after uninstall is empty.
2. Contract suite green on all three OSes.
3. Verification record written with run ids.

## Tests
- `scripts/e2e.sh env.mjs` (container); CI matrix; bench `--ab`.

## Failure conditions
- Any step done by a test hook instead of the UI and the protocol.

## Documentation updates
`docs/roadmap/verification/M2.md`, `docs/roadmap/milestones.md` (M2 status), `docs/roadmap/current.md`.

## Handoff
Run ids, timings, and the snapshot diff.
