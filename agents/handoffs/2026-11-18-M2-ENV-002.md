## Download cache layout and plan lifetime
- **Cache:** `<data dir>/cache/<sha256>` holds verified downloads, keyed by their expected digest
  and re-hashed before reuse. A download in progress is `cache/.part-<planId>`, renamed only after
  its digest matches.
- **Installs:** `<data dir>/toolchains/<provider>/<version>/`. While extracting and verifying,
  an install lives in `toolchains/<provider>/.staging-<version>-<planId>/`; detection ignores
  dot-directories.
- **Plans:**
  - A plan is a server-side record. The client holds only its `planId` (32 hex characters).
  - It expires after 10 minutes, and expired records are pruned when the next plan is issued.
  - Any install attempt, including a refused one, removes the record, so a plan runs at most
    once.
  - The provider's current manifest must equal the one the plan was made from (any change to a
    URL, digest, step source or tool is refused).

## Behaviour implemented
- **`crates/env/src/fetch.rs`:**
  - `Http` uses reqwest 0.12 with rustls and the OS trust store (`rustls-tls-native-roots`):
    no native TLS, and no webpki-roots, whose CDLA licence is not in `deny.toml`.
  - A custom redirect policy (HTTPS, at most 10 redirects); 20 s connect and 60 s read timeouts.
  - Version sources: `static`; `json` with a `*` pointer; `github_releases` (drafts and
    pre-releases skipped).
  - `HEAD` for sizes. It reads the header: reqwest's `content_length()` reports 0 on HEAD.
  - Checksum-file parsing.
- **`archive.rs`:** our own extraction for tar.gz, tar.xz and zip. The rules are in the module
  doc.
- **`install.rs`:** `Installer` with `versions` (one-hour cache), `plan`, `install`,
  `uninstall`, `host_platform` and `valid_version`.
- **`error.rs`:** `EnvError` maps to `RpcError`:
  - an unsafe archive → `permission_denied` with details `{reason}`;
  - a network failure → `io` with `retryable`;
  - checksum → `checksum_mismatch` with `{url, expected, actual}`.
- **`detect.rs`:** `tool_version_in_root` (verifies a staged root) and a public
  `managed_bin_dirs`.
- **`axiomd`:**
  - `App` holds an `Arc<Installer>`.
  - `env/install` runs the install as its own task. The RPC layer aborts a cancelled handler
    after 100 ms, but the install still sees the cancellation and cleans up itself.
  - Progress is forwarded through a channel, and every progress notification is queued before
    `env/installed`, which comes before the response.

## Deviations and decisions
- **"Altered plan":** the client sends only the `planId`, so it cannot alter the plan, and the
  daemon executes its own copy. "Altered" is enforced as "the provider's manifest changed since
  planning".
- **Planning an installed version is `already_exists`.** Reinstalling means uninstalling first.
- **Verification failure is `not_found`** ("demotool did not run from the installed files").
  ADR-0014 names no error kind for it.
- **Installs use built-in and user providers only.** `PlanInstallParams` has no workspace, so
  trusted workspace providers can be detected but not installed. If that is needed, an optional
  `workspaceId` would be an additive change.
- **Test-only switch:** `AXIOM_TEST_INSECURE_LOOPBACK_HTTP=1` is read by `axiomd`. It allows
  plain HTTP to 127.0.0.1, ::1 and localhost only, and logs a warning. UI-002's end-to-end tests
  can use it with a fixture server.
- **Outside the declared scope:** `crates/axiomd` (handlers, `App`, tests and dev-dependencies).
  The spec's scope line names `crates/env` only, but the daemon must serve the methods.
- **Checksum files are matched by base name**, because static.rust-lang.org writes
  `<hex> *./rustup-init`. Found while preparing ENV-003.
- **Fixed in this task:** ENV-001's `detect_found_and_missing` failed on Windows CI. The test
  built an expected path with `join("demo/1.10.0")` and compared strings. The same pattern was
  fixed in the new install test.
