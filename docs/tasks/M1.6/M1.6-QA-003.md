# M1.6-QA-003: Accessibility verification

## Objective
The redesigned shell is shown, by automated checks and one recorded manual pass on
Linux, to be fully keyboard-operable, to keep focus visible everywhere, to meet the
contrast requirements of `design-system.md` §2.3 on **rendered composites** (not
just tokens), to convey no state by colour alone, and to honour reduced motion and
forced colours. Results are recorded in `docs/roadmap/verification/M1.6.md` §A11y.

## Context
`docs/design/design-system.md` §2.3 (contrast), §8 (focus and states);
`motion-system.md` §6 (reduced motion); `frontend-architecture.md` §6 (forced
colours); `docs/architecture/design-system.md` §Accessibility rules; M1.5's open
screen-reader item (S-8 in `docs/migration/qt-to-tauri/feature-parity.md`), which
is still unverified. `agents/MANUAL_VERIFICATION.md` is the procedure for the
manual pass.

## Required interfaces
- The e2e harness (`e2e/webdriver.mjs`, `runner.mjs`) and the QA-001 shots
  harness (fixture workspace, state drivers).
- `appearance.motion` (INTERACTION-001) and `appearance.theme`.

## Implementation requirements
1. Add `e2e/a11y.mjs` (suite run by `scripts/e2e.sh a11y.mjs`) with these checks,
   each in dark and light:
   1. **Tab traversal**: from the window start, Tab reaches in order the title-row
      menus, workspace switcher, command field, transport buttons, layout toggles,
      tree, editor tabs, editor, console tools, prompt, status-bar interactive
      segments; Shift+Tab reverses; no trap outside dialogs (dialogs trap).
   2. **Focus visible**: for every element reached in 1, its computed `outline`
      (or the documented inset ring for rows) is ≥ 2 px or the row ring is present,
      and is not clipped (bounding box inside its scroll container).
   3. **Names and roles**: every focusable element has a non-empty accessible name
      (`aria-label`, `aria-labelledby` or text) and a role; list all violations.
   4. **Rendered contrast**: for every visible text node in states S2, S4, S7,
      S11 and S12, compute the colour against the *rendered* background (walk
      ancestors, compositing translucent fills) and require ≥ 4.5:1 (≥ 3:1 for
      text marked `data-nonessential`, i.e. line numbers, placeholders,
      ignored rows, idle hints); report every failure with selector and ratio.
   5. **Not by colour alone**: assert that dirty tabs carry "(unsaved)" in the close
      button name; stderr rows have the hidden "stderr:" prefix; LEDs have a label
      or adjacent text; the failed task status contains "Failed".
   6. **Reduced motion**: with `appearance.motion = "off"`, after any interaction
      settles, `document.getAnimations().filter(a => a.playState === "running")` is
      empty; with the OS emulation `prefers-reduced-motion`, presence fades ≤ 80 ms.
   7. **Forced colours** (Chromium-only emulation is not available in WebKitGTK):
      checked manually on Windows in QA-005; record "unverified" here.
2. Manual pass on Linux with **Orca** (GNOME, WebKitGTK accessibility): open a
   folder, navigate the tree, open a file, hear the tab names and the dirty state,
   run a command, hear the status change, open the palette and choose a command,
   handle the unsaved dialog. Record what is announced and any gaps.
3. 200% scale pass (`GDK_SCALE=2`): no clipped text or overlapping controls in
   S4, S7, S11; minimum hit targets ≥ 24 px at 100%.
4. Write the results table into `docs/roadmap/verification/M1.6.md` §A11y
   (create the file if absent, using `verification/M1.5.md`'s layout).

## Constraints
- Fix nothing in product code here. Each failure becomes a defect note on the
  owning task (governance: fix on the dependency) and is re-checked after the
  fix. Trivial token fixes may be made only through SURFACES-003's owner.
- No new dependency (no axe-core: the checks above are implemented in the suite).

## Non-goals
- macOS VoiceOver and Windows NVDA/Narrator (QA-005, hardware); M7's full audit.

## Acceptance criteria
1. `a11y.mjs` passes in dark and light, with zero violations in checks 1–6.
2. The Orca transcript is recorded with every gap listed and triaged.
3. The 200% pass is recorded with screenshots.
4. The verification record states clearly what is unverified on macOS and Windows.

## Tests
- `apps/desktop-tauri/scripts/e2e.sh a11y.mjs` (under `headless.sh`).
- All other suites: `scripts/e2e.sh` (smoke, quit, geometry, parity, shots).
- `scripts/check.sh` green.

  record.
- The manual Orca pass is skipped and the task is marked tested anyway.
