## Exit criterion
> In fixture projects for each tier-1 language on Linux and macOS, starting with no server
> installed: opening a source file offers the server; after the approved install, completion lists
> a standard-library symbol with its documentation within 300 ms of typing its prefix, hover shows
> its docs, and go-to-definition opens the SDK's source; every file in the grammar fixture set is
> highlighted with its language named in the status bar; typing and scrolling stay within the
> frame budget on a 10,000-line file.

- **The grammar fixture set:** every file of `tests/fixtures/languages` is recognised and
  highlighted (`language_fixtures_test.dart`) → **pass**.
- **The offer and the approved install:** proven end to end with servers installed from loopback
  (`lsp_install_test.dart`) → **pass**.
- **Completion, documentation, hover, definition:** proven with the fake server (`lsp_test.dart`)
  → **pass**.
- **With the real servers per language:** `languages_test.dart` (opt-in,
  `AXIOM_TEST_LSP_INSTALL=1`, it downloads servers and SDKs) **has not been run**: downloading
  them here needs the owner's go-ahead. The real installs of marksman, rust-analyzer and
  basedpyright run in CI (`ci_lsp_install.rs`). .NET is not installed by Axiom (SHA-512 digests
  only upstream; ADR-0021 §6) and SourceKit-LSP needs a Swift toolchain, so those two languages
  are skipped with the reason.
- **Frames** (`frames.sh`, profile build, virtual KWin at 125 %): typing, drag and Shift+Down
  selection, editor fling: no frame over 16.7 ms → **pass**.

## Performance (P2, P7 against M5)
Release builds of both; M5 is `main` at `9aa8ae8`, exported and built clean, with its own `axiomd`.
Interleaved pairs (`--ab`) on a private Xvfb with software rendering. The load was 5–9, which
made both builds slow in absolute terms (startup ~1.7 s cold against M5's 255 ms in its own
record); the paired differences are what is compared.

- **P2, first run** (`M5.5-bench/p2-first.json`): +47 ms cold, +73 ms warm. Two causes found:
  the daemon rebuilt the registry and the environment for each of the ~20 servers it lists when
  a folder opens, and the shell ran tool detection (`env/detect`, a JVM start among others) on
  every folder open to name providers. Both fixed: the launch base is read once per listing, and
  only provider names are read, when an offer needs them.
- **P2, after the fix** (`M5.5-bench/p2-after-fix.json`, 7 pairs): **−10.0 ms cold**
  (−154…+52), **+18.0 ms warm** (−69…+95); medians 1730.6 / 890.7 ms against M5's 1739.1 /
  897.7 → **pass**.
- **P7** (`M5.5-bench/p7.json`, 3 pairs): idle CPU **0.0 %** with a folder and with a document
  (M5: 0.0 %); PSS **+2.4 MiB** with a folder (−1.5…+7.5), **−5.4 MiB** with a document;
  typing p99 **−14.2 ms** → **pass**.
