# M1.6-SYSTEM-002: Bundle the IBM Plex typefaces

## Objective
The shell renders with IBM Plex Sans (400/500/600) and IBM Plex Mono (400/500)
from bundled WOFF2 files on every OS, so metrics and appearance are identical
across Linux, macOS and Windows, within the start-time budget.
**If D2 was rejected by ADR-0013:** this task instead records the fallback stacks
of `design-system.md` §5 in `tokens.css` and verifies them per OS (requirements 6–7
only).

## Context
`docs/design/concepts.md` §1.3 weakness 10 (named fonts are not bundled, so each
machine shows a different fallback) and D2; `design-system.md` §5 (type scale and
fallbacks); `frontend-architecture.md` §4 (vendored files, not `@fontsource` at
runtime) and §6 (smoothing per OS). The CSP allows `font-src 'self' data:`
(`src-tauri/tauri.conf.json`): no CSP change is needed.

## Required interfaces
- `--font-ui`, `--font-code` tokens (SYSTEM-001).
- The editor font setting (`editor.fontFamily`): an empty value means "the theme's
  code face" (`src/App.tsx` reads `--font-mono` today; keep the alias working).
- The ADR-0011 licence policy and the CR accepted in DESIGN-001 (OFL assets).

## Implementation requirements
1. Obtain IBM Plex from the official release (github.com/IBM/plex, tagged release
   archive), verifying its SHA-256 against the release page. Vendor IBM's **own,
   unmodified** split WOFF2 files (`fonts/split/woff2/`) for Sans 400/500/600
   (+400 italic for comments) and Mono 400/500 (+400 italic): the `Latin1` subset,
   plus `Pi` (arrows, box drawing and symbols used by cargo output) if its glyphs
   are needed, under `src/assets/fonts/ibm-plex/`, with `OFL.txt` and a `SOURCE.md`
   (version, URL, SHA-256 of the archive, list of files and their SHA-256).
2. **Do not subset, convert or otherwise modify the files.** The Plex licence
   declares the Reserved Font Name "Plex"; a locally modified font (including our
   own `pyftsubset` output) could not be distributed under that name (ADR-0013 §6).
   If IBM's subsets exceed the size target, report it and stop rather than
   subsetting. Target total ≤ 200 kB; report the actual size.
3. `src/styles/fonts.css`: `@font-face` rules with `font-display: block` for the UI
   face (a 100 ms block avoids a layout shift at start) and `swap` for Mono (Monaco
   remeasures; see 5), plus `unicode-range`. Families are named `"Axiom Plex Sans"` and
   `"Axiom Plex Mono"` so an installed system Plex never shadows the bundled one.
4. `--font-ui: "Axiom Plex Sans", <fallback stack>` and
   `--font-code: "Axiom Plex Mono", <fallback stack>` (fallbacks exactly as in
   §5); `--font-mono` remains an alias of `--font-code` until QA-006.
5. After `document.fonts.ready`, call `monaco.editor.remeasureFonts()` once
   (in `MonacoHost.tsx`, guarded so that it runs only if Monaco is loaded), so that the
   editor's cursor measurement is correct with the swapped Mono.
6. `-webkit-font-smoothing: antialiased` only under `html[data-os="mac"]` (set
   `data-os` from `navigator.platform` in `main.tsx`; WebKitGTK and WebView2 keep
   their defaults). `font-feature-settings`: none by default; Plex Mono ligatures are
   off (Plex has none).
7. Text rendering check per OS on the gallery's type specimen: S4 and the
   SYSTEM-003 gallery "Type" section.

## Constraints
- Fonts load from the app bundle only (no network); the CSP is unchanged.
- No runtime npm dependency (no `@fontsource` in `package.json`).
- The OFL text ships with the fonts, and the licence list (About or the licences
  file) mentions IBM Plex.

## Non-goals
- Choosing a different typeface (DESIGN-001's job); a font-picker UI.

## Acceptance criteria
1. On Linux, `document.fonts.check('13px "Axiom Plex Sans"')` and the Mono
   equivalent are true at start (e2e check), and the computed `font-family` of
   `.tree-row` and `.view-lines` starts with the bundled family.
2. Bundle size growth ≤ 200 kB and is reported.
3. The typing-latency and cold-start budgets hold (P1, P2).
4. Cursor placement in Monaco is correct after load: a new e2e check types `abc` at
   the end of line 1 and asserts the caret's x equals the end of the rendered text
   ± 1 px.
5. `scripts/check.sh` green; all e2e suites pass.

## Tests
- `apps/desktop-tauri/scripts/e2e.sh smoke.mjs` with the new checks "bundled UI and
  code fonts are active" and "caret aligns after font swap".
- `pnpm test`: new `tests/fonts.test.ts` ("every @font-face src exists in
  src/assets/fonts", "OFL.txt and SOURCE.md present").

## Visual verification
S2, S4, S7 and S11 dark and light vs the SYSTEM-001 set: only glyph shapes and
metrics change. Check §5 "Typography" and "Alignment" (baseline drift in tabs,
tree rows and status bar) at 100% and S4 at 200%. Template `visual-qa.md` §7.

## Performance
P1 and P2 before/after (`bench/run.sh --runs 3`); P10 (memory). A cold-start
regression > 40 ms fails the task, unless the subset can be reduced further.

## Failure conditions
- Fonts fetched from a CDN or a non-official source; licence text missing.
- Visible text reflow after start (flash of fallback for the UI face).

## Documentation updates
`docs/design/design-system.md` §5 (actual families and sizes); the licences list
used by the About dialog or the README; `docs/decisions/` per the CR from DESIGN-001.

## Handoff
Font version, archive SHA-256, subset ranges, the size per file, before/after
start time, and screenshots of the type specimen on Linux (others: "unverified on
macOS/Windows").
