## Decisions and deviations from the spec text
- **`env/installed` is a notification as well as the end of the request.** The ADR says
  `env/install` "ends with `env/installed`". `env/install` stays a pending request, so `$/cancel`
  works on it as on any request, and responds with the `InstallResult`. Just before that, the
  daemon broadcasts `env/installed` with the same payload, so other views (the Environment page
  while a plan dialog runs the install) can refresh.
- **`env/trust` was added.** It is not in the ADR's table. ADR §5 needs "a per-workspace store flag
  set from the UI", and that needs a method. It is additive and recorded in `ipc.md`.
- **`ProviderInfo.errors` replaces a separate "invalid" list.** For a manifest that did not parse,
  `id` is its directory name.
- **`Step::SystemPackages` also carries `argv`**, the exact command after the elevation wrapper,
  so the plan shows every command (ADR §2).
- **`InstallPlan` also has `expiresMs`**, the 10-minute lifetime of ADR §2. The spec's
  `sha256Source` is the field `sha256` of type `Sha256Source`.
- **Unknown `Step` kinds fail to deserialize.** This is pinned in `install_plan_roundtrip`: a
  client must never approve a step it cannot show.

## Tests changed outside the protocol crate, and why
Registering the new methods before any daemon serves them broke three existing "the daemon serves
exactly the registry" checks. All three still assert exact set equality.
- **The checks:** `crates/axiomd/src/router.rs` (unit test), `tests/lifecycle.rs` and
  `tests/smoke.rs`.
- **What changed:** each now subtracts one list, `axiomd::NOT_YET_SERVED` in
  `crates/axiomd/src/router.rs`. It holds the ten env/build methods, and the router test checks
  that every name in it is a real protocol method.
- **Who empties it:** each M2 task that wires a method removes it, and M2-BUILD-001 leaves it
  empty.
- **Version assertions:** three now use `PROTOCOL_VERSION` instead of a literal `"0.1"`:
  `axiomd/tests/lifecycle.rs` (2 places) and `rpc/tests/behaviour.rs` (1). They asserted the
  server's version, which is now 0.2: the `supported` detail on a major mismatch, and the server
  minor that a 0.9 / 0.7 client negotiates down to.
- **Unchanged:** assertions that 0.1 clients get `"0.1"` (rpc, bridge and daemon tests) still pass.
- **Protocol tests:** `crates/protocol/tests/contract.rs` is unchanged; the new tests are in
  `tests/m2_contract.rs`.
- **Also outside the declared scope:**
  - `apps/desktop-tauri/src/daemon/protocol.gen.ts`, regenerated by `pnpm run gen:types` (the
    gate checks its freshness);
  - `scripts/check_deps.py`, as the spec requires;
  - the `axiomd` and `rpc` test files above. No behaviour changed.
