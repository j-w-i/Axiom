# 0017 A program keeps its own tools, and the harness is an advanced choice
**Decision** (the owner, 2026-11-26: "harness picking should be an advanced feature in settings turned off by default, and axioms own tooling should never overlap the default").
**Tools.** Claude Code, Codex and whatever else is linked work with the tools they come with. Axiom gives them only what is Axiom's to do: the tool `agent`, where their documentation says how (K41). It gives them none that reads, writes, runs or lists, also not in place of theirs. What was built for that on 2026-11-25 (`--tools ""`, all of Axiom's tools over the bridge, the environment `axiom`) is gone, and with it the list of things to do and the plan over the bridge: those are for Axiom's own loop, and Claude Code and Codex have their own.
**One that was set up so** is not started: with its own tools it would be held back by something else than its person was told. It says so, and another agent is added (SI-1, SI-26).
**What that costs.** Claude Code can look or work, and not ask first (K40): its way of asking is not documented for a program other than its own SDK. What it does is contained by its own sandbox, not by Axiom's, and is not judged by a folder's rules. It is said before each start, as of any program.
**The harness** follows from the model: a person chooses a model, of an account or of a program that is linked, and is not asked for a harness beside it. With *Choose the harness* in Settings, off unless somebody turns it on, it is a choice of its own, as before. Whose model it is, is shown with it in any case, and who runs an agent is never hidden (PR-2, PR-12).
**Alternatives.** Both sets of tools at once: two ways to do each thing, one of them judged and the other not. Axiom's in place of the program's, as a choice in advanced settings: what is there has to be kept working for nobody.
**Reverses** the last part of "considered and refused" in 0007.
