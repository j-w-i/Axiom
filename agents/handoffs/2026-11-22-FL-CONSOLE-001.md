# Handoff — 2026-11-22 — FL-CONSOLE-001

Session: Claude   Branch: task/flutter

## Result
Task status: **implemented**. Verified on Linux (Fedora 44, KDE Wayland; the suites in a private
virtual KWin and in a private Xvfb). macOS runs in CI.

- **`lib/state/tasks.dart`**: a port of the Tauri `TasksStore` and `OutputBuffer`.
  - One command at a time; output in `seq` order, with late and duplicate chunks handled,
    split per stream; ANSI stripped; the last CR overwrite kept.
  - Capped at 10 000 lines and published once per frame.
  - The history is `run.history` in workspace state.
  - Provider tasks come from `build/tasks` and run with `build/run`.
  - Output that arrives before `task/start` answers is replayed.
  - `spawn_failed` becomes a structured error line.
  - `task/list` gives the start time.
- **`lib/state/problems.dart`**: `build/diagnostics` per run, and each provider task's new run
  replaces its last one's. Alongside the language servers' diagnostics.
- **`lib/state/terminals.dart`**: `terminal/*`. The store owns one `xterm` `Terminal` per
  daemon terminal, so screens survive switching console views.
  - Output that arrives before the create answers is kept.
  - When the folder opens, `terminal/list` brings the terminals back with their backlog.
  - Tabs are labelled "zsh 2" and "(ended)".
- **`lib/console/output.dart`**:
  - the Output view: the prompt (Enter runs, ↑↓ walk the history), Run or Stop, Clear, and the
    rows (stderr in amber and named "stderr: …" for screen readers, status rows in green or
    red, selectable);
  - the `Transport` in the title row: a lamp, the label, mm:ss, a 16-bar rate meter, Stop, and
    "Rerun: …" when idle.
- **`lib/console/terminal_view.dart`**:
  - terminal tabs with New and Close;
  - `TerminalView`, themed from the tokens (`AnsiColors`, the Tauri values);
  - the window's chords pass through to the shell (`app.shellShortcut`); the list is Tauri's
    `isAppChord` plus Mod+Shift+`;
  - copy and paste: Ctrl+Shift+C/V, or Cmd+C/V on macOS.
- **Shell:**
  - the console has Output, Problems and Terminal views;
  - new commands: Run Command… (Mod+Shift+R), Rerun (F5), Stop (Shift+F5), the provider tasks
    ("Build: cargo build" …), New Terminal (Mod+Shift+`), Show Terminal, Focus the Console
    (Mod+`);
  - the shortcut map is one table, used by the window and by the terminal's pass-through.
- **Dependencies:** `xterm` 4.0.0 (MIT), named in ADR-0020, with `zmodem` (MIT).
  `check_dart_licences.py` passes. `xterm` imports Material internally; Axiom's own code still
  doesn't (`no_material_test`).

## Deviations
- **The test types into the shell** with `Terminal.textInput`, the call `TerminalView` makes
  for text input, plus real Enter and Ctrl+C key events. Flutter's simulated key events carry
  no text on desktop.
- **The terminal test starts the shell as `/bin/sh`** (`SHELL` for the daemon) for a
  predictable prompt; the shell the daemon picks is covered by its own tests.
- **Clicking a Problems row** opens the file and focuses the editor. Keyboard Enter on a row
  was already covered by `lsp_test`.
- **The frame benchmark was not run again** for this task. The console's new views are not in
  `frames_test`, and the title row changes only while a task runs.
