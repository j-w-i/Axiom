# M1.6-QA-002: Performance baseline and the new bench scenarios

## Objective
Before any restyle merges, the existing ten budget rows are re-measured on the M1.6
branch, and six new scenarios exist in the bench and are measured on the
unchanged shell: tab switch, palette open, panel toggle, splitter drag,
idle-with-task-running, and typing under streaming output. Together they replace
the provisional baseline in `docs/design/performance.md` §1.

## Context
`docs/design/performance.md` §1 (provisional baseline), §3 (budgets P1–P12),
§4 (procedures). Existing harness: `apps/desktop-tauri/bench/run.sh` and `run.py`,
`daemon_tap.py`, and results in `bench/results/`. Prototype numbers
(`docs/design/concepts.md` §4) are indicative only and are not a baseline.

## Required interfaces
- `bench/run.py` scenario structure and the `medians` block of its JSON.
- The e2e WebDriver client (`e2e/webdriver.mjs`) and the `e2e` Cargo feature build.
- App shortcuts: Ctrl+Tab, Ctrl+K, Ctrl+B, Ctrl+J (`src/App.tsx`, unchanged here).

## Implementation requirements
1. Add `src/e2e-probe.ts`, imported only when `import.meta.env.MODE === "e2e"` (or
   the existing e2e build flag; production `dist` must not contain it). It exposes
   `window.__axiomFrames.start()/stop()` (rAF intervals), `window.__axiomMarks`
   (keydown `timeStamp` → the first rAF after a named DOM condition), and a React
   commit counter via `<Profiler>` around the workbench.
2. In `bench/run.py`, add scenarios with these exact names and methods
   (performance.md §4.2): `tab-switch` (4 documents, Ctrl+Tab ×20, key → the first
   frame after Monaco's model change; p50/p95), `palette` (Ctrl+K ×20: key → the
   first frame with `[data-testid=palette]`; rAF intervals during open/close),
   `panel-toggle` (Ctrl+B and Ctrl+J ×10; rAF intervals for 400 ms after each),
   `splitter-drag` (40 WebDriver pointer moves on the side-bar splitter;
   rAF intervals and the commit count), `idle-running` (run `sleep 30`; sample
   `/proc/<pid>/stat` of the app, `WebKitWebProcess` and `WebKitNetworkProcess` for
   10 s focused and 10 s with focus moved to another X window; % of one core), and
   `typing-under-stream` (run
   `python3 -c "import time,sys;[(print('x'*80),sys.stdout.flush(),time.sleep(0.0005)) for _ in range(10000)]"`,
   about 2,000 lines/s for 5 s; type 200 characters with the existing typing probe).
3. Each scenario writes medians into the `medians` block under `tauri.<scenario>`
   and reports frames > 20 ms and > 25 ms counts.
4. Run `bench/run.sh --runs 3 --heavy-runs 3` on the reference machine with load
   < 1.0 (quote `uptime`), on the branch head **before** SYSTEM-001 merges.
   Commit the JSON to `bench/results/`.
5. Record the UI bundle size (`dist/assets/*.js` excluding the Monaco chunk, and
   total CSS) in the handoff.

## Constraints
- The probe must be absent from production builds: a Vitest test greps `dist/` for
  `__axiomFrames` after `pnpm run build` and fails if found.
- No change to product behaviour; no new runtime dependency; Python standard
  library only in the bench.

## Non-goals
- Judging the redesign (QA-004); macOS/Windows numbers (QA-005, needs hardware).

## Acceptance criteria
1. The six scenarios run end to end through `bench/run.sh` and appear in the JSON.
2. A baseline JSON from the unchanged shell exists in `bench/results/` with all
   ten existing rows and the six new ones, three runs each.
3. `docs/design/performance.md` §1 is replaced by the measured table (source = the
   new JSON file name).
4. The probe is not in the production bundle (named test).
5. Existing e2e suites (smoke, quit, geometry, parity) and the 51 Vitest tests pass.

## Tests
