## The project.toml grammar as built
```toml
[environment]               # the only table; anything else is an error
<provider-id> = "<version>" # [a-z0-9][a-z0-9-]* = an installed managed version, or "system"
```
- **Versions:** `[A-Za-z0-9._+-]`, at most 64 characters, not starting with `.`; or the literal
  `"system"`.
- **Errors:** `invalid_params` with `{line, reason}`, and the message starts with
  `.axiom/project.toml:`. TOML syntax and unknown keys get the parser's line. A bad id or
  version gets the line of its key.
- **Resolution rules:** see `providers.md` §Project files (as built).

## Behaviour implemented
- **`crates/env/src/project.rs`:**
  - `parse`;
  - `resolve`, which collects every missing tool or provider into one `prerequisite_missing`;
  - the `Lock` / `LockedToolchain` / `LockedDownload` types, with stable TOML text and no host
    paths;
  - `Receipt`;
  - `process_env` (`vars` plus `PATH` = prepend + inherited).
- **`install.rs`:** writes `<root>/.axiom-install.toml` (provider, version, the downloads with
  their digests) into staging before the publishing rename.
- **`error.rs`:** `ProjectFile { line, reason }` → `invalid_params` with those details.
- **`axiomd`:**
  - `env/resolve` reads `project.toml` through `Workspace::read_text` (containment). It
    resolves with the workspace's providers (trust applies) and the daemon's `PATH`, then
    compares with the current lock and writes through `Workspace::write_text` (temp file +
    rename) only on a difference.
  - `env/detect` adds `selectedVersion` (a malformed file is ignored there and reported by
    `env/resolve`).
- **`axiom-exec`:** `SpawnSpec` already had an `env` overlay, so no change was needed. A new test
  proves that the overlay's `PATH` selects the program.

## Deviations and decisions
- **The spec's test name `lock_written_atomically` is a daemon test.** `crates/env` cannot write
  into a workspace (no edge to `workspace`), so the daemon does the write.
  `resolve_writes_the_lock_once_and_detect_shows_the_selection` covers it: the write goes
  through `write_text`, no temp file remains, and an unchanged lock is not rewritten.
- **`missing` lists tool ids, plus the provider id for an unknown provider.** The spec says
  "missing tool ids".
- **`task/start` (IPC 0.1) does not apply the environment by itself.** That would change a
  frozen meaning. Provider tasks (`build/run`, M2-BUILD-001) will run inside it.
- **Outside the declared scope:**
  - `crates/axiomd` (handlers and tests);
  - `crates/exec/tests/exec.rs` (the overlay test);
  - `crates/env/tests/ci_install.rs` (the real-toolchain check).
