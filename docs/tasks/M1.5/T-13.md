# T-13: Packaging for Linux, Windows and macOS

## Objective
CI builds release packages for each OS: AppImage, deb and rpm on Linux; MSI and
NSIS on Windows; dmg on macOS. The daemon ships as a Tauri `externalBin`. Signing
hooks and the licence bundle are in place. Each artifact installs, launches and
connects to the daemon in a smoke test.

## Context
Source: implementation-roadmap.md §1 (wave D), §2 (T-13), exit criterion 6 of M1.5,
§5 condition on release packages. Licensing inputs: ADR-0011 as amended by T-01
(WebKitGTK LGPL-2.1 system library; WebView2 bootstrapper terms) and
`docs/migration/qt-to-tauri/architecture.md` §1.2 R21 and §2.2 (build).

## Required interfaces
- `apps/desktop-tauri/src-tauri/tauri.conf.json` (bundle targets, `externalBin`).
- `apps/desktop-tauri/src-tauri/` capabilities (unchanged by packaging).
- `.github/workflows/ci.yml` — packaging job or steps (additive).
- `docs/` — licence notices and install docs.

## Implementation requirements
1. `tauri.conf.json` bundle targets: `appimage`, `deb`, `rpm` (Linux); `msi`,
   `nsis` (Windows); `dmg` (macOS).
2. The daemon `axiomd` is declared as `externalBin` for each target triple; the
   host's `--daemon` default resolves the bundled binary first, then the existing
   lookup order (`bridge::locate_daemon` in `crates/desktop-bridge`).
3. Signing hooks: configuration points for Windows and macOS signing exist and are
   disabled unless secrets are present; no secret is committed.
4. Licence bundle: the package includes the Axiom licence, third-party notices, the
   WebKitGTK LGPL notice on Linux, and the WebView2 bootstrapper terms on Windows.
5. CI: a packaging job builds the artifacts on each OS and uploads them.
6. Each artifact is smoke-tested in CI: install, launch, the status shows
   "connected" (daemon `initialize` succeeded), exit cleanly.
7. Record the installed size per OS in the handoff.

## Constraints
- No new command or capability in the host (architecture.md §2.3).
- Packaging does not change protocol 0.1 or bridge 1.
- The Qt shell is not packaged by this task; it remains the release artifact until T-14.
- `.github/workflows/ci.yml` changes are additive (governance parallel work rule).

## Acceptance criteria
1. Artifacts for each target listed in req. 1 are built in CI (req. 1, 5).
2. Each artifact installs, launches and connects in the smoke test (req. 6).
3. The daemon is present inside each package as `externalBin` (req. 2).
4. Licence notices are present in each package (req. 4).
5. Installed size is recorded per OS (req. 7).
6. Signing is configured but not required for the build to pass without secrets (req. 3).

## Tests
- `cargo build -p axiom-desktop-tauri --release` (per OS, CI).
- `cd apps/desktop-tauri && pnpm tauri build` (per OS, CI packaging job).
- Smoke test per artifact in CI: install, launch, read connected status.
- `scripts/check.sh` — green on Linux.

## Failure conditions
- An artifact is reported as installed-and-launched without the smoke test run.
- A target is missing from the bundle list without a recorded reason.
- A licence notice is missing from any package.
- A secret is committed or required to pass the build.
- An OS is not built: report "unverified on <OS>".

## Documentation updates
- `docs/contributing/dev-setup.md` — packaging prerequisites per OS.
- `docs/` licence notice location (e.g. `docs/licensing/` if it exists; otherwise
  the notice is added where ADR-0011 is amended — state the path in the handoff).
- `docs/roadmap/current.md` (governance rule 10).

## Handoff
Per-OS artifact list with names and sizes, smoke-test results with CI links,
licence notice paths, and signing status (configured / not configured).
