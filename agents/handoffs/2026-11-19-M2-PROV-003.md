## Behaviour implemented
- **`providers/python/provider.toml`:**
  - **Delegate `uv`** with `UV_PYTHON_INSTALL_DIR`, `UV_PYTHON_BIN_DIR`, `UV_CACHE_DIR` (all under
    `${root}`), `UV_PYTHON_INSTALL_REGISTRY=0` (no PEP 514 registry writes on Windows) and
    `UV_NO_CONFIG=1` (the user's `uv.toml` is ignored).
  - **Versions:** a static list (3.13, 3.12, 3.11, 3.10). uv resolves each to the newest patch
    release.
  - **Bootstrap archive:** uv's `latest/download` URLs; `${version}` here is the Python version.
- **Installer fix found here (`install.rs` `relink`):** uv leaves **absolute** symlinks
  (`bin/python3 → <root>/python/.../python3.12`). Because installs run in a staging directory
  that is then renamed, those links would dangle.
  - Before publishing, every symlink whose absolute target is inside staging is re-pointed at
    the same path under the final root.
  - Relative links and links outside the root are left alone.
  - Unit test: `relink_points_absolute_links_at_the_final_root`.
- **CI test:** `ci_install.rs` `python_managed_install_roundtrip`.
