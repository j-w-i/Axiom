## Behaviour implemented
- **`manifest`: `parse` and `validate`.** Validation returns every problem, not only the first.
  Checks:
  - `schema = "axiom.provider/1"` and the id format;
  - unique tool and task ids;
  - bare `program` names;
  - `version_regex` compiles with exactly one capture group;
  - templates use only `${version}`, `${root}` and `${workspace}`, in task commands, artifact and
    checksum URLs, JSON version URLs, delegate argv and env values;
  - archive artifacts carry 64-hex digests or a checksum URL;
  - `bin_dirs` stay inside the root;
  - a delegate's `using` is one of the tools;
  - `process` is rejected ("not supported yet", ADR-0014 §5).

  serde errors are flattened to one line.
- **`registry`: `Registry::load(&Sources)`.**
  - **Sources:** built-in (`Builtin::Embedded`, compiled in, or `Builtin::Dir` for tests), user
    (`<data dir>/providers`) and workspace (`<ws>/.axiom/providers`, with a trust flag).
  - **Overrides:** later sources override earlier ones by id, and only valid, trusted entries
    count, so an invalid user manifest never shadows a valid built-in.
  - **Listing:** `infos()` gives `ProviderInfo` for every entry. Invalid ones carry `errors`;
    untrusted workspace ones have `trusted: false`.
- **`detect`:**
  - **Project:** `any_file` patterns (`*`/`?`) are matched against names in the root and its
    non-hidden first-level directories.
  - **Tool search order:** managed roots first, newest version first, then `PATH`. A managed root
    is `<data dir>/toolchains/<id>/<version>/<bin_dir>` using the archive methods' `bin_dirs`;
    dot-directories (staging) are ignored. On Windows, `.exe`, `.cmd` and `.bat` are tried.
  - **Version command:** run by absolute path with no shell, stdin null, `kill_on_drop` and a
    5 s timeout. The working directory is the system temp dir, so a project's
    `rust-toolchain.toml` cannot make rustup's proxy install a toolchain during detection. stdout
    is checked first, then stderr.
- **`axiom-store`:** migration 2 adds `workspace_trust(root, trusted_ms)`, with
  `workspace_trusted` and `set_workspace_trusted`. It is kept apart from `workspace_state`,
  which any client can write through `workspace/setState`.
- **`axiomd`:**
  - `handlers/env.rs`: `env/providers` (optional workspace), `env/detect` and `env/trust`. The
    registry loads in `spawn_blocking`.
  - `App::with_data_dir`: the data dir is the database's directory, so `--data-dir` and
    `AXIOM_DATA_DIR` now also place `providers/` and `toolchains/`. `App::new` derives it.
- **Tests:** `tests/common` gains `Daemon::spawn_configured`, used to control the daemon's `PATH`.

## Deviations and decisions
- **`Registry::load` takes a `Sources` struct**, not four positional arguments, and the built-in
  set is compiled in. The packaged app then needs no provider data files, and a test pins the
  embedded copies to `providers/*`.
- **`selectedVersion` is always absent for now.** Reading `.axiom/project.toml` is
  M2-ENV-004's, and doing it here would duplicate that parser.
- **Outside the declared scope:**
  - `crates/store`: the trust table. The spec's "per-workspace trust flag" needs it, and
    `workspace_state` is client-writable.
  - `crates/axiomd/tests/common/mod.rs`: `spawn_configured`.

## Found: a manifest gap for M2-ENV-003
A **delegate** method has no `bin_dirs`. For managed rustup installs the executables live in
`${root}/cargo/bin`, which the manifest cannot express, so detection finds managed delegate
installs only once that is added. Proposed for ENV-003: an optional `bin_dirs` on
`InstallMethod::Delegate`, additive to the frozen manifest through that task's spec. No field
was found to be unnecessary.
