# M1.6-SHELL-001: Split App.tsx into shell modules without visual change

## Objective
`App.tsx` (433 lines today: layout, menus, shortcuts, palette commands, title bar,
status bar) becomes a composition root under 120 lines, and its responsibilities move
to `src/shell/`. Pixels and behaviour stay identical. Every later SHELL, EDITOR and
SURFACES task then edits one small module instead of one shared file, so they can run
in parallel.

## Context
- `docs/design/frontend-architecture.md` §2 (target layout) and §7 (testing hooks).
- `apps/desktop-tauri/src/App.tsx`, the file being split.
- `docs/design/visual-qa.md` §2: the QA-001 harness gives the pixel baseline, if merged.

## Required interfaces
- Stores in `src/state/*` (unchanged); `host` and `listen` from `@tauri-apps/*` (only
  `shell/` and `daemon/` may import Tauri, per frontend-architecture.md §2).
- Existing `data-testid`s: `status`, `task-status`, `palette`, and those of the
  components. They must not change.
- The `axiom://menu` event contract with the native macOS menu (T-07) and
  `runMenuAction` ids: `open-folder`, `save`, `save-all`, `close-folder`, `settings`,
  `find`, `toggle-sidebar`, `toggle-panel`, `run-command`, `rerun`, `stop`, `about`.

## Implementation requirements
1. Create `src/shell/`:
   - `Workbench.tsx`: the side bar, splitters, main column, console host and layout
     state (`Layout`, `LAYOUT_KEY = "axiom.layout.v1"`, `loadLayout`), moved unchanged.
   - `TitleRow.tsx`: the header (brand, the five menus, workspace crumb, palette
     button, layout toggles, settings button).
   - `StatusBar.tsx`: the footer (daemon label, task status, cursor, encoding).
   - `shortcuts.ts`: `useAppShortcuts(ctx)` with the capture-phase key handler moved
     verbatim (same keys, same guards, `preventDefault` + `stopPropagation`).
   - `commands.ts`: `buildCommands(ctx): PaletteCommand[]` and
     `buildFileCommands(...)`, the existing lists in the same order with the same ids
     and enabled rules.
   - `actions.ts`: `runMenuAction(id, ctx)` and the `axiom://menu` listener hook.
   - `platform.ts`: `IS_MAC` and `MOD`, defined once.
2. `App.tsx` keeps only store subscriptions, theme/appearance effects, the crash
   recovery heartbeat, the quit flow, dialog state and composition. Under 120 lines
   (`wc -l`).
3. One `ShellContext` object (plain TS interface, no React context provider unless one
   is needed to avoid prop drilling deeper than two levels) carries `ready`, `hasDoc`,
   `ws`, `docs`, `task`, `prefs`, `dark` and the setters. No new state.
4. Inline styles in the moved JSX stay as they are (later tasks restyle).
5. No CSS change. No class name change. No DOM-order change (screenshots must match).

## Constraints
- Behaviour-preserving refactor only: no new feature, no renamed action, no new
  dependency. `src/state/`, `src/components/` and `src-tauri/` are out of scope.
- Governance rule 4: still no business logic in views.

## Non-goals
- No restyling, no token changes, no new components (SHELL-002 onward).
- No change to keyboard behaviour (EDITOR-002 adds region-focus shortcuts).

## Acceptance criteria
1. `App.tsx` < 120 lines; the six `shell/` modules exist with the responsibilities
   above.
2. Every keyboard shortcut of the old handler behaves identically (e2e smoke and
   parity suites pass unchanged).
3. Palette command list: same ids, labels, order and enabled rules (unit test).
4. Zero pixel difference for states S2, S4, S7, S9, S11 and S13 against the QA-001
   baseline (dark and light). Without QA-001, a before/after screenshot pair from
   `scripts/e2e.sh` is attached and reviewed.

## Tests
- `cd apps/desktop-tauri && pnpm run check && pnpm test`: green, with a new
  `tests/shell.test.ts` case `buildCommands matches the M1.5 command list` (snapshot of
  `{id, group, label, shortcut, enabled}` for three fixture contexts: not ready, ready
  without a workspace, workspace with a document and a running task).
- `apps/desktop-tauri/scripts/e2e.sh`: all suites (smoke, quit, geometry, parity) green.
- `scripts/check.sh`: green.

## Visual verification
States S2, S4, S7, S9, S11 and S13 (`docs/design/visual-qa.md` §4) in dark and light at
1440×900; the diff report shows 0 changed pixels. Fill in the §7 checklist with
"no visual change intended".

## Performance
No budget is expected to move. Run the bench `typing` and startup rows (P1, P2) once
before and once after, and paste both medians. A change of more than noise (±1 ms
typing, ±20 ms start) is investigated.

## Failure conditions
- Any pixel diff, or any e2e check changed or skipped to pass.
- A shortcut, menu item or palette command behaves differently.
- `App.tsx` still owns layout, menus, shortcuts or command lists.

## Documentation updates
- `docs/design/frontend-architecture.md` §2: mark the shell split as done; list any
  deviation from the module names.
- `docs/roadmap/current.md` (governance rule 10).

## Handoff
Line counts before and after per file; the diff report location; confirmation that
