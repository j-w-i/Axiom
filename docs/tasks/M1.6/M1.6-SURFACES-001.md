# M1.6-SURFACES-001: Command palette redesign

## Objective
The command palette (Ctrl/⌘+K commands, Ctrl/⌘+P files) matches
`docs/design/workspace-spec.md` §3: overlay material, a mode chip, grouped rows with
keycaps, a gliding selection, match highlighting in file mode, a footer of keys,
recent-first ordering, and designed empty states — with the existing keyboard model
and commands unchanged.

## Context
Spec: `workspace-spec.md` §3; motion: `motion-system.md` §4 row "Command palette";
material: `design-system.md` §4 (overlay = flat surface + one popover shadow). Reference:
`docs/design/concepts/r-palette-dark.png`, `r-files-dark.png`, and `Palette` in
`experiments/e5-visual-concepts/src/shared.tsx`. Current implementation:
`src/components/CommandPalette.tsx` (Radix Dialog, combobox + listbox, subsequence scorer).

## Required interfaces
- Command list from `src/shell/commands.ts` (moved there by SHELL-001; same ids/labels/shortcuts).
- `Kbd`/`Keys` (SYSTEM-003); Dialog presence and scrim (SYSTEM-004, INTERACTION-003 keyframes).
- Quick open lists only files the explorer has listed (`workspace.visibleRows()`): unchanged
  (workspace-wide index is M4).

## Implementation requirements
1. Position: top 12% of the window, width `min(600px, 100% − 32px)`; scrim `--scrim`, no blur.
2. Input row 44 px: search icon (muted), input at `--text-title` (15 px), mode chip right
   ("Commands" / "Files", `--text-tiny`, muted). The input draws no focus outline (the palette
   owns focus indication).
3. Rows 32 px, list padding 4 px, max height 340 px: commands = group (60 px, faint, 12 px) ·
   label · keycaps right-aligned (platform `⌘`/`Ctrl`); files = glyph chip · name ·
   directory (faint, 12 px) with the matched span in `--accent-text` 600.
4. Selection: one `.palette__glide` element, `transform: translateY(calc(var(--sel) * 32px))`,
   transition `--dur-1` `--ease-out`, background `--selected`, `inset 2px 0 0 var(--accent)`.
   `aria-selected` on the option remains the source of truth; mouse move selects.
5. Footer 30 px on `--surface-chrome` with a top seam: `↑↓ move`, `↵ run`, `Esc close`, and
   "Ctrl P for files" / "Ctrl K for commands" right-aligned.
6. Ordering: with an empty query, recent commands first (shell-local MRU, max 8, key
   `axiom.palette.mru.v1` in `localStorage`), then the existing order. Filtering keeps the existing scorer.
7. Empty states: no match → "No matching commands" + faint "Try fewer letters"; files mode without a
   workspace → "Open a folder to search files" and an "Open Folder…" row that runs the existing action.
8. Motion: scrim fade `--dur-2`; panel pop-in/out (INTERACTION-003 keyframes); command runs after
   close starts (existing `setTimeout(c.run, 0)`).
9. Accessibility unchanged or better: combobox + listbox + `aria-activedescendant`, Tab trapped,
   Escape closes and returns focus, group read as part of the option's accessible name.

## Constraints
- No new commands that have no M1 action (no placeholder UI); no agent "ask" mode.
- Tokens only; no new dependency.

## Non-goals
- Workspace-wide fuzzy file index (M4), symbol search, agent prompts.

## Acceptance criteria
1. Both modes look like the reference screenshots (deviations listed in the handoff).
2. Keyboard: ↑/↓, Enter, Escape, typing, Tab trap all work as before; MRU ordering works across restart.
3. Empty states render as specified.
4. Key → first painted palette frame ≤ 1 frame; filtering 5,000 listed files ≤ 8 ms per keystroke (P6).
5. Existing palette e2e checks pass; `scripts/check.sh` green.

## Tests
- Vitest `tests/palette.test.ts`: `mru puts recent commands first`, `file match highlight span`,
  `empty state without workspace offers open folder`, `filter 5000 entries under 8 ms` (perf assertion with margin).
- e2e `smoke.mjs`: existing palette checks, plus `palette glide follows arrow keys`.
- `pnpm test`, `pnpm run check`, `scripts/e2e.sh`, `scripts/check.sh`.
