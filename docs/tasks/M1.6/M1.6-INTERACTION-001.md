# M1.6-INTERACTION-001: Motion foundation: presence, loop gate, motion level setting

## Objective
The shell has one motion foundation that every later motion task uses: the motion
level (`standard` / `reduced` / `off`) read from the `appearance.motion` setting and
from the OS, a presence helper for enter/exit transitions, a loop gate that pauses
looping indicators when the window is hidden or unfocused, and stepped loop CSS.
No visible surface changes yet, except that existing loops (the spinner) become
stepped and pause when idle.

## Context
Spec: `docs/design/motion-system.md` §2 (tokens and setting), §3 (rules), §5 (looping
policy), §6 (reduced motion). Reference implementation: `usePresence` in
`experiments/e5-visual-concepts/src/shared.tsx` and the presence keyframes in
`experiments/e5-visual-concepts/src/base.css`. Measured reason for the looping
policy: `docs/design/concepts.md` §4 (18% → 4.4% of a core in software raster).
Decision D5 (`concepts.md` §6) adds the setting.

## Required interfaces
- Motion tokens defined by M1.6-SYSTEM-001 in `src/styles/tokens.css`
  (`--dur-press`, `--dur-1..3`, `--travel`, `--ease-out`, `--ease-in`, `--ease-in-out`).
- Settings: `settings/get`/`settings/set` (IPC 0.1, frozen). Unknown keys are
  stored and returned unchanged (`docs/protocols/ipc.md` §Settings (known keys)),
  so `appearance.motion` needs **no protocol or daemon change**.
- `src/state/settings.ts` key map (`appearance.theme` → `theme` …): add one entry.

## Implementation requirements
1. `src/state/settings.ts`: map `appearance.motion` → `motion: "standard" | "reduced" | "off"`,
   default `"standard"` when absent; any other stored value reads as `"standard"`.
   Only the read mapping and the typed snapshot field are added (writing goes through
   the existing `setValue`).
2. `src/ui/motion.ts` (no imports from `state/`, `shell/`, `components/`, `@tauri-apps/*`):
   - `resolveMotion(setting, prefersReduced): "standard" | "reduced" | "off"`:
     the OS reduced-motion preference forces at least `reduced` (`off` stays `off`).
   - `applyMotion(level)`: sets `document.documentElement.dataset.motion`.
   - `usePresence(open: boolean, exitMs: number): { mounted: boolean; phase: "in" | "out" }`:
     mounted while open and for `exitMs` after closing; `exitMs` treated as 0 when the
     level is `reduced`/`off`; re-opening during exit returns `phase: "in"` immediately.
   - `startLoopGate()`: on `visibilitychange` (hidden) and window `blur` sets
     `data-idle="true"` on `<html>`; on `focus`/visible removes it. Returns a disposer.
3. `App.tsx` (or `shell/` once SHELL-001 lands; one call site) calls
   `applyMotion(resolveMotion(prefs.motion, matchMedia("(prefers-reduced-motion: reduce)").matches))`
   whenever either input changes, and `startLoopGate()` once.
4. `src/styles/base.css` motion switches:
   - `[data-motion="reduced"]`: `--travel: 0px; --dur-2: 80ms; --dur-3: 80ms` (fades only);
     `[data-motion="off"]`: all `--dur-*` = `0ms`, `--travel: 0px`.
   - Loops: `.spinner` → `animation: spin .8s steps(8) infinite`; LED run pulse
     (`.led[data-state="run"]`) → `animation: led-pulse 1.6s steps(6) infinite`
     (`50% { opacity: .45 }`); caret blinks `1s steps(1)`.
   - `[data-motion="reduced"], [data-motion="off"]`: loops `animation: none`.
   - `[data-idle="true"] *`: `animation-play-state: paused`.
   - Presence keyframes `in-left/out-left/in-right/out-right/in-up/out-up/pop-in/pop-out/fade-in/fade-out/toast-in`
     exactly as in the prototype's `base.css`, using the motion tokens; entrances use
     `--dur-2 --ease-out`, exits `--dur-1 --ease-in`.
5. `window.__axiomMotion = { level, running: () => document.getAnimations().length }`
   is defined only in dev and `e2e` builds (`import.meta.env.DEV || import.meta.env.MODE === "e2e"`).
6. No animation of layout properties anywhere (motion-system §3.1); no `will-change` in CSS
   (the presence helper may set it during an animation only).

## Constraints
- IPC 0.1 frozen: no new method, no daemon edit, no change to `crates/`.
- No JS animation library; CSS animations keyed by `data-phase` only.
- Tokens only (guard test).

## Non-goals
- The Settings UI control for motion (M1.6-SURFACES-002).
- Panel, tab or overlay motion (INTERACTION-002/003).
- New loops of any kind.

## Acceptance criteria
1. With `appearance.motion` unset, `<html data-motion="standard">`; set to `"off"` via
   `settings.setValue`, it becomes `off` without restart; the OS reduced-motion
   preference turns `standard` into `reduced`.
2. The value persists across restart (stored by the daemon as an unknown key).
3. The spinner and the LED pulse are stepped (`steps(8)`, `steps(6)`) in computed styles.
4. With the window blurred, running animations report `playState === "paused"`.
5. With motion `off` and the app idle (task running), `document.getAnimations()` is empty.
6. All existing Vitest and e2e checks pass; `scripts/check.sh` green.

## Tests
- `cd apps/desktop-tauri && pnpm test` — new `tests/motion.test.ts`:
  `resolveMotion OS preference forces reduced`, `resolveMotion off stays off`,
  `settings maps appearance.motion with standard default`,
  `usePresence keeps mounted for exitMs then unmounts`, `usePresence reopen during exit`.
- New e2e check in `e2e/smoke.mjs`: `motion off leaves no running animations`
  (set the key, start `sleep 5`, assert `__axiomMotion.running() === 0`), and
  `blur pauses loops` (embedded driver may skip blur only with a logged reason).
- `pnpm run check`, `scripts/check.sh`.

## Failure conditions

- A loop still animates while `data-motion="off"` or `data-idle="true"`.
- A test skipped or weakened.
