# M1-CI-002: Desktop CI on three OSes and milestone exit

## Objective
CI builds and smoke-tests the whole application on Linux, macOS and Windows,
and Milestone 1 is closed with a recorded end-to-end verification.

## Context
Read: `docs/research/qt-rust.md` §CI and deployment findings,
`docs/contributing/dev-setup.md`, `docs/roadmap/milestones.md` §M1 exit
criteria.

## Implementation requirements
1. CI job `desktop` with matrix `ubuntu-latest`, `macos-latest`,
   `windows-latest`:
   - Rust toolchain + cache; Node 22 + pnpm; build `axiomd`; build
     `editor/dist`.
   - Qt 6.12.x with `jurplel/install-qt-action` (modules `qtwebengine
     qtwebchannel qtwebsockets qtpositioning`; Windows arch
     `win64_msvc2022_64`); Ninja; MSVC dev environment on Windows.
   - Linux packages for GL/xkbcommon headers and the WebEngine runtime
     libraries reported missing by `ldd`.
   - Configure, build, `ctest --output-on-failure` with
     `QT_QPA_PLATFORM=offscreen` (and `QTWEBENGINE_DISABLE_SANDBOX=1` on
     Linux CI only, with a comment explaining why).
   - Upload test logs and any grabbed screenshots as artifacts on failure.
2. Make the shell tests portable: replace unix-only commands in
   `tst_*` with a tiny cross-platform helper where needed (e.g. a
   `tests/helpers/emit` Rust binary in the workspace that prints given text
   to stdout/stderr, sleeps, and exits with a given code) and remove the
   `QSKIP`s introduced by M1-SHELL-004.
3. `scripts/smoke.sh`: one command that builds everything and runs the
   desktop smoke tests locally (thin wrapper over `check.sh desktop`).
4. M1 exit verification: run the nine-point scenario from
   `docs/roadmap/milestones.md` §M1 on at least one OS with a real display
   if available (otherwise offscreen), and record the result in
   `docs/roadmap/verification/M1.md`: date, OS, Qt version, each point with
   pass/fail and the evidence (test name or manual observation), and a
   per-OS table stating what CI verified.
5. Update `docs/roadmap/current.md` to point at M2 and at its first task
   ("freeze the provider contract and write M2 task files").

## Constraints
Do not weaken tests to get a platform green. A platform-specific failure
that cannot be fixed within this task is recorded as a known defect with
the failing test left enabled-but-allowed-to-fail **only** via an explicit
`continue-on-error` on that single matrix entry, with an issue reference in
the workflow file and in `docs/roadmap/current.md`.

## Acceptance criteria
- CI is green on Linux; macOS and Windows are green or have explicitly
  recorded, individually justified exceptions as above.
- `docs/roadmap/verification/M1.md` exists and is truthful.

## Tests
`scripts/check.sh`; the CI run URL(s) in the report (if the repository has
no remote/CI yet, say so and record local results only).

## Failure conditions
No CI is available (no remote): complete items 2–5 locally, mark the
cross-platform parts "unverified" in `verification/M1.md`, and leave this
task at `implemented`, not `tested`.

## Documentation updates
As listed in items 4–5; `AGENTS.md` status section.

## Handoff
Known platform defects with reproduction notes.
