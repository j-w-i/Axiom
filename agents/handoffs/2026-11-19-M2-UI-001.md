## Deviations and decisions
- **One commit for UI-001 and UI-002.** The page's primary action is UI-002's dialog.
- **The side bar for Environments** is a summary list (one row per toolchain, moving focus to
  its row on the page), so the side bar shows the active destination with real content.
- **Rust's real install is not exercised in smoke.** It would need the network and minutes.
  Smoke uses two fixture providers (single-file "toolchains" served by a loopback HTTP server,
  `AXIOM_TEST_INSECURE_LOOPBACK_HTTP=1`). The real Rust install is covered by M2-ENV-003's CI
  test.
- **Shots S18b, S18c and S18d set the store's own state from the harness**, as S1b does with
  `opening`: an install's mid-progress and failure moments cannot be held still otherwise.
- **Fixes found while verifying (shots review):**
  - an empty dialog showed during the exit animation, because the plan and remove dialogs now
    keep their last content while closing;
  - a wide table pushed the whole window past the viewport, because of fixed table layout and
    `min-width: 0`;
  - the step list scrolled the dialog's title away, so the steps now scroll between the title
    and the buttons;
  - the failure reason was clipped, so it now gets two lines.

## Found and fixed: a lost click into the editor
- **Symptom:** with detection running on every workspace open, smoke failed intermittently
  (3 of 5 runs, both drivers) at "dirty tab". A click into Monaco did not take focus, and the
  typed text reached the console prompt. a11y check 2 failed the same way (no focus ring
  anywhere).
- **Bisect:**
  - the base commit passes 58/58 twice;
  - with no detection on open it passes 63/63 twice;
  - with detection on open but no badge subscription, the typing step passes twice.

  So the cause is the workbench re-rendering when the badge count arrives.
- **Fix:** the count is subscribed inside `Rail` (only the rail re-renders). After the fix:
  smoke 63/63 twice and a11y 27/27.
- **Not found:** the exact mechanism inside the workbench re-render. Anything else that
  re-renders the workbench at the moment of a click could do the same; this is worth a look
  in QA-001 if it reappears.
