## Behaviour implemented
- **`providers/node/provider.toml`:**
  - **Artifacts:** Linux x64/arm64 `tar.xz`, macOS arm64/x64 `tar.gz`, Windows x64/arm64
    `zip`; all `strip_components = 1`, all `sha256_url` to `SHASUMS256.txt`.
  - **`bin_dirs = ["bin", "."]`:** `bin/` on Unix, the root on Windows.
  - Comments explain the layout and why npm is optional.
- **`VersionSource::Json` gains an optional `strip_prefix`** (additive; nodejs.org writes
  `v22.11.0`). Versions without the prefix are dropped. Schemas and `protocol.gen.ts` are
  regenerated.
- **Pre-releases are no longer offered by any version source:** a version with a `-` is dropped.
  nodejs.org's index includes `27.0.0-alpha.*`, which sorted first and would have been the
  default install.
- **Built-in registration:** `BUILTIN` (`crates/env/src/registry.rs`), so the contract test's
  "embedded == providers/*" covers it.
- **`ci_install.rs`:** `node_managed_install_roundtrip` (versions → plan → install → resolve a
  project selecting it and run `node` from the environment → uninstall).

## Deviations and decisions
- **npm is not required.** It is a Node script, so it runs only with `node` on `PATH`. That is
  true when tasks run in the project environment, but not for the daemon's own detection inside
  a managed root.
- **On Windows, `npm` tasks start `npm` by name.** Rust's process spawning resolves only `.exe`,
  so `npm.cmd` would not be found. Windows was deferred by the owner; this is noted for QA-001.
- **One additive manifest field (`strip_prefix`)**, recorded here and in the schema.
