# M1.6-QA-001: Real-app screenshot harness and pre-redesign visual baseline

## Objective
A repeatable command captures the production shell (Tauri + WebKitGTK on Linux) in
every required state of `docs/design/visual-qa.md` §4, in both themes, at fixed
size and scale, and compares two runs pixel by pixel. Its first run is the
**pre-redesign baseline** that every M1.6 restyle task compares against.

## Context
`docs/design/visual-qa.md` §1–§4 (principles, harness, gallery, states). The e2e
harness already drives the real app through two WebDriver servers
(`apps/desktop-tauri/e2e/webdriver.mjs`, `runner.mjs`, `scripts/e2e.sh`) and runs
under `scripts/headless.sh` on Linux. Reuse it; do not add a browser automation
dependency.

## Required interfaces
- `e2e/webdriver.mjs` (W3C `takeScreenshot`, actions, execute script), `e2e/runner.mjs`.
- `scripts/e2e.sh` argument handling (suites are `.mjs` names).
- The settings keys `appearance.theme` and (once INTERACTION-001 exists)
  `appearance.motion`; until then, animations are disabled by injected CSS.
- `AXIOM_DATA_DIR` for an isolated profile (AGENTS.md: never the user's profile).

## Implementation requirements
1. Add `tests/fixtures/visual/`: a committed snapshot of real Axiom files (copies of
   `crates/exec/src/{executor.rs,lib.rs,tree.rs,backend.rs,error.rs,utf8.rs}`,
   `crates/exec/Cargo.toml`, a `README.md`, `docs/ipc.md` copied from
   `docs/protocols/ipc.md`, a `.gitignore` listing `target/`, and an empty
   `target/.keep`). Total < 200 kB.
2. Add `e2e/shots.mjs`: a suite runnable as `scripts/e2e.sh shots.mjs`, which copies
   the fixture to a temp directory, launches the app at a 1440×900 window, and for
   each state S1–S17 (including S1b–S1d) of `visual-qa.md` §4 that the **current** shell can show (the
   hint line S16 and the focused-region rule appear only after their tasks; mark
   them `pending` in the manifest), drives it, waits for `document.fonts.ready` plus
   two animation frames, and saves
   `e2e/shots/<os>/<state>-<theme>.png`.
3. Determinism: inject `*{animation:none!important;transition:none!important;caret-color:transparent!important}`
   via execute-script before each capture; a long-running task for S5 uses
   `sleep 30`, and its elapsed text is replaced by a fixed string through a
   test-only hook `window.__axiomFreezeClock = "00:12.4"` (read by the view if
   present; added to `e2e/` probe only, not product code: if the current UI has no
   elapsed display, skip it).
4. Both themes via `settings/set appearance.theme` before each pass. A 200% pass
   (S4 only) uses `GDK_SCALE=2` on Linux.
5. Write `e2e/shots/<os>/manifest.json`: app commit, OS, engine version
   (`navigator.userAgent`), scale, window size, state list and status per state.
6. `node e2e/shots-compare.mjs <dirA> <dirB> [--threshold 0.001]`: a dependency-free
   PNG decoder (zlib from `node:zlib`) plus a per-pixel diff with an anti-aliasing
   tolerance of 1 channel step; writes `diff/<state>.png` and `report.html`
   (before / after / diff side by side); exit code 1 when any state exceeds the
   threshold.
7. Add `e2e/shots/` to `.gitignore` except `e2e/shots/README.md`, which explains how
   to produce and compare sets.
8. Run it once on the unchanged shell: this is the **baseline** set, attached to
   the handoff (zip) and copied to `docs/roadmap/verification/M1.6/baseline/linux/`
   at 100% only.

## Constraints
- No product code change except reading the e2e-only freeze hook, and only if the
  view already shows elapsed time (today it does not: do not add it here).
- No new npm dependency (PNG handling via `node:zlib`).
- Never open a window on the developer's desktop: refuse to run without
  `headless.sh` on Linux (same guard as the other suites).

## Non-goals
- Restyling anything; macOS/Windows sets (QA-005); the component gallery (SYSTEM-003).

## Acceptance criteria
1. `scripts/e2e.sh shots.mjs` produces every available state in dark and light
   plus S4@2x, and the manifest lists pending states.
2. Two consecutive runs on the same commit compare with **0 states over threshold**.
3. A deliberate one-token change (e.g. `--bg` lightened) is detected in every
   state that shows that surface, and the HTML report shows it.
4. The baseline set is attached and committed at 100% in
   `docs/roadmap/verification/M1.6/baseline/linux/`.
5. All existing suites (smoke, quit, geometry, parity) still pass.

## Tests
- `apps/desktop-tauri/scripts/e2e.sh shots.mjs` (under `headless.sh`).
- `node apps/desktop-tauri/e2e/shots-compare.mjs runA runB` → exit 0; after the
  token change → exit 1 with named states.
- New Vitest case `tests/shots-compare.test.ts`: "identical images report 0 changed
  pixels", "one changed pixel is counted", "anti-aliasing tolerance ignores ±1".
- `scripts/check.sh` green.

## Visual verification
The baseline set itself is reviewed against `visual-qa.md` §5 only for capture
defects (wrong state, half-loaded fonts, a cursor visible), not for design.

## Performance
None (capture runs are not benchmarks).

## Failure conditions
- Non-deterministic output (consecutive runs differ) that is papered over by raising
  the threshold above 0.1%.
- Screenshots taken from a dev server in a browser instead of the real app.

## Documentation updates
`docs/design/visual-qa.md` §2 (any difference between the spec and the built
harness), `apps/desktop-tauri/README.md` (one line: how to take shots).

## Handoff
The state list with status, engine version, run time, the location of the baseline
set, and any state that could not be captured and why.
