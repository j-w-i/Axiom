# M4-GIT-002: Git in the UI

## Objective
Git state is visible and diffable (ADR-0018 §5): status letters and colours on explorer rows and
tabs (fixed semantic slots), gutter markers (added / modified / deleted) against HEAD text, Monaco's
diff editor (HEAD ↔ working copy, read-only left side) opened from a Source Control side-bar page,
the explorer context menu and the chat diff block's "Open in diff editor"; the branch (and
ahead/behind) in the status bar.

## Implementation requirements
1. Source Control rail destination (or side-bar page) listing changes grouped Staged / Changes /
   Untracked, keyboard navigable (Enter opens the diff, Shift+Enter the file).
2. Gutter markers recomputed on edit (debounced, off the keystroke path) from the HEAD text, cached
   per path until `git/didChange`.
3. Diff tab is a tab kind in the strip ("main.rs (Working Tree)") and survives restart like files.
4. Colours from tokens; letters as text (not colour alone) for accessibility.

## Acceptance criteria
1. e2e `git.mjs` on a temp repository: edit a file → explorer shows M and the gutter marker;
   Source Control lists it; Enter opens the diff editor with the change; a new file shows U;
   the branch shows in the status bar; committing outside the app clears the markers.
2. a11y scan of Source Control and the diff tab in both themes.

## Tests
`pnpm test`; `scripts/e2e.sh git.mjs`.

## Failure conditions
Gutter computation on the keystroke path; status shown by colour only.
