# M3 verification — Agent runtime

_Written 2026-11-22 by the implementing session (M3-QA-001). It records what was run, where, and
what was not._

## Exit criterion (milestones.md §M3)
> With a scripted provider in CI and a real local model manually: "add a function and fix the
> build" completes through tools only; every write was preceded by a checkpoint and can be
> restored; denied operations do not execute; the session resumes after restart; an external MCP
> client can list and call tools subject to the same policy; Claude Code / Codex run inside Axiom
> through ACP under the same gate (ADR-0016); with no folder open, a person can configure a model
> and hold a first-rate conversation in Chat entirely by keyboard (ADR-0017).

### The scenario, end to end: `apps/desktop-tauri/e2e/agent.mjs`
The real app, the real daemon and real cargo. The "agent" side is either the scripted model
(`AXIOM_TEST_SCRIPTED_MODEL`), a fake OpenAI-compatible server on loopback (which drives the real
OpenAI adapter), or the in-repo fake ACP agent and fake MCP server (`tests/helpers/`).

Opening the folder uses the store's own request, because the native dialog cannot be driven (as in
smoke). In the folder part, the policy is the default (reads allowed, everything else asks) plus
one user rule, `cargo build` allowed, which is set through `agent/setPolicy` as Settings would.

**Defect found here and fixed:** after the first-run setup the focused button unmounts, and focus

when it becomes usable and nothing else has focus (`Composer` in `components/Chat.tsx`). Step 0b
fails closed on it: it waits for the focused composer and types without clicking.

### The MCP server for external clients (`axiom mcp`)
`apps/cli/tests/mcp.rs` `mcp_lists_and_calls_tools_under_the_same_policy`: an MCP client
(`axiom mcp` over stdio, as Claude Code starts it) initializes (2025-06-18; an unknown revision
gets 2025-06-18), lists the tools and calls them. A write asks the connected "Axiom window" (the
daemon's stdio client with approvals), which approves once, and it runs: the same gate. The
MCP *client* (Axiom using configured servers) is `crates/axiomd/tests/agent_sessions.rs`
`agent_uses_the_tools_of_a_configured_mcp_server`. Both run in every CI Rust job (Linux, macOS,
Windows) as part of `cargo test --workspace`.

### ACP under the gate
`crates/axiomd/tests/agent_acp.rs` covers the protocol side against fake-acp:
- fs reads and writes, terminals, and permission prompts asked once;
- a write without permission refused;
- reads outside the workspace refused;
- cancel;
- Axiom's MCP offered to the agent.

The UI side is step 7 above.
