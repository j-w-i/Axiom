## Behaviour implemented
- `WorkspaceController` (`workspace` in QML): `open/opening/name/root/id`, `recent` (RecentModel), `tree` (FileTreeModel); `openFolder(path)`, `openFolderUrl`, `close()`, `refreshRecent()`, `reopenLast()`. Open sequence: `workspace/open` → `fs/watch` → `workspace/getState` (`explorer.expanded`) → root `fs/list`; `opened` is emitted when the first listing arrived (or failed). Opening another workspace first saves state and closes the old one. A daemon that fails or restarts drops the open workspace (a new process knows none). Errors → `errorOccurred(message)` (shown in a warning `AxBanner` with Dismiss).
- `FileTreeModel`: roles name/path/kind/ignored/expanded/loading; lazy `fs/list` via `canFetchMore`/`fetchMore` and `setExpanded`; per-directory epoch guard so answers for a closed workspace are ignored; failure of a child listing becomes an inline `error` row; `fs/didChange` → re-list the root and expanded+loaded directories that are parents of changed paths (all when a change has `path: ""`), applied as a minimal remove/insert diff (rows kept → expansion and selection survive; a change arriving while a listing is in flight queues one more listing); collapsed directories are re-listed on next expand.
- State: `explorer.expanded` saved with `workspace/setState` debounced 500 ms, flushed on close and on shell destruction (bounded 1.5 s wait); restored on open (`expandRequested` makes the view expand them).
- QML: `ExplorerView` (TreeView; Up/Down from TreeView, Right expands/moves to first child, Left collapses/goes to parent, Home/End, Enter toggles a directory or emits `fileActivated(path)`, double click on a file too), `AxListRow` (chevron, muted ignored entries, error rows in danger colour, tooltip for truncated names, accessible names incl. expanded/collapsed), `WelcomeView` (Open Folder… primary button; recent list only when non-empty; click opens), File menu: Open Folder… (Ctrl+O via `StandardKey.Open`, `FolderDialog`), Open Recent submenu, Close Folder; title `<name> — Axiom`.
- Startup: once per launch when the daemon becomes Ready, `reopenLast()` reads `workspace.reopenLast` and `workspace.lastRoot` via `settings/get`.

## Qt TreeView notes / workarounds
- A directory with no children cannot hold "expanded" in Qt's `TreeView` adapter (`isExpanded` is true but the model sees no state), so the *model's* expanded set follows the TreeView's `expanded`/`collapsed` signals (single source of truth for mouse, keyboard and programmatic expansion) rather than delegate bindings. An empty directory (like `docs` in the smoke test) therefore toggles visually but only counts as expanded in the model once the tree reports it; not an issue for the expansion-restore feature. No Qt bug link known.
- `TableView.SelectRows` + `selectionModel` is needed for a visible current row; Home/End and Left→parent are implemented in `Keys.onPressed` because TreeView has no built-in for them.
- Delegate rows use `focusPolicy: NoFocus`; the TreeView is the single tab stop.

## Deviations and decisions
- `opened` is emitted after the first root listing, not directly after `workspace/open`.
- Explorer state is saved by the controller from the model's `expandedPathsChanged`.
- Added `RecentModel` and a `FileTreeModel::isFile` helper; added an "error" kind for inline error rows (not a protocol kind).
- The warning banner for workspace errors is dismissible; it clears on the next successful open.

## Known defects / limitations
- Expansion of a directory restored by state may briefly show collapsed rows before its children arrive.
- The model keeps expanded-but-collapsed-parent directories' state but does not refresh them until visible.
