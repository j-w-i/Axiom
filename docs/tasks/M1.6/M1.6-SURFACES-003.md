# M1.6-SURFACES-003: Light theme pass and native title-bar theme sync

## Objective
The light theme ("Aluminium") is as carefully finished as the dark one on every M1.6
surface (D10), every contrast pair meets `docs/design/design-system.md` §2.3 (including
light warning text ≥ 4.5:1, up from the prototype's 4.0:1), and on Windows and Linux the
native title bar follows the app theme (D3).

## Context
`design-system.md` §2.1 (light `ember` darkened to `#a8520f`), §2.2 light column, §2.3 contrast table,
§3 generator; `concepts.md` §6 D3 and D10; `frontend-architecture.md` §6 (window chrome,
`core:window:allow-set-theme`). Reference: `docs/design/concepts/r-workspace-light.png`,
`r-components-light.png`.

## Required interfaces
- `src/styles/themes.json` + `scripts/gen-themes.mjs` (SYSTEM-001); guard test `tests/tokens.test.ts`.
- All restyled surfaces from SHELL-003…007, EDITOR-001, SURFACES-001/002.
- Tauri `Window.setTheme` (`@tauri-apps/api/window`), capability `core:window:allow-set-theme`.

## Implementation requirements
1. Light theme inputs in `themes.json` produce the §2.2 light values (ΔE2000 < 2 vs the prototype)
   with these corrections: `--warn` light `#a8520f` (≥ 4.5:1 on `--surface-editor` and
   `--surface-panel`); `--text-faint` ≥ 3:1 on both; brass text `#85601c`.
2. Light-specific recipes that cannot come from tokens alone are fixed in component CSS through
   tokens only: raised controls' inset shadow `rgb(0 0 0 / .14)` (via a `--press-shadow` token),
   pressed toggles, the recessed well shadow; no literal colours outside `tokens.css`.
3. Go through visual-qa §4 states S1–S17 in light and fix every deviation from the references
   or from §5 of the checklist, in CSS/tokens only.
4. Monaco light theme (`axiom-light`): syntax tokens per `design-system.md` §2.2 light column
   (generated by EDITOR-002's generator from `--syn-*`), checked on `r-workspace-light.png`.
5. **Title-bar sync (D3, Windows/Linux only)**: when the resolved theme changes, call
   `getCurrentWindow().setTheme(theme === "system" ? null : theme)`; add
   `core:window:allow-set-theme` to `src-tauri/capabilities/main.json` and record the
   capability in `docs/architecture/security.md` §Host commands/capabilities. If D3 is rejected
   or a custom frame is chosen, skip this requirement and record why. On macOS the overlay title
   bar from SHELL-003 needs no call.
6. Extend `tests/tokens.test.ts` with the full §2.3 matrix for light (text on editor, panel, chrome,
   overlay ≥ 7:1; muted ≥ 4.5:1; faint ≥ 3:1; state texts ≥ 4.5:1; on-accent ≥ 4.5:1; focus ≥ 3:1).

## Constraints
- No new host command; the capability is the only `src-tauri/` change.
- Dark theme values unchanged by this task (the generator's dark output must stay byte-identical).

## Non-goals
- High-contrast themes (forced colours handled in QA-003), user theming.

## Acceptance criteria
1. Guard test passes the full light matrix; light warning text ≥ 4.5:1.
2. S1–S17 light screenshots reviewed with the §5 checklist; no open deviations (or each accepted by the owner).
3. Windows/Linux native title bar switches with the theme setting (Linux verified; Windows
   "unverified on Windows" until QA-005).
4. Dark screenshots unchanged (diff = 0 changed pixels except where a light-only fix touched shared CSS, explained).
5. `scripts/check.sh` green; existing suites green.

## Tests
- `pnpm test` (`tokens.test.ts` new cases: `light contrast matrix`, `dark generator output unchanged`).
- e2e `smoke.mjs`: `theme switch calls setTheme` (Linux, via the e2e build's host log).
- `apps/desktop-tauri/src-tauri` `cargo test` (capability surface test, if it enumerates permissions).
- `scripts/check.sh`.

## Visual verification
All states S1–S17 in light at 100%, S4/S7 at 200%; compare with `r-*-light.png`. The §7 checklist
applies, with the diff report vs the dark-only baseline.

## Performance
None on budgeted paths; confirm P2 unchanged (theme switch adds no startup work).

## Failure conditions
- A literal colour added outside `tokens.css`; dark output changed; any §2.3 pair failing.

## Documentation updates
`docs/architecture/security.md` (capability); `docs/design/design-system.md` §2.1 only if the
generated values differ from the table (record the new values); `docs/roadmap/current.md`.

## Handoff
Before/after contrast table for light; screenshot set; capability diff; Linux verified,
macOS/Windows "unverified on <OS>".
