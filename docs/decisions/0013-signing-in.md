# 0013 Signing in with ChatGPT, and the one listener
**Decision.** Axiom's own loop can run on a ChatGPT plan, by the sign-in OpenAI documents for open-source programs on a person's own computer (`research/subscription-auth.md` §3): registered for each account by the sign-in itself, no secret, the public Responses API. SI-20 gets one exception for it: while a sign-in waits for its person, and no longer than ten minutes, the host listens on `127.0.0.1` at a port the system chooses.
**Why a listener.** The documentation knows no other way back: no device code, no scheme of one's own, only an http address on literal `127.0.0.1`.
**How narrow.** One path, `GET`, `HTTP/1.1`, the exact `Host`; at most 16 KiB of head and 5 s for it; 16 connections at once. A request counts only with the sign-in's `state` (32 random bytes, compared in constant time), once; anything else is answered 404 and empty and changes nothing. The code it brings is worth nothing without the verifier (PKCE S256), which never leaves the host. The identity is checked (RS256 against OpenAI's keys, issuer, audience, time, nonce), and that it is the same person when signing in again. The page it answers has no script and nothing of the request in it. It closes before the code is traded.
**What is kept.** In the system's store what renews (another each time; kept before what it gave is used); in memory the access token; in a file the registration, who it is for, and a random name for this installation. The identity token is not kept. Removing an account ends it at OpenAI first, and says so if that is not certain.
**Who opens the browser.** The client, on its person's press, and only OpenAI's two addresses. The host opens nothing.
**Never.** OpenAI's private endpoints; another program's login; another way to pay when the plan's limit is reached, or another account.
**Considered.** Codex with this token: another program's loop, not Axiom's. Codex's own login: only for Codex itself.
**Risk.** A preview: it may change or end (K47). Another program of the same person could take the port after it is closed, or answer in the browser's stead: it would have neither state nor verifier.
**Revisit.** When OpenAI documents a way without a listener, or if Axiom is ever paid or hosted: then plan use needs OpenAI's agreement.
