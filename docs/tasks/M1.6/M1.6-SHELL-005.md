# M1.6-SHELL-005: Status bar and hint line

## Objective
A 24 px status bar of hairline-separated segments (backend, task, **hint line**,
cursor, encoding, EOL, language), and the hint mechanism adapted from FL Studio's hint
bar: the hovered or focused control's `data-hint` ("Action — Shortcut") is shown in
the status bar, with the shortcut rendered as keycaps.

## Context
- `docs/design/workspace-spec.md` §2.5 (segment table: the spec of record).
- `docs/design/research.md` §1.5, §9.1 principle 1 (hint channel).
- `docs/design/design-system.md` §9 (`StatusBar`, `HintLine`); `motion-system.md` §5.3
  (one animated "running" indicator).
- Prototype: `experiments/e5-visual-concepts/src/shared.tsx` (`useHint`),
  `src/concepts/a.tsx` (`HintText`), `src/concepts/r.css` (`.r-hint*`).

## Required interfaces
- `data-testid="status"` and `data-testid="task-status"` (e2e smoke) stay, with the
  same text content semantics.
- `DaemonClient` state, `TasksStore.statusText` / `running`, `DocumentsStore`
  `cursorText` and the active document's EOL and language (existing data only).

## Implementation requirements
1. `src/ui/hint.ts`:
   - `useHint(rootRef, idle = "")` listens for `pointerover` and `focusin` on the
     window root, finds the closest `[data-hint]` and returns its text;
   - `parseHint("Rerun the last command — F5")` returns `{ what, keys[] }`, where
     keys are split on `+`/space only if every token is a key name (`Ctrl`, `Shift`,
     `Alt`, `⌘`, `F1`–`F12`, `Enter`, `Esc`, arrows, single characters);
   - `MOD` substitution, so hints are written once as `Mod+K` and render `Ctrl K` or
     `⌘ K`.
2. Every interactive element in the title row, the status bar, panel tools, splitters,
   tabs and the console prompt gets a `data-hint` (the text table in the PR: e.g.
   splitter "Drag to resize — double-click resets", Rerun "Rerun the last command —
   F5"). Monaco's text area has none (an empty hint while typing).
3. `StatusBar.tsx`: height `--status-h` 24, `--surface-chrome`, 1 px `--line` above;
   segments are `0 var(--s-2)` padded and separated by a 1 px `--line-mid`
   (`inset 1px 0 0`); 12 px `--text-muted`; interactive segments have a `--hover`
   background.
   - **Backend:** an LED (`on` when ready, stepped `run` while starting, `err` when
     stopped or failed) and "axiomd <version>" / "Connecting…" / "Backend stopped".
     It is a button when stopped (restart via `client.restart()`).
   - **Task:** while running, a spinner and the label; otherwise `statusText`
     (`statusbar__failed` styling becomes `--danger`). The spinner is static (no
     animation) while the title-row transport is visible. Click shows the console.
   - **Hint line** (flex 1): `what` in `--text-muted` and keycaps (`Kbd`, 10 px,
     14 px line) when present; empty when idle. `aria-live="off"`; the segment is not
     part of the `role="status"` region.
   - Cursor ("Ln 84, Col 17"), "UTF-8", EOL ("LF"/"CRLF" from the document) and
     language display name, shown only with an active document.
4. The `role="status"` and `aria-label` move to the backend and task segments only,
   so hint changes are never announced.
5. Styles in `styles/components/statusbar.css`, new tokens only.

## Constraints
- No output parsing (no "7/14 passed": that is M2 diagnostics).
- No new store data except reading the document's EOL, if `documents.ts` already
  exposes it. If it does not, show nothing (no store change in this task).

## Non-goals
- Capability glyphs in hints (research §1.5 "Adapt"; later); pending-chord display
  (no chords exist in M1); problem counts (M2).

## Acceptance criteria
1. Hovering Rerun shows "Rerun the last command [F5]" with keycaps; focusing it by
   keyboard shows the same; moving to the editor clears it.
2. Every element in requirement 2 has a hint (unit test over the rendered shell).
3. Screen reader: hovering controls produces no announcements; backend state changes
   are announced once.
4. Only one task indicator animates at a time (`document.getAnimations()` count while
   a task runs ≤ 1 in the status bar plus transport).

## Tests
- `pnpm test`: `tests/hint.test.ts` `parseHint splits key chords`, `MOD substitution
  per platform`, `non-key suffix stays text`.
- e2e smoke: existing `status` / `task-status` checks green; new
  `hint line follows hover and focus`.
- `scripts/check.sh` green.

## Performance
P7 (idle CPU, no task) is unchanged: the hint uses event listeners only, with no
polling. Check with the bench idle row before and after.

## Failure conditions
- Hint text announced by screen readers; a hint stuck after the pointer leaves; any
  segment showing invented data.
