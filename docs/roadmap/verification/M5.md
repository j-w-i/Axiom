# M5 verification — Visual intelligence (web)

_2026-11-22. Written by the implementing session (M5-QA-001)._

- **Linux:** Fedora 44 on KDE Wayland. The suites ran in a private virtual KWin; the page ran
  in headless Chrome with a throw-away profile.
- **macOS:** CI.
- **Windows:** owed (deferred by the owner).

## Exit criterion (milestones.md §M5)
> On the fixture app: click a button → correct source opens (exact line/column) → scripted agent
> applies a spacing fix → hot reload → report `verified` with a passing geometry check; a
> deliberately wrong patch yields `failed`; an element from an uninstrumented library is
> presented as uncertain, not exact.

### The scenario, end to end: `apps/desktop-flutter/integration_test/inspect_loop_test.dart`
One app session against the real daemon.
- **Fixture:** `tests/fixtures/inspect-react` (React 19, Vite 7, a library component without
  stamps).
- **The page:** in headless Chrome. The test clicks in it the way a person would, with mouse
  events sent over Chrome's debugging port. That is the test's hand only: the product uses no
  CDP (ADR-0019 §1).
- **The model:** scripted. The write is approved in the UI, under the default policy (reads
  run, writes ask).

## Performance (P2, P7 against M4)
**How it was measured.**
- **Harness:** the bench harness from the tag `tauri-shell-final` (retired with the Tauri shell,
  run from a scratch copy).
- **Two changes to the harness** (`M5-bench/run.py.diff`):
  - the baseline runs with its own `axiomd`;
  - that daemon is counted as the daemon, not as part of the shell.
- **Builds:** both release builds.
  - **M4** is `b25da83`, the end of `task/flutter`: M4 plus the Flutter shell. Its shell and
    daemon were built from a clean export.
  - **M5** is this branch.
- **Display:** a private Xvfb with software rendering.
- **Order:** interleaved, as `--ab` does it; the load was 3–6.
- **Results:** `M5-bench/*.json`.

**P2, startup until the explorer is painted** (`JWI-Fedora-20261122-080842.json`):
- 5 pairs, with a shared cache directory, so cold means a fresh data directory;
- M5's median was 254.7 ms cold and 254.8 ms warm; M4's was 257.7 and 256.5;
- the paired difference was **−3.5 ms cold** (range −23.6…+45.7) and **−1.7 ms warm**
  (−23.2…+4.1) → **pass**;
- the inspection service starts only with the first preview, so M5 adds no work at startup.

**P7, idle CPU and memory** (`JWI-Fedora-20261122-081902.json`, 3 interleaved pairs):

| | Idle CPU | Memory (PSS) |
|--|--|--|
| Workspace open | **0.0 %**, against M4's 0.0 % | **+0.5 MiB** (−1.8…+0.8) |
| A document open | **26.6 %**, against M4's 26.6 % (difference +0.1 %) | **+4.8 MiB** (+3.7…+13.8) |

- **Daemon:** 25.2 MiB, against M4's 24.3.
- **Typing (p50 / p95):** the difference from M4 was −0.3 / −1.6 ms.
- **Verdict:** pass.

**Found by this measurement, not from M5: the Flutter editor's idle CPU.**
- **What:** with a document open, both builds use about 27 % of a core while idle, on Xvfb's
  software renderer. The Tauri shell measured 1.2 % in the same scenario in M4.
- **Likely cause:** the caret's blink repaints the window, and every frame is drawn on the CPU
  here.
- **Not yet measured:** this on a GPU.
- **Status:** a follow-up for the Flutter shell (§Owed).

## Defects found by M5's own checks and fixed
- **`ui/nodeDetails` and unstamped elements** (M5-UI-001): the details of an element without a
  stamp of its own got a text-search guess (`15:38`) instead of its owner (`7:5`). They now walk
  up to the nearest stamped ancestor, as hit-test chains do.
- **The Inspector's report below the fold:** the latest verification sat under the property
  list, outside the side bar's lazily built list. It now comes first.
- **The macOS window** (PR 6's CI): it opened at the Xcode template's 800×600. With the side bar
  and the dock open, that left the editor 57 pt, so rows overflowed and taps missed.
  - It now opens at 1180×760, as on Linux, and honours `AXIOM_WINDOW_SIZE`.
  - Both platforms now have a minimum window size of 900×560.
- **`env_rust_test`** (PR 6's CI, Ubuntu): it looked for "Plan install…" before a frame had
  rebuilt the page; it now waits for the button.

## Deviations from the task texts (recorded in each handoff)
- **No web view in the Flutter shell (ADR-0020 §8):** the preview opens in the person's browser,
  and the Inspector is a panel beside the editor.
  - The task files for M5-UI-001 and M5-QA-001 named the Tauri shell; they now name the Flutter
    shell.
  - The exit suite is `inspect_loop_test.dart` rather than `e2e/inspect.mjs`.
- **No pixel checks in M5:** `pixelsChangedInRegion` and `pixelsStableElsewhere` are reported
  as `skipped` (ADR-0019). The verdict rests on geometry, properties, re-identification, and
  build, runtime and settle checks.
- **No diff-line re-identification:** a stamp that moves falls back to type, text and ancestor
  path, with exactly one match required (M5-VERIFY-001).
- **The Inspector shows the latest verification an agent ran;** it has no Verify button of its
  own.
