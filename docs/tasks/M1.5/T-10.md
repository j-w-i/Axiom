# T-10: Manual verification protocol and its first run

## Objective
`docs/roadmap/verification/M1.5.md` contains a per-OS manual checklist (who,
when, what) covering IME, clipboard, drag and drop, HiDPI, screen-reader
navigation and a real-GPU benchmark run, and records the first run. This is
exit criterion 5 of M1.5.

## Context
Source: implementation-roadmap.md §1 (wave D), §2 (T-10), §5 condition 5. The
unverified areas are listed in `docs/migration/qt-to-tauri/architecture.md` §4
(open questions 2 and 3) and feature-parity.md rows S-8 and summary gaps "Screen
readers, IME, HiDPI, real GPU". The format precedent is
`docs/roadmap/verification/M1.md` (environment table, criteria table, evidence).
Review procedure: `agents/REVIEW_GUIDE.md`. Implementation procedure:
`agents/IMPLEMENTATION_GUIDE.md`.

## Required interfaces
- `docs/roadmap/verification/M1.md` (format reference, read only).
- `docs/migration/qt-to-tauri/performance.md` §1 (benchmark method, `bench/run.sh`).
- `docs/migration/qt-to-tauri/design-system.md` (accessibility rules).

## Implementation requirements
1. Create `docs/roadmap/verification/M1.5.md` with: environment table per OS
   (OS version, WebKitGTK / WebView2 / WKWebView version, screen reader and
   version, display scaling); a checklist with one row per item, each with an
   "expected" column and a "result" column.
2. Checklist items (from roadmap T-10): IME (Japanese and Chinese input in Monaco);
   clipboard to and from another application; drag and drop of a folder onto the
   window; 150 % and 200 % scaling; screen-reader navigation of explorer, tabs,
   output and dialogs (Orca on Linux, NVDA or Narrator on Windows, VoiceOver on
   macOS); real-GPU run of `apps/desktop-tauri/bench/run.sh`.
3. Each row records who ran it, the date and the observation. A row not run is
   left as "not run", never as pass.
4. Add a short protocol section to `agents/` (e.g. `agents/MANUAL_VERIFICATION.md`)
   describing how to run the checklist on a real machine without writing to the
   user's profile (`AXIOM_DATA_DIR` to a temp directory).
5. The first run is executed by the owner or a human reviewer on real hardware
   where possible; agent runs are recorded as such.

## Constraints
- Documentation and protocol only: no code, no change to `apps/` or `crates/`.
- Do not claim a result that was not observed.
- Benchmarks use the same method as performance.md; no change to budgets.

## Acceptance criteria
1. `docs/roadmap/verification/M1.5.md` exists with the per-OS environment table
   and all checklist items from req. 2 (req. 1–2).
2. Every row has a who/when/what entry; un-run rows read "not run" (req. 3).
3. The protocol in `agents/` is referenced from M1.5.md (req. 4).
4. The benchmark result is recorded with OS and GPU, or the row reads "not run".
5. Exit criterion 5 of M1.5 is either met (no blocker found) or its blockers
   are listed with owners.

## Tests
- `python3 scripts/tasks.py check` — task board consistent.
- A reviewer reads the checklist and confirms every row has an entry (manual).
- `scripts/check.sh` — still green (no code change).

## Failure conditions
- A checklist row is marked pass without an observation.
- A result is claimed on an OS or GPU that was not used.
- The first run is recorded as complete while rows remain "not run" (the task
  is then Implemented, not Tested).
- Any screen-reader result is recorded from a different screen reader than the
  one named in the environment table.

## Documentation updates

- `docs/roadmap/current.md` (governance rule 10).

The checklist completion counts (pass / fail / not run) per OS, every blocker
with its owner, and the list of rows that feed the T-12 gate.
