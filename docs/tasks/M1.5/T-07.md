# T-07: Native application menu on macOS

## Objective
On macOS the app shows a native menu bar with File, Edit, View, Run and Help,
with accelerators. Each native item dispatches to the same store action as the
in-window menu. Linux and Windows keep the in-window menus.

## Context
Source: implementation-roadmap.md §1 (wave C), §2 (T-07). The current state is
recorded in `docs/migration/qt-to-tauri/architecture.md` §2.2 (Menus: "in-window
Radix menus; neither is a native macOS menu bar today") and feature-parity.md
row S-7. Tauri menu API is the mechanism named by the roadmap.

## Required interfaces
- `apps/desktop-tauri/src-tauri/` — host (Tauri 2 menu API). The host gains no
  file, process or shell command (architecture.md §2.3); menu events are
  forwarded to the webview through the existing `host_subscribe` channel as a
  menu-action event.
- `apps/desktop-tauri/src/` — the in-window menu definitions and store actions
  (single source of action ids).

## Implementation requirements
1. On macOS, build a native menu with submenus File, Edit, View, Run, Help
   using the Tauri 2 menu API; accelerators match the in-window menus.
2. Each native item emits one action id to the webview; the webview dispatches
   it to the same store method used by the in-window menu (no duplicated logic).
3. Action ids are defined once in `apps/desktop-tauri/src/` and shared by both
   menus (a test asserts the two lists are equal).
4. On Linux and Windows the native menu is not installed; the in-window menus
   behave as before.
5. No new host command in `build.rs` and no capability added; the event uses the
   existing channel (T-03 capability test must still pass).
6. Accessibility: menu item labels are the same strings as the in-window menu.

## Constraints
- No business logic in the host; the host only forwards action ids.
- No change to `crates/` or to the seven commands (architecture.md §2.3).
- `docs/migration/qt-to-tauri/feature-parity.md` S-7 is not changed by this
  task except through T-06 (menu structure).

## Acceptance criteria
1. On macOS the menu bar shows File, Edit, View, Run, Help (req. 1).
2. Accelerators are displayed for at least Save (Cmd+S), Run (F5) and Stop (Shift+F5) (req. 1).
3. E2E on macOS triggers at least Save and Run through the menu API and the
   store actions run (req. 2; roadmap T-07 acceptance).
4. Action id lists are equal between the two menus (req. 3; test).
5. Linux and Windows show no native menu; the capability test still passes (req. 4–5).

## Tests
- `cargo test -p axiom-desktop-tauri` — capability test unchanged and passing.
- `cd apps/desktop-tauri && pnpm test` — action-list equality test passes.
- macOS: `apps/desktop-tauri/scripts/e2e.sh` menu case on a macOS runner (CI, T-09).
  Locally on Linux this cannot run: report "unverified on macOS".

## Failure conditions
- The macOS E2E menu case is not run: the task is not Tested (the roadmap
  requires macOS evidence). Report it as blocked on CI or a macOS machine.
- A native item dispatches its own logic instead of the shared store method.
- Any new host command or capability is added.

  implementation differs from the text).
