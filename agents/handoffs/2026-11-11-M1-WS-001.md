## Behaviour implemented
- `open`: absolute only, canonicalized with `dunce`, idempotent per canonical root, ids `w1`, `w2`, … (never reused after close).
- `resolve`: the four security.md steps; dangling symlinks are rejected as `Escapes`.
- `list`: `symlink_metadata`-style kinds (entry metadata, symlinks never followed), size for files only, required sort, `ignored` via `ignore::gitignore::Gitignore` chains (`.gitignore` then `.ignore` per directory, `.git/info/exclude` weakest, deepest matcher with an opinion wins, children of ignored directories are ignored, `.git` always ignored). Matchers are cached per directory and invalidated by writes to `.gitignore`/`.ignore`/`.git/info/exclude` through this crate.
- `read_text`, `write_text` per the spec and the `ipc.md` decision table; atomic temp-file + fsync + rename; permission bits copied from the existing file (new files get 0644 on Unix); a per-file async mutex covers the version check and the rename. All blocking work in `spawn_blocking`.

## Deviations and decisions
- `resolve` returns `NotADirectory` (→ `invalid_params`) when a path component is a regular file (`f/child`); spec silent.
- `.ignore` takes precedence over `.gitignore` in the same directory (ripgrep order); spec silent.
- Dangling symlinks are treated as `Escapes` on resolve (stricter than spec; prevents write-through to arbitrary targets).
- Messages name workspace-relative paths; the root itself is shown as "the workspace root".
- A test (`error_messages_never_contain_absolute_paths`) checks the no-absolute-path rule for common errors. `WsError::Io` messages (`osError` details) may contain OS text that includes paths; that is by spec (`details`).
