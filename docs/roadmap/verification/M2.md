# M2 verification — Environments and builds

_Written 2026-11-19 by the implementing session (M2-QA-001). It records what was run, where, and
what was not._

## Exit criterion (milestones.md §M2)
> On a machine without Rust: open a Cargo project → Axiom reports Rust missing → shows an install
> plan → installs a managed toolchain → `cargo build` runs inside it → a compile error appears in
> Problems and clicking it opens the file at the line → uninstall removes the directory and
> nothing else. Provider contract suite passes for all bundled providers.

### The scenario, end to end: `apps/desktop-tauri/e2e/env.mjs`
**"Without Rust"** means three things:
- the app, and so the daemon and everything it starts, gets a `PATH` with every directory
  holding `cargo`, `rustc` or `rustup` removed;
- HOME is a fresh empty directory, and so is the data dir;
- the project selects `rust = "1.84.0"` in `.axiom/project.toml`.

Opening the folder uses the store's own request, because the native folder dialog cannot be
driven (as in smoke). Every other step is input through the UI: clicks, keys and the palette.

| # | Step | Result (Linux, Fedora 44 x86_64, WebKitWebDriver, 2026-11-19) |
|---|------|--------------------------------------------------------------|
| 1 | Rust missing on the Environments page, selected by `.axiom/project.toml`, with Plan install… | pass |
| 2 | The plan shows all six steps: rustup-init download (20.4 MB, SHA-256 from its `.sha256`), place, set up rustup, `rustup toolchain install 1.84.0`, verify cargo, verify rustc | pass |
| 3 | Install runs the approved plan; the row turns Ready, `1.84.0`, managed | pass, 15.0–16.0 s over three runs |
| 4 | Build: cargo build (palette) runs inside the managed toolchain and fails on the type error | pass, 0.1 s |
| 5 | The error E0308 is in Problems; Enter opens `src/main.rs` at Ln 2, Col 18 | pass (after a fix: see below) |
| 6 | Remove names the directory; afterwards the data dir equals the post-install snapshot minus exactly `toolchains/rust/1.84.0` (160 paths); HOME has no `.cargo` or `.rustup` | pass, snapshot diff empty |

The suite reported "6/6 env checks passed in 19.7 s". CI runs it on Ubuntu, in the Tauri
job's step "End-to-end, M2 exit scenario (env.mjs)".
- **Not a container:** the clean machine is the `PATH` and HOME isolation above. A container
  image with WebKitGTK and the built app was not set up.
- **Defect found here and fixed:** a Problems entry opened before any document had been opened
  left the cursor at 1:1. The editor loads with its first document, and `openAt` dropped the
  reveal. The reveal is now held until the editor is ready (`documents.ts`; store test "openAt
  before the editor surface exists…").

### Provider contract suite on every OS
`crates/env/tests/provider_contract.rs` covers all five built-in providers: rust, node, cmake,
ninja and python. It runs in every CI Rust job (Linux, macOS, Windows) as part of
`cargo test --workspace`.

## Performance (P2, P7 against M1.6)
Bench `--ab` against the M1.6 shell (main at 3409988, built in a separate worktree), on this
machine, load 3.5–4.4, interleaved:
- **P2, startup → explorer painted:**
  - 3 pairs, `apps/desktop-tauri/bench/results/JWI-Fedora-20261119-013715.json`;
  - M1.6 base cold 397.8 / warm 387.9 ms;
  - paired difference cold **+17.0 ms**, warm **+4.9 ms**;
  - budget ≤ +40 ms → **pass**.
- **P7, idle CPU:**
  - one run, `…-013821.json`;
  - workspace **0.1 %**, with the editor **1.1 %**, against M1.6's recorded 0.2 / 1.1 % →
    **unchanged**.
  - This side was not interleaved: one sample against M1.6's recorded figures, to keep the bench
    short (owner, 2026-11-19).
- **Caveat:** the M2 binary measured was the `e2e`-feature build (it includes the WebDriver
  server), so both numbers are conservative.
