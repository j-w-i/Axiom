# M4-LSP-001: Language-server supervision in the daemon

## Objective
`axiom-lsp` runs language servers as daemon children, one per (workspace, server definition),
speaks LSP base protocol to them, shares each with every client (own id space, pending map),
answers server→client requests itself, mirrors open documents, keeps diagnostics per URI, and
restarts with a bounded policy. `axiomd` serves `lsp/servers|request|notify|restart` and relays
`lsp/notification` and `lsp/serverState`. Provider manifests gain `[[lsp]]`; rust and node
declare rust-analyzer and typescript-language-server.

## Context
ADR-0018 §2; ADR-0004; `crates/env` manifest loader and resolution (the server binary is found in
the project's environment); `crates/exec` patterns (process groups, kill on drop).

## Implementation requirements
1. Framing: `Content-Length` headers, UTF-8 JSON bodies, bounded (64 MiB) messages; stderr kept
   as the last 200 lines for errors.
2. `initialize` with a fixed client-capability set (documented in the crate), `rootUri` and one
   `workspaceFolders` entry, `initializationOptions` from the manifest merged with settings
   `lsp.<id>.initializationOptions`; then `initialized`. Requests before ready wait (bounded 60 s).
3. Server→client requests: `workspace/configuration` (settings `lsp.<id>.settings` by section, else
   null), `client/registerCapability` / `unregisterCapability` (accepted), `window/workDoneProgress/create`
   (accepted), `workspace/applyEdit` (`applied: false`), `window/showMessageRequest` (null);
   anything else: MethodNotFound.
4. Start on first `didOpen` for a matching language id or first `lsp/request`; idle servers stay
   up until the workspace closes; `shutdown`/`exit` on close and daemon shutdown (bounded 2 s, then
   kill).
5. Crash: up to 3 restarts in 3 minutes (re-sending `didOpen` for mirrored documents), then
   `failed` with the stderr tail. `missing` when the command is not found, with the manifest's
   install hint.
6. Document mirror: apply `didOpen/didChange (full or incremental)/didClose` to a text copy with
   UTF-16 positions; diagnostics stored per URI and merged into what `build/diagnostics`
   consumers see through a `source: "lsp:<id>"` label (Problems merge is in M4-LSP-002).
7. Reads outside the workspace: the daemon records absolute paths that appear in `Location`/`LocationLink`
   results and `fs/readFile` allows exactly those (read-only), per ADR-0018 §2.
8. `tests/helpers/fake-lsp`: a scriptable fake server (initialize, completion, definition, a
   server→client configuration request, diagnostics on open, crash on demand).

## Acceptance criteria
1. Against fake-lsp: two clients' requests interleave with correct responses; `$/cancelRequest`
   forwarded; configuration answered from settings; diagnostics relayed and stored; a crash
   restarts and re-opens documents; the fourth crash in 3 minutes leaves `failed`.
2. With real rust-analyzer on a fixture Cargo project (CI installs the component): a definition
   request across files returns the right location; diagnostics for a type error arrive.
3. A missing server is `missing` with a hint; nothing is installed silently.

## Tests
`cargo test -p axiom-lsp`; `cargo test -p axiomd --test lsp`; the real-server test runs where
`rust-analyzer` resolves (CI installs it; locally it is present) and fails, not skips, when
`AXIOM_REQUIRE_LSP=1` and it is absent.

## Failure conditions
A server outlives the daemon; ids collide across clients; the editor can read an arbitrary file
outside the workspace.

## Documentation updates
`modules.md` §lsp, `providers.md` (`[[lsp]]`), `ipc.md` notes.

## Handoff
The client-capability set and the server definitions.
