# T-14: Make the Tauri shell the default

## Objective
Release artifacts, the default developer command and the documentation point to
the Tauri shell. The Qt shell stays buildable behind an explicit flag for one
milestone, with its tests still passing.

## Context
Source: implementation-roadmap.md §1 (wave F), §2 (T-14), §4 (rollback after T-14),
§3 (the Qt shell remains the release artifact until T-14). **Gated:** this task
may start only after T-12 (parity gate) is recorded as passed and T-13 packaging
is green. The reason is the cost of porting M2 UI to QML if the flip is reverted
(roadmap §4).

## Required interfaces
- `scripts/check.sh` — targets `tauri` (default) and `desktop-qt` (flagged Qt).
- `.github/workflows/ci.yml` — release workflow.
- `README.md` and `docs/` quick-start pages.
- `scripts/` launcher for the default shell (name chosen in this task and stated in the handoff).

## Implementation requirements
1. Gate check before any change: `docs/roadmap/current.md` states the T-12 gate
   "passed" (T-14 is not started otherwise).
2. The default `scripts/check.sh` (`all`) runs the Tauri gates; the Qt gates run
   under `scripts/check.sh desktop-qt`. The current `desktop` target name is kept
   as an alias for `desktop-qt` for one milestone.
3. Release artifacts and the release workflow build the Tauri shell by default.
4. The Qt shell builds and its tests pass under `scripts/check.sh desktop-qt`
   (roadmap T-14 acceptance).
5. A documented switch selects the Qt shell for one milestone (e.g. a flag on the
   launcher script); the flag is named in `docs/` and `README.md`.
6. `README.md` and the quick-start docs describe the Tauri shell as the default
   and Qt as the flagged legacy shell, with the Linux WebKitGTK prerequisite.
7. `docs/roadmap/current.md` records the switch and the date.

## Constraints
- No change to `apps/desktop-tauri/src/` or `src-tauri/` behaviour; this task is
  wiring and documentation only.
- Protocol 0.1 and editor bridge 1 unchanged.
- The Qt shell is not deleted (that is T-15) and is not removed from CI.
- Governance: edits to shared files are additive where possible.

## Acceptance criteria
1. Gate check (req. 1) is recorded in the handoff with the T-12 result link.
2. `scripts/check.sh` (default) runs the Tauri gates; `scripts/check.sh desktop-qt`
   runs the Qt gates and passes (req. 2, 4).
3. Release workflow builds the Tauri shell (req. 3).
4. The flag for Qt is documented in `README.md` and `docs/` (req. 5–6).
5. CI is green on three OSes for both shells (or red cells with owners).

## Tests
- `scripts/check.sh` — passes (Tauri default).
- `scripts/check.sh desktop-qt` — passes; `ctest` offscreen results shown.
- CI run: both `tauri` and Qt jobs green on ubuntu, macos, windows.
- Manual: the documented flag starts each shell (`--help` or launcher output).

## Failure conditions
- Started before the T-12 gate is recorded as passed.
- The Qt shell's tests are skipped or removed to make `desktop-qt` green.
- Release artifacts still point to Qt while the handoff says Tauri is default.
- The flag is undocumented.

## Documentation updates
- `README.md` — default shell and flag.
- `docs/contributing/dev-setup.md` — prerequisites for both shells.
- `docs/roadmap/current.md` and `docs/roadmap/milestones.md` — switch recorded.
- `docs/architecture/` — the shell description, if T-01 text needs correcting.

## Handoff
The T-12 gate link, the default-shell switch date, the flag name, and CI links for
both shells on three OSes.
