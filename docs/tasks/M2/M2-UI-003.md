# M2-UI-003: Problems view, click-to-source, and provider tasks in the palette and transport

## Objective
The console gains its view strip with Output and **Problems** (diagnostics from `build/diagnostics`: severity glyph, message, code, `file:line:col`, click opens the file at the position); provider tasks (build/run/test) appear in the palette and as the transport's Rerun target.

## Context
Epic 2.7. `workspace-spec.md` §2.4 (view strip), §5.1 (diagnostic rows); ADR-0014 §7.

## Required interfaces
- `build/tasks`, `build/run`, `build/diagnostics`; editor bridge `revealPosition` (frozen, existing).

## Implementation requirements
1. View strip (Output / Problems) with counts; Problems groups by file, sorted by severity then position.
2. Activating a row opens the document and reveals the position (`documents` store; no bridge change).
3. Palette: "Build", "Test", "Run" commands per provider task; transport label shows the provider task.
4. Diagnostics clear when a new run of the same task starts.

## Constraints
- ADR-0014 (accepted) is the decision record; do not reopen its decisions in this task.
- Frozen contracts (IPC 0.1 meanings, editor bridge 1) unchanged; additive protocol changes only where this spec says so.
- `scripts/check.sh` green; no test deleted, weakened or skipped.
- No bridge change: reveal through the existing `revealPosition`.

## Acceptance criteria
1. After a failing `cargo build` fixture run, Problems shows the error; Enter on it opens the file at line and column.
2. a11y suite passes with Problems open.

## Tests
- Vitest for the diagnostics store; smoke `problems click to source`; shots for Problems; `scripts/check.sh`.

## Failure conditions
- The view strip appears with a placeholder view.

## Documentation updates
`docs/design/workspace-spec.md` §2.4 (as built), `docs/roadmap/current.md`.

## Handoff
Screenshots of Problems in both themes.
