### macOS: 120 Hz rendering (owner-approved private API)
WKWebView capped the page's rendering updates at ~60 Hz on the owner's 120 Hz XDR display (rAF every
16.7 ms, visible and hidden; Monaco, which renders its own scrolling, moved 59–60 times per second).
`src-tauri/src/macos_frame_rate.rs` turns off WebKit's `PreferPageRenderingUpdatesNear60FPSEnabled`
through the private `+[WKPreferences _features]` / `-[WKPreferences _setEnabled:forFeature:]` (owner:
"if it allows smoother scrolling you can use a private api"); each selector is checked first, so a
WebKit without them keeps 60 Hz. Measured after: rAF every ~8 ms, editor scrolling 119 frames/s. The
page still renders only when something changes, so ProMotion lowers the refresh when idle (only the
caret's timer blink runs); while a task runs the LED pulse is an infinite animation and may keep
120 Hz (panel refresh not measured). Hidden-mode suites after the change: smoke 53/53, quit 8/8,
parity 13/13, a11y 17/19 (the inactive-window focus-ring artefact).
