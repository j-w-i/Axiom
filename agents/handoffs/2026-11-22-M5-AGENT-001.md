### The tools (`crates/axiomd/src/tools.rs`; inputs in `axiom-agent::tools::inputs`)
- **`preview.start`** (execute):
  - gated as the command it will run: the project's `node_modules/.bin/vite`, else
    `npm run dev`, else the given argv;
  - returns the URL and whether a page is connected; when none is, it tells the model to ask
    the person to open the URL.
- **`ui.snapshot`** (read): an indented tree, one node per line: id, type, `#name`, text,
  `key=<stable key>`, `at x,y wxh`, and `src=file:line:col (exact)` or the guess with its
  relation, method and confidence. Default 300 nodes, at most 2000, bounded to 31 KiB.
- **`ui.inspect`** (read): one node by `stableKey` (found through a snapshot) or by `node` id.
  It gives the line above plus every source candidate, the accessibility and the `css.*`
  properties.
- **`ui.selection`** (read): the person's latest selection in inspect mode, with its
  ancestors. `Previews` now records the `selected` chain, and drops it with the preview. When
  nothing is selected, the tool says so and suggests `ui.snapshot`.
- **`ui.verify`** (read): `ui/verify` through the handler. The text is `verdict: …` followed
  by one `pass` / `FAIL` / `skipped` line per check. An empty assertion list is refused with a
  hint on what to state.
- **Which preview:** every `ui.*` tool defaults to the workspace's ready preview. A `previewId`
  that belongs to another workspace is `not_found`.
- **No page connected:** `adapter_unavailable` comes with a hint to ask the person to open the
  URL.

### Assertion-first
- The system prompt has a UI line: find the element, decide the checks before patching, call
  `ui.verify` after `fs.applyPatch`, and report the verdict as it is.
- `ui.verify`'s description says the same and explains each verdict.
